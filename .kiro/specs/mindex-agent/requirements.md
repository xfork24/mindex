# 需求文档：Mindex 智能助手（全局 LLM 操控入口）

## 简介

在所有页面提供全局悬浮的智能助手面板。用户用自然语言驱动 Mindex 的核心能力，助手在需要时澄清需求，高风险操作须经用户确认。工具层与运行方式无关，同一注册表可导出为 MCP 服务，供 deepseek-harness（dsh）、Claude Code、Codex 等外部 harness 使用；实现须与未来接入 dsh 运行时兼容。

## 需求

### 需求 1：智能助手模型角色

**用户故事：** 作为用户，我希望在设置页配置智能助手使用的模型，并验证它支持工具调用。

#### 验收标准

1. 设置页模型角色中出现「智能助手」（`agent`），支持档案的新建、编辑、删除、激活与测试连接。
2. 档案的 `backend` 可选 `openai`（OpenAI 兼容 tools 协议）或 `anthropic`（原生 Messages 协议）。
3. WHEN 测试连接 THEN 系统发送一次带 echo 工具的探测请求，并报告工具调用是否可用。
4. 提供 DeepSeek、阿里云百炼、智谱、Anthropic 的智能助手预设。

### 需求 2：工具注册表

**用户故事：** 作为开发者，我希望工具定义与运行时解耦，既能内置执行也能导出为 MCP。

#### 验收标准

1. 每个工具包含名称（`^[A-Za-z0-9_-]{1,64}$`，无前缀）、领域、描述、参数 JSON Schema、风险级别（read/write/danger）、可选预览、执行、给模型的文本渲染与可选的界面元数据。
2. 工具一律经进程内 ASGI 回环调用既有 REST 接口，保留严格校验、乐观锁、互斥锁与 i18n 错误。
3. 启用访问令牌时，回环请求凭进程内随机内部凭证放行；伪造的凭证被拒绝。
4. 409/422 作为可恢复结果返回给模型，而不是中断对话。
5. 第一期工具不超过约 30 个：Studio 与设置完整读写；素材、人物、检索只读；按页面上下文加载领域。

### 需求 3：分级确认

**用户故事：** 作为用户，我希望改动前看到预览，危险操作必须由我显式确认。

#### 验收标准

1. read 工具直接执行；write 工具展示预览后一键确认；danger 工具（删除、改模型或密钥、构建）必须显式确认。
2. 确认结果只有 `allowed-once | rejected | cancelled | unavailable`，只有 `allowed-once` 放行。
3. 没有可用的确认通道时失败关闭（`unavailable` → 拒绝）。
4. 用户可选择「本会话内不再询问此工具」，该授权作为事件记录。
5. 不允许修改或停用当前正在使用的智能助手档案。

### 需求 4：会话与事件日志

**用户故事：** 作为用户，我希望会话持久保存、可切换，服务重启后仍可继续。

#### 验收标准

1. 会话事件使用 dsh 信封 `{session_id, seq, time, type, data, ignorable?}`，seq 在会话内连续。
2. 核心事件类型与 dsh 一致：`turn/start`、`turn/end`、`step/start`、`step/end`、`user/message`、`assistant/message`、`tool/call`、`tool/result`；扩展事件使用 `plugin:mindex/...` 命名空间。
3. 发送给模型的历史只从日志派生；超出上下文预算时先省略较早的工具结果。
4. 服务重启时，未结束的轮次以 `turn/end{reason:{kind:'interrupted'}}` 关闭。
5. SSE 接口支持按 seq 断点续传，同时推送持久事件与临时流式块。

### 需求 5：澄清与密钥

**用户故事：** 作为用户，我希望助手用表单向我提问，密钥不会泄露给模型。

#### 验收标准

1. 提问工具名为 `ask_user_question`，参数是 dsh 结构的超集（支持 `fields`，类型含 `secret`）。
2. secret 字段值存入会话绑定、带 TTL 的保险库，会话中只出现 `secret://<id>` 引用。
3. 明文密钥不出现在事件表、发给模型的请求、SSE 输出中；只在回环客户端内解引用。
4. 过期或不属于本会话的引用被拒绝。
5. 用户在聊天框粘贴疑似密钥时，前端拦截并提示改用表单。

### 需求 6：构建跟踪与自动总结

**用户故事：** 作为用户，我希望提交构建后看到进度，结束后助手自动总结并建议下一步。

#### 验收标准

1. 构建提交后对话中显示实时进度卡片。
2. WHEN 构建进入终态 THEN 系统写入 `plugin:mindex/build-finished` 事件，并自动触发一轮总结（`source.kind='followup'`）。
3. 服务重启后，仍在运行的构建继续被跟踪。

### 需求 7：全局面板

**用户故事：** 作为用户，我希望在任何页面唤起助手，它知道我当前在看什么。

#### 验收标准

1. 五个页面都提供启动按钮与侧边抽屉：会话列表、流式消息、工具卡片、确认卡片、提问表单、构建进度卡片。
2. 每个页面通过 `window.MindexAgentContext()` 提供上下文（页面、job、方案、展开的分镜），随消息发送。
3. 助手完成写操作后派发 `mindex:agent-mutation` 事件，宿主页面自行刷新。
4. 所有界面文案进入 `messages.json`，中英双语。

### 需求 8：能力缺口

**用户故事：** 作为产品负责人，我希望知道用户提出了哪些当前做不到的需求。

#### 验收标准

1. 对做不到的需求（如拆分镜粒度），助手如实说明、给出替代做法，并调用 `report_capability_gap` 记录。
2. `GET /api/agent/gaps` 列出已记录的缺口。

### 需求 9：MCP 导出

**用户故事：** 作为外部 harness 用户，我希望用 dsh、Claude Code 或 Codex 驱动 Mindex。

#### 验收标准

1. MCP 服务名为 `mindex`，提供 streamable-http `/mcp`（Bearer，默认关闭）与 `mindex mcp` stdio 两种传输。
2. read 工具标注 `readOnlyHint`，danger 工具标注 `destructiveHint`；不导出 `ask_user_question`。
3. 服务端按 `agent.mcp.policy`（read/write/all）强制执行，超出策略的调用返回 `isError`。
4. 文档给出 dsh、Claude Code、Codex 的配置示例与未来 `DshRuntime` 的接入路径。

### 需求 10：可替换运行时与验收

**用户故事：** 作为开发者，我希望未来用 dsh 运行时替换内置运行时，而不改前端与工具。

#### 验收标准

1. `AgentRuntime` 协议提供 `create_or_resume`、`prompt`、`events`、`answer_approval`、`answer_question`、`cancel`、`status`，与 dsh SDK 方法一一对应。
2. 用脚本化假模型跑 10 个确定性场景：用户的 3 个示例、切换方案、改音色、诊断构建失败、检索、歧义 ID、拒绝确认、密钥处理。
3. `scripts/agent_eval.py` 对真实 Claude 与 OpenAI 兼容模型运行同一组场景并报告通过率。

### 需求 11：页面同步与定位

**用户故事：** 作为用户，我希望助手的每次查询与修改都反映到网页上，并定位到对应位置让我看到。

#### 验收标准

1. 读工具与写工具返回定位描述（page、任务、方案、分镜、阶段、区块、角色、档案、检索词等）；写工具在确认预览阶段就先定位到要改的位置。
2. 改动与定位写入全局通道（`agent_changes`），内置助手与 MCP（含独立进程）都发布；`GET /api/agent/changes` 以 SSE 推送，连接时不回放历史。
3. 提供 `navigate` 工具让模型主动切换页面与定位；不导出到 MCP。
4. 本标签页发起的会话：同页立即定位；跨页的定位在会话空闲或等待确认时跳转到最后目标，跳转后面板自动打开、确认卡片仍在。纯查询同样跟随。
5. 所有打开的页面在任何来源的改动后刷新；MCP 或其他标签页的操作只做页内高亮，不跨页跳转；重放历史不定位。
6. 面板提供「跟随助手定位」开关（默认开启、记住选择）；关闭后只刷新数据。

### 需求 12：Markdown 渲染

**用户故事：** 作为用户，我希望助手回复中的标题、列表、表格与代码块正确显示。

#### 验收标准

1. 助手消息（含流式输出）用固定版本的 marked 渲染、DOMPurify 净化后显示；用户消息与工具卡片仍为纯文本。
2. 脚本、事件属性、`javascript:` / `data:` 链接等危险内容被清除；外部链接新窗口打开。

### 需求 13：面板内的图片与音视频

**用户故事：** 作为用户，我希望在助手面板里直接浏览相关图片、播放配音和视频。

#### 验收标准

1. 工具结果附带的媒体以卡片显示：图片为缩略图网格，可打开大图浏览（左右切换、Esc 关闭）；音频与视频可直接播放，镜头片段与创作页播放方式一致。
2. 图片与成片默认展开，音频与单镜视频默认折叠；切换会话或关闭面板时暂停播放。
3. 只加载本站 `/api/...` 地址的媒体；Markdown 回复中的图片同样只放行本站地址。

### 需求 14：可调整面板宽度

**用户故事：** 作为用户，我希望拖动调整助手面板的宽度。

#### 验收标准

1. 面板左边缘可用鼠标、触屏或键盘调整宽度（320px 至 80% 视口），双击恢复默认；宽度在刷新与切换页面后保持。
