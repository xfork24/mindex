# REHASH_REFINEMENT_PLAN：macOS 模型身份与索引兼容性重构

## 目标与范围

解决模型迁移到 macOS 后，因路径、服务别名、构建版本或上下文容量变化而无法使用的问题，同时保留权重、投影和向量协议的有效校验。

采用已确认的迁移策略：**允许一次性重建索引，保留旧索引，不改写旧向量的身份**。先完成 WeMM 和 trailer 验收，正片随后重建。ASR、Analyzer 同步适配公共接口，但不要求同时部署或迁移；TTS 不在本次身份重构范围内。

不采用原方案的“七字段等于文件内容哈希”。这些字段仅用于结构校验和诊断。

## 身份与兼容性设计

| 层次 | 包含内容 | 使用方式 |
|---|---|---|
| 模型内容身份 | 实际 weights、mmproj 的 SHA-256 | 文件内容变化必须产生新身份 |
| 向量空间契约 | 内容身份、维度、池化、归一化、输入模板、视频预处理及适配器语义版本 | 决定索引兼容性 |
| 部署观测 | 服务地址、模型路径/别名、构建信息、能力声明、ctx、可观测运行参数 | 诊断、部署验证与请求期间漂移检查 |

具体规则：

- 新向量空间不包含地址、文件路径、服务别名、完整源码文件哈希；以显式的 `llama-native-wemm-2` 协议版本替代整文件哈希。
- 修改模板、池化、归一化或预处理时必须升级对应契约版本；修改日志、ASR 代码或注释不改变 WeMM 空间。
- 路径或别名变化需要核对部署清单，不要求重建索引。构建、后端或数值配置变化需要重新验证兼容性。
- 七项模型元数据必须存在且类型有效；维度、量化和视觉/视频能力必须满足当前角色要求。缺失字段不得以 `None` 哈希后放行。
- 每次推理前后核对部署观测与本地文件状态；请求期间发生漂移，拒绝保存该次结果。

**部署兼容性门槛：**

- 首次建立 v2 空间时，保存六个固定视频样本、六条固定文本及其原始向量作为基线，同时保留输入哈希、预处理配置和部署记录。
- 后续部署使用同一空间前，必须通过现有结构 smoke；每条文本、视频向量与基线的余弦相似度均须达到 `0.999`。
- 基线和验证结果分别绑定空间身份与部署观测摘要。建索引和检索均检查当前部署是否已通过。
- 验证不通过时禁止混用旧索引；需要升级契约中的数值实现版本、建立新基线并重建。不得自动降低阈值或自动修改旧索引。
- 此门槛是明确的工程兼容策略，不宣称证明所有输入上的数值等价；中文检索质量另行验收。

## 接口与实现调整

- `inspect_service()` 只探测，不推理，统一返回完整报告：原始服务观测、规范化元数据、诊断摘要及能力信息。
- `checked_runtime()` 统一返回上述完整报告。同步修改 embedding、ASR、Analyzer 和 CLI 的全部调用方，不再混用“完整报告”和 `observable`。
- 推理请求中的 `model` 使用当前核验报告里的服务模型 ID；该 ID 不进入稳定空间身份。
- 部署清单升级为 `schema: 2`，记录文件身份、空间契约、部署观测及信任来源。保留 schema 1 的读取和原校验行为，不自动转换旧清单。
- `e2e pin` 增加 `--weights-file`、`--mmproj-file`：本地流式计算 SHA-256，生成新清单。保留旧 SHA 参数用于远程部署，但两种输入方式互斥，远程摘要明确标记为操作员声明。
- 本地清单记录绝对路径和服务器工作目录，核对 `/props.model_path` 的解析结果。mmproj 与启动参数仍需部署者确认，不能宣称标准 HTTP API 已证明实际加载文件。
- 文件哈希在 pin 和新进程首次使用时计算；后续按路径、文件标识、大小及纳秒修改时间缓存，文件状态变化时重新核验，避免每次请求读取数 GB 权重。
- 新增全局 `--no-runtime-overrides`，默认保持现有配置行为。迁移命令显式使用该选项；启动验收 Web 时也必须贯穿运行时配置读取器，不能只跳过 CLI 的一次合并。
- 本轮不重构 ASR、Analyzer 的缓存身份；它们只适配公共报告接口和清单版本，不触发无关业务改造。

## 迁移、验收与回滚步骤

1. **冻结和备份**
   - 盘点访问同一 `data_dir` 的全部服务及后台任务，包括 18302 验收服务；正常停止写入后备份。
   - 同时保存代码版本、原始配置、动态配置选择、部署清单和活动索引 ID。
   - 检查备份数据库完整性、索引成员及媒体文件；不依赖固定的 Chroma 目录 UUID。

2. **完成代码与协议测试**
   - 实现上述身份分层、清单兼容和调用方调整。
   - 修正原计划测试中把 tuple fixture 当字典使用的问题。
   - 先通过定向回归，再进入实际模型验证。

3. **准备 Mac WeMM**
   - 启动脚本按脚本自身位置解析模型路径，使用绝对路径，不依赖调用目录。
   - 初始配置采用 ctx=32768、单 slot，明确使用 f16 K/V cache。
   - 记录实际上下文容量、模型/投影/缓存/计算缓冲占用；测试最长支持的视频输入并观察内存压力和 swap。
   - 若内存不足，降到 16384 后重新执行容量和兼容验证；若最长输入仍无法容纳，则停止迁移，不截断输入或悄悄改变视频预处理。
   - 模型分阶段运行，不要求 WeMM、ASR 和 Analyzer 同时驻留。

4. **生成新清单并验证 trailer**
   - 使用独立迁移配置和新命名清单，不删除或覆盖旧文件；所有命令固定使用 YAML 配置。
   - 先 probe、核验本地文件，再 pin，创建新实验并运行 smoke、保存 v2 基线。
   - 新建 trailer 的 visual/moment 索引，暂不激活。数量以数据库和冻结清单为准；当前为 61 个 moment，不写死原计划的 122。
   - 指定新索引完成中文文本、图片和视频检索验收，记录耗时与资源占用。

5. **重建正片并切换**
   - trailer 验收通过后，使用同一 v2 空间重建正片索引；保持输入、切分和预处理配置一致。
   - 验证成员完整性、断点续建和代表性检索结果，通过后再切换默认活动索引。
   - 保留原有两个索引及旧清单；不把 trailer 测试索引直接设为默认素材库。

**回滚：**正常停止写入，恢复备份对应的代码、配置、清单及活动索引；需要恢复整个数据目录时，先重命名保留失败目录，再恢复备份。旧索引必须配套旧身份实现和对应部署使用，不能只切换索引 ID。

## 测试与交付标准

必须覆盖：

- 同结构、同量化但不同权重，以及仅更换 mmproj，均产生不同内容身份。
- 路径、别名和地址变化不改变空间身份；协议语义变化必须改变。
- 元数据缺失、能力不符、维度错误、无效向量及请求期间部署漂移被拒绝。
- schema 1/2 均有测试；embedding、ASR、Analyzer 使用正确的实时模型 ID。
- 新部署未经验证不能检索或建索引；smoke 内部验证路径可以建立基线。
- 跨部署兼容通过/失败、基线缺失或损坏，以及本地文件变化均有明确结果。
- YAML 固定模式在 probe、pin、index 和验收 Web 中一致生效。
- 索引中断后仅补算缺失向量；失败不切换活动索引，不破坏旧数据。

运行定向及全量 pytest、Ruff、相关前端 JS 语法检查；真实验收记录服务身份、输入哈希、向量对照、检索结果、峰值内存、耗时和回滚步骤。六样本 smoke 不替代检索质量验收。

交付修订代码、测试、新旧清单与配置说明、迁移记录，并更新运行文档。
