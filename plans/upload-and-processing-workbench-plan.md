## 素材上传与四项处理工作台

### 页面与交互

- 在素材管理页增加“添加新素材”按钮，打开上传窗口，支持选择或拖入多个视频。逐个显示上传进度、登记结果和失败原因；单个失败不影响其他文件。
- 上传保存到当前 `data_dir/sources`，按文件内容去重，保留原文件名。重复上传定位已有素材，不覆盖处理结果；上传只登记素材，不启动分镜或模型处理。
- 将“处理与检索状态”改为四项工作：**分镜处理、对白处理、LLM 分析、人物处理**。每项展示处理状态、结果摘要、检索状态和对应操作。
- 未开始显示“待处理”；运行时显示阶段与进度；失败或中断提供重试；已完成提供查看结果及补充处理入口。
- 每项提供“完成后更新检索”，默认勾选。另提供“更新检索”按钮，供关闭自动更新或发布失败后使用。

### 四项处理行为

| 工作 | 启动与前置条件 | 完成后的结果展示 |
|---|---|---|
| 分镜处理 | 登记后即可启动；复用现有检测、切片流程 | 分镜数、精细片段数、缺失文件数；可浏览已有镜头 |
| 对白处理 | 提供自动、字幕轨道、ASR 三种方式；自动优先完整文本字幕，无法使用时回退 ASR | 实际方式、字幕轨道或 ASR 模型、对白条数、有对白片段数及检索覆盖 |
| LLM 分析 | 分镜完成后可启动；有对白则使用，没有对白仍可分析 | 已分析/应分析片段数、场景数；通过镜头详情查看分析内容 |
| 人物处理 | 分镜完成后，配置窗口选择关联作品；检查演员、角色和参考图，缺失时提供人物库入口 | 已处理分镜覆盖、关联人物数、已接受/待确认/已排除分镜数；提供核对入口 |

- 手动选择字幕方式时，仅使用所选文本字幕，不静默改用 ASR；手动 ASR 跳过字幕。无音轨、空对白分别显示对应结果。
- 人物处理默认覆盖整部素材，复用现有识别与核对规则；处理完成不等于所有人物身份已人工确认。
- 检索更新采用现有增量索引及人物发布机制，保留其他素材、渠道和现有检索粒度。没有内容索引时，人物发布先建立已完成的内容渠道索引。
- 处理与发布分别记录结果：处理成功但更新检索失败时，保留处理完成状态，显示发布错误，重试仅执行发布。

### 后端与兼容

- 将原片登记从 `Pipeline.detect()` 中拆出，供网页上传与 CLI 共用；登记阶段完成媒体验证、哈希、原子落盘及数据库记录，不进行分镜检测。
- 新增单文件上传接口 `POST /api/admin/sources/upload`，由前端顺序提交多文件；返回素材标识及是否重复。
- 为分镜、LLM 分析和独立检索更新增加持久化后台任务接口，支持启动、查询和失败/中断重试。对白、人物继续复用现有任务管理。
- 为对白选项增加 `method: auto | subtitle | asr`，默认 `auto`，兼容现有 CLI 和 API 调用。
- 素材详情接口增加统一四项工作摘要，包括现有结果、最近任务、进度、发布状态及启动条件；保留原有字段。
- 后台任务与 CLI 共用 `pipeline.lock`；管线忙时明确提示，不重复启动。冻结任务配置，服务重启后标记中断，由用户重试继续检查点。
- 上传使用临时文件，验证通过后移入素材目录；空文件、无视频流、超限或上传中断清理临时文件。新增独立素材上传限额，默认每文件 20 GiB，不沿用检索视频的 100 MB 限制。
- 旧素材继续使用已有分镜布局，不因当前设置变化重切。已有任务、结果、参考图和索引保持兼容。

### 旧素材状态与验收

- 从分镜文件、对白记录、LLM 注释、人物覆盖及当前发布版本计算真实状态，不批量重跑或修改历史数据。
- “已有处理结果”与“最近一次任务失败”分别展示。例如当前《给阿嬷的情书》应显示：分镜完成，1,126 个镜头及 2,336 个精细片段；ASR 对白完成，1,820 个有对白片段已进入检索；LLM 未处理；人物处理完成，当前核对结果为 854 个已接受、272 个已排除分镜。
- 验证批量上传、重复文件、失败清理，以及新素材上传后四项待办展示。
- 验证四项任务启动、前置条件、轮询、重复启动保护、中断恢复及发布失败单独重试。
- 验证字幕、ASR、自动回退、无音轨和空对白；人物资料缺失引导及已有资料启动。
- 使用隔离测试素材走通上传→分镜→处理→发布→检索→详情核对；验证旧素材状态展示和桌面、窄屏布局。真实旧素材仅进行读取验收。
- 更新素材管理说明，保留本次会话已完成的检索页面调整。

默认不增加自动串联四项工作的“一键全部处理”；各流程由用户点击对应按钮启动。
