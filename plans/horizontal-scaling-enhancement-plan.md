# 水平扩展完整交付方案

## 一、结论与当前实现质量

**当前分支已经搭起主要后端能力，但尚未完成水平扩展交付。未提交的修复补上了一批关键缺陷，也仍需要进一步收敛和验证。**

按照你确认的范围，本次完成原计划阶段 0–6 的全部必交付项，包括服务端集群、迁移恢复、桌面远程模式和真实验收。agent 保留单实例网关；agent 多实例、NFS、存储 HA/分片不纳入本次必交付，其他向量后端仅在原定容量闸门失败时启动评估。

当前代码和测试反映的完成情况如下：

| 范围 | 已提交实现 | 未提交改动 | 尚未闭合的问题 |
|---|---|---|---|
| 后端抽象与 PG | 协议、PG schema、SQL 方言、行对象、迁移和往返装载 | 修正大量业务路径静默使用 SQLite；恢复任务时补齐节点部署配置 | 上下文生命周期、连接预算、身份校验、追加迁移与升级验证不完整 |
| 检索 | 派生倒排、SQL BM25、部分投影与候选水合、Chroma 服务端连接 | 修正预热数据库入口和离线客户端测试 | 预热仍加载全量快照；人物查询仍走全快照；向量过滤成本和缓存上限未解决 |
| 队列与 worker | 租约、claim、重试、取消字段、worker 框架 | 实际并发、过期续租拒绝、事务 fencing、跨节点取消、账本事务内入队和终态提交 | Studio/index 未真正进入持久执行链；线程上下文、到期回收后的账本状态、外部副作用仍有缺口 |
| S3 与 staging | 对象上传、物化、媒体出口、下载 pin、清理基础 | 条件创建、输入摘要复算、下载预算、响应期 pin、检查点指针 | 权威文件覆盖不全；staging 预算与 pin 仍主要是进程内状态；部分调用提前释放物化 pin |
| Studio | 本机工作区修订校验、部分 If-Match | 增加远端文件指针、跨目录 CAS 测试、依赖上传 | 仍是逐文件发布；部分写接口未检查修订；递归上传旧目录可能覆盖较新文件，不能视为完整 manifest 发布 |
| 备份与迁移 | PG 快照、媒体/向量导出、基础 CLI | 移除危险的删 schema 行为；增加 preflight/activate、摘要校验、恢复媒体、续跑基础 | 本地恢复日志存在崩溃窗口；媒体闭包、迁移身份切换、真正的分阶段续跑和激活约束仍需完善 |
| agent 与运维 | 单实例网关角色、outbox、诊断和指标 | 流式代理、持久去重回执、先落事件后 ack、live/ready | 网关全入口、断流、重启恢复、生命周期和故障响应尚未完整验证 |
| 桌面与发布 | 远程模式、连接窗口、凭据文件 | 当前没有新增桌面修复 | 凭据存储、连接错误处理、SSE/上传/创作及三平台安装包验收未完成 |

实现的优点是本地模式保留较好，PG 语义和组件测试投入充分，分阶段演进方向正确。主要质量问题是：**组件通过测试被提前等同于集群链路完成，文档中的完成状态也存在互相矛盾。**

此前发现的高风险实例包括：

- `migration load` 声称拒绝非空库，实际直接删除 public schema。
- worker 只在队列完成时验证归属，业务表可能已经被旧 worker 写入。
- `--concurrency` 原先没有产生并行执行。
- Studio 的修订检查原先只读取本机文件。
- outbox 在事件持久化之前确认消费，崩溃会丢通知。
- PG/S3 配置下仍有业务路径进入本地 SQLite 或节点私有文件。

这些问题已得到部分修复，但不据此宣布集群就绪。

验证证据也需要准确区分：此前隔离后端联调选集为 **36 通过**；切换 Plan 模式后运行的定向检查为 **15 通过、12 个外部后端用例跳过**，ruff 通过。此前较大回归运行期间代码仍在变化，且出现旧测试语义失败，不能作为当前工作区全绿证明。**最终需要在冻结代码后重新完整执行。**

## 二、统一架构与正确性约束

后续保留现有改动及有效测试，将修补中的实现收敛为以下一致架构，避免继续通过零散接线扩展行为。

### 1. 运行上下文与身份

- local 保持 SQLite、本地 Chroma、文件系统、inline 和文件锁。
- PG 业务路径统一获取运行上下文，再向内部组件传递 Store、媒体、向量和执行上下文；禁止业务模块自行推断远端配置。
- 明确支持的部署组合；显式请求 cluster 时，任何共享后端缺失均拒绝启动。
- PG、S3 namespace、Chroma namespace 绑定同一 `library_id`，节点缓存同时按库身份隔离。为既有未隔离集合提供显式迁移步骤。
- 启动检查 schema、协议、分词器、模型空间及后端能力；DDL 仅由迁移命令执行。
- 实际落实查询池和控制池的独立容量、超时与连接总预算，控制通道不暴露为普通业务绕过入口。

### 2. 任务与发布事务

- 引入明确的任务事务接口：创建/重试账本与入队同事务；当前数据库触发器原型迁移为应用层显式事务，补偿扫描只负责历史数据和异常修复。
- 账本绑定当前 attempt；队列、账本和发布引用的终态同事务提交。到期回收、取消、失败上限、人工重试均同步更新用户可见状态。
- 将执行 token 显式传至任务、线程和发布事务。ContextVar 仅作辅助传播，不作为唯一正确性机制；显式 commit、线程池及独立子任务也必须校验。
- fencing 在受保护资源的提交事务中完成，并与回收/重派互斥。旧 attempt 可以留下不可见孤对象，不能改变当前可见状态。
- source/dialogue/person/topic/studio/index 全部接入持久调度。Studio/index 保留必要串行协调区，CPU 素材处理不全程持有全库独占锁。
- 调度触发使用稳定的周期去重键；单实例 leader 切换不能重复创建同一周期工作。
- 外部调用登记稳定幂等键、request_id 和恢复状态；未知结果进入“待人工核对”，不得盲目自动重试。GPU 槽位按物理资源组管理，同时验证模型服务真实并发限制。

### 3. 权威文件与媒体生命周期

- 小检查点使用不可变对象加 PG 指针；Studio 使用**不可变目录 manifest 加 PG 当前 revision 指针**。
- Studio attempt 先上传全部依赖并核验摘要，再以 expected revision 和执行 token 原子切换 manifest。`job.json`、`workspace.json` 保留为本地视图和导出逻辑视图。
- 人工修改统一使用工作区修订：读取返回 ETag/revision，修改携带 If-Match；集群缺失前置条件返回 428，修订冲突沿用现有 409，前端支持刷新和保留编辑内容。
- 覆盖全部权威文件：字幕及归档、对白/转写/分析检查点、人物图像、音乐、声音样本、选题输入、Studio 输入和产物。agent 附件仍在网关持久卷中。
- 大媒体保持流式读写；业务处理和 HTTP 响应在整个使用期持有物化上下文，不通过提前释放 pin 的裸 Path 传递远端媒体。
- 节点 staging 使用跨进程预约和活动 pin，预算包含输入、输出、临时空间；崩溃能回收预约，不能删除其他进程正在使用的文件。
- 统一管理 attempt、发布版本、备份和下载的远端 pin。GC 按标记、宽限、引用复验和条件删除执行，下载 pin 与删除竞争必须受同一协调机制保护。

## 三、实施顺序与接口交付

按以下依赖顺序分批实施、测试和提交。现有未提交修改保留，但不直接作为一个未经收敛的大提交合入。

| 批次 | 完整交付内容 | 批次退出条件 |
|---|---|---|
| A：事实基线与底座 | 重建需求—调用点—测试—证据矩阵；关闭 SQLite 回落；统一身份、上下文、连接池、配置组合及追加迁移 | 本地完整回归、PG 语义矩阵、旧 schema 升级和包内容检查通过 |
| B：执行正确性 | 显式原子入队、attempt 绑定、全部任务类型、取消和回收、事务 fencing、维护 gate、外部副作用恢复、GPU 准入 | 多进程暂停超 TTL 后无旧写回；队列与账本一致；跨节点取消；真实任务能并行 |
| C：共享文件与发布 | 权威文件全覆盖、Studio manifest/CAS、流式物化、跨进程 staging、统一 pins/GC | 清空任意 API/worker 缓存后仍可读取与续跑；并发编辑无丢失更新；GC 不破坏活动产物 |
| D：上传与媒体访问 | pending/multipart/complete/abort、配额和可信摘要、幂等完成、过期回收；浏览器独立 endpoint、CORS、Content-Type、Range/HEAD/ETag | 大文件、断点、重复完成、错误归属、磁盘不足、过期 URL 和长视频 seek 全部通过 |
| E：检索容量 | 人物/annotation/可见性过滤统一进入投影与统计快照；取消集群预热全快照和全 map；候选、缓存、请求体和查询时间预算 | 语义与参考实现一致，过滤不越界；规定容量与尾延迟闸门通过 |
| F：迁移与恢复 | 完整 preflight/export/load/verify/activate；统一 bundle 入口；分阶段日志、断点、媒体/向量闭包、秘密裁剪及反向迁移 | local→cluster→local 全量恢复一致；任何阶段中断可续跑；非空及异值目标不被覆盖 |
| G：集群与 agent | 两 API/两 worker、网关完整代理、outbox 重放、就绪检查、监控、部署和故障 runbook | 不同本地目录全链路通过；共享服务故障时明确未就绪；网关恢复不丢失或重复可见事件 |
| H：桌面与最终验收 | 安全凭据存储、远程连接恢复、三平台安装包、本地 sidecar 回归；双机故障、容量和灾备演练 | 原计划阶段 0–6 全部必交付项有执行记录和产物 |

接口和兼容性处理固定如下：

- 保留既有业务 API 和 CLI 入口，新增能力通过统一实现复用，避免 Web、CLI、MCP 各自走不同后端。
- 新增上传会话接口族，客户端只能向 pending key 上传；complete 成功后才注册正式素材。
- 保留 `migration preflight/export/load/verify/activate`。元数据单独导出可用于诊断，但缺少必要媒体或向量的 bundle 不允许正式激活。
- 迁移开始前持久化 migration_id 和源清单身份；PG 与本地恢复均消除“数据已落、日志未落”的窗口。
- 在续跑校验通过之前，不上传或改写目标对象；按对象和集合记录断点。恢复队列只重建可重试账本，旧 running attempt 不恢复为成功。
- `/api/live` 只表示进程存活；`/api/ready` 检查共享依赖和身份；`/api/health` 保留兼容性，明确其语义。
- agent 代理覆盖 SSE、附件、取消、重连和 MCP，处理流式关闭、认证和循环路由；业务 API 和远程 stdio MCP 不创建本机 agent 状态。
- 桌面凭据使用系统支持的加密存储；旧明文配置提供迁移。非法远程配置明确提示，不静默连接到另一个本地库。
- 设置页展示并校验部署配置，按字段区分可热更新和需重启；凭据只保存引用。同步中文 CLI/错误和中英 UI。

检索方面，先完成现有 Chroma 架构的过滤下推、分页和预算控制。容量测试失败时按查询计划和性能剖析修复；若证明当前后端无法达到原闸门，再启动原计划中的替代搜索/向量后端评估，**不降低验收门槛代替修复**。

## 四、测试、验收与可复现证据

### 自动化矩阵

- 默认本地测试继续离线运行；真实后端 CI 单独安装 cluster extra，使用固定版本/镜像 digest 的 PG、MinIO、Chroma。
- 每次执行自动创建隔离库、bucket、collection 和节点目录，成功或失败均清理；不使用用户数据和现有模型运行目录。
- 集群专项中，必需的后端缺失或用例意外跳过即失败，不能依靠默认测试中的 skip 宣布通过。
- 增加构造链和调用点静态检查，防止新的业务 SQLite 直构、未持 pin 的远端媒体消费及未登记权威文件重新进入代码。
- 完成源码、wheel、冻结 sidecar 与三平台安装包检查；最后冻结代码执行完整回归。

### 正确性与故障验收

使用两个 API、两个 worker、PG、MinIO、Chroma 和单实例 agent 网关，节点目录互不共享；先在本机多进程执行，再在两台主机重复。

覆盖 kill -9、SIGSTOP 超 TTL、后端断连、查询池耗尽、控制通道失败、上传和发布各边界崩溃、重复 claim/complete、取消竞争、双 API 编辑、备份同时 purge、网关重启与 SSE 重连。每项核对账本、token、发布指针、对象摘要和实际产物，不能只断言 HTTP 成功。

### 容量与质量验收

保持原计划门槛：

- 10 万/100 万 segments，100 万/300 万 vectors，每库三个索引版本。
- 20 并发、固定两 API 资源预算；热检索 p95≤2 秒、p99≤5 秒。
- 1%/0.1% eligible 过滤分别达标，所有查询不得越过人物或素材范围。
- 每 API RSS≤2 GiB，另报冷启动、候选规模、池等待、网络与资源占用。
- 无 GPU 瓶颈的真实 CPU source 任务，两 worker 吞吐至少为一 worker 的 1.5 倍。
- 确定性向量只用于工程容量；真实模型按确认版本的评测集执行质量验收，保留 Hit@5≥85% 的原定要求。

### 恢复与桌面验收

- 从真实 bundle 恢复空白目标，核对元数据、原文 JSON/BLOB、排序序列、媒体、向量身份及值、Studio 历史版本。
- 完成首次切换、目标写入后的逆向迁移、PG/WAL 和对象保护恢复演练；记录停写边界、吞吐、RPO/RTO。日常灾备 RPO≤24h、RTO≤8h 必须以实测通过。
- macOS、Windows、Linux 安装后验证远程检索、上传、SSE、创作、重启、断网恢复和凭据清除；同时验证本地 sidecar 工作流。

每次验收保存代码版本、配置摘要、镜像、硬件、数据生成方法、命令、原始结果和报告。性能失败、环境不足与功能失败分别记录，均不标为完成。
