# 人物库、演员表导入与人物出镜召回

## 目标与默认行为

建立“人物名字 → 参考形象 → 原片出镜时间”的关联，支持通过演员名或角色名跨素材检索。

- 命中已登记人物名时，默认要求有出镜证据；对白提及通过单独的“对白提及”模式检索。
- 支持正脸、侧脸、全身和背影；同镜头连续轨迹可继承已确认身份，跨镜头纯外观匹配须人工确认。
- 专用模型运行于独立服务；多模态 LLM 仅辅助演员表拆分，本次不对整片运行 LLM 分析。
- 复用现有分镜、画面向量和对白向量，人物能力独立处理、缓存与发布。

## 人物库与演员表 UI

- 新增“人物库”页面，支持新建人物、别名、多张照片、多次追加、修改配对和移除错误参考；支持从素材画面选取参考截图。
- 区分全局演员身份、作品内角色和角色阶段。演员名与角色名是两类身份，歧义提示必须标注身份类型；一个演员可饰演多个角色，一个角色可由多个演员出演；年龄、造型和服装分别记录。
- 素材默认独立归属一个作品，用户可把多份素材关联到同一作品。演员跨作品共用；角色可归属单部作品，也可跨多部电影（如系列片中的同一角色），角色身份不因扩展作品而重建。人物库身份、参考图与演员表导入均为全局操作，不绑定具体素材。
- 演员表导入是人物的主要创建入口（第一分区）：确认导入时同名演员与同作品同名角色自动复用，不存在的自动创建；导入作品可选已有或直接填写新名创建，不强制先手动登记身份。支持上传一张或多张演员表截图。LLM 输出候选条目、照片区域、演员名、外文名和角色名；裁切使用原图坐标，不固定列数或卡片布局。
- 导入页展示原图与配对预览，允许框选照片、修改名字、删去重复条目、关联已有演员及跨电影合并角色。条目不含阶段/年龄/造型/服装字段；同一人物的不同时期（如老年叶淑柔）直接写成完整角色名。确认后才进入正式人物库；不按同名猜测跨作品合并角色。
- 将用户示例纳入验收：八个主条目、小头像重复入口、代表作干扰，以及“叶淑柔／老年叶淑柔”的阶段关系。布局不明确、多人照片或 LLM 不可用时提供手动录入。

## 人物处理与证据

- 独立服务采用 InsightFace `PersonAnalysis` 的 `cheetah_l` 模型包，提取人脸和人体特征；应用负责跟踪、身份规则和持久化。接口支持人脸、人体检测及参考图匹配，但不管理视频轨迹或历史数据库。[官方说明](https://github.com/deepinsight/insightface/blob/master/python-package/docs/person_analysis.md)
- 新增人物模型配置与连接测试，固定模型文件摘要、预处理和特征空间身份。服务使用独立环境，沿用现有 GPU 锁；单 GPU 按阶段运行，不自动停止已有模型。
- 按已有原片镜头处理，默认最多分析 5 帧/秒，极短镜头至少取一帧，保留实际时间戳；镜头切换重置跟踪。使用 ByteTrack 关联镜头内检测结果。
- 人脸匹配综合多张参考图、图像质量及不同人物之间的分数差距；冲突或不确定结果进入待确认列表，不强行赋名。
- 已确认人脸可作为同轨迹全身、背影的身份锚点。失去可靠关联、轨迹交叉或重新入画时重新核验；不把姓名扩散到整个镜头或场景。
- 人体外观样本限定在作品与造型内。跨镜头外观匹配仅生成候选；未经确认不得进入严格人物召回，也不得继续扩展参考库。
- 保存人物 ID、轨迹、原片时间、截图、框位置、匹配分数、证据类型和确认来源。人脸身份不能独自区分同演员在同作品中的多个角色，此类角色归属须确认。
- 检测、特征提取与身份配对分别缓存。追加照片主要重新配对已有特征；修改名字无需重新推理。任务持久化、按镜头保存检查点，支持进度、失败重试和中断恢复。

## 召回、接口与版本

- 搜索页增加人物选择与自动识别姓名的提示标签，支持“人物出镜／对白提及”切换；同名或别名歧义必须选择具体人物。
- `TextSearch` 增加 `person_ids`、`person_mode`（默认 `auto`，另有 `onscreen`、`mentioned`）及多人物关系参数（默认同时出镜，可切换任一人物）。
- 默认姓名解析只匹配人物库中的名字和别名，不由 LLM 猜测身份；角色名支持后缀模糊识别：输入“叶淑柔”联合召回“老年叶淑柔”等变体角色（任一变体出镜即算，不算歧义），输入完整名只召回该角色（最长名优先）；演员与角色同名等无关歧义仍须显式选择。“演员 A 哭泣”先筛选 A 出镜的片段，再用剩余动作描述执行现有召回；仅查询人物名时可直接按出镜覆盖时长和证据质量排序，无需调用 WeMM。
- 出镜过滤先于各渠道候选截断与排名融合，避免人物片段在过滤前被挤出。对白命中不能突破出镜限制；多人物“同时出镜”要求证据时间有交集。
- 结果展示演员名、角色名、出镜区间、证据截图，以及人脸匹配、连续跟踪或人工确认等依据；支持定位到对应时间并纠错。
- 新增人物与参考图管理、演员表解析与确认、人物任务启动／状态／重试、候选确认接口；CLI 提供对应的处理和发布入口。任务请求立即返回 ID。
- 人物索引使用独立不可变版本；新增检索发布记录，绑定现有内容索引与人物版本，并原子切换活动组合。旧索引回退恢复对应组合，既有三渠道权重不变。
- 未处理人物的素材明确显示覆盖缺失；严格人物查询不偷偷降级为对白提及。人物模型离线不影响已发布的人物查询。删除素材清理其轨迹与缓存，全局演员及用户参考图单独管理。

## 素材管理镜头详情（追加需求，2026-10-17）

- 为素材管理中的每个镜头增加“详情”按钮；精细片段同样可查看对应区间的结果。
- 将“名称 / 备注”按钮文案改为“备注”。镜头操作顺序固定为：**详情、备注、收藏、隐藏**；收藏和隐藏保留已有切换行为。
- 点击“详情”打开该镜头的分析结果弹窗，同时、独立展示 **ASR 分析结果、字幕轨道结果、LLM 分析结果**，不以当前优先使用的对白渠道替代其他结果。
- ASR 展示已有转写与时间戳；未处理显示“ASR 未处理”，已处理但此镜头无对白显示该状态。
- 字幕轨道展示原片轨道信息及与当前镜头时间范围相交的字幕；没有轨道显示“无字幕轨道”。有轨道但此镜头无字幕、位图字幕无法提取文本及提取失败分别展示真实状态。
- LLM 展示已有动作、人物、场景、情绪、镜头语言、画面依据、对白推断和不确定信息等分析字段；没有分析显示“LLM 未处理”。
- 详情读取现有分析与字幕文本，不触发 ASR 或 LLM 推理，也不要求发布索引或在线模型。字幕读取可缓存，按原片时间筛选，不能把整片对白显示为镜头结果。
- 验证按钮顺序、缺失状态、三类结果同时存在、独立来源、跨镜头时间边界与无需模型/发布索引可用性。

## 验证与落地

- 自动化覆盖演员／角色／阶段关系、多次补图、重名、歧义配对、不同演员饰演同角色，以及模型空间变更后的缓存隔离。
- 验证多种演员表版式、错误坐标、重复头像、多人合照、缺失角色名、LLM 失败及人工修正流程。
- 核心反例：两人聊天提到 A，但 A 没有出镜，严格姓名查询必须排除；“对白提及”模式仍能找到该片段。
- 验证正脸转背影、人物交叉、遮挡、镜头切换、相似服装、角色换装及跨作品查询，纯外观候选未经确认不得泄漏到正式结果。
- 验证补图不重新提取全片特征、不重新调用已有 WeMM 嵌入；隐藏、素材筛选、发布失败保护和回退继续有效。
- 提供模型服务部署脚本与操作文档。真实处理先用当前电影约三分钟区间和用户确认的参考图验收，再扩展整片；记录耗时、自动匹配、待确认和出镜覆盖情况。人工核对前只报告工程验证结果。


## 恢复后衔接与验收

- 保留跨作品角色、演员表导入优先与变体角色联合召回的当前实现；同名演员已有多个匹配时要求显式关联，不选择第一条记录。
- 出镜审核按分镜分组，勾选演员与可选角色并保存。人工确认的范围为整个分镜，界面要求核对完整镜头；未选证据驳回留档。阶段不参与分镜审核，逐条审核 HTTP 接口移除。
- CLI `persons review review.json` 与分镜审核使用相同请求结构；搜索结果纠错链接仍可按证据 ID 定位所属分镜。
- 失败/中断人物任务可删除任务记录，保留特征缓存和证据；人工分镜排除不会因更换模型空间重新进入结果。
- 验证分镜审核前端、CLI/API 衔接、跨空间复核、无关同名角色歧义与部分时期变体联合召回。
