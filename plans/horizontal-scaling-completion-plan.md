# 水平扩展剩余能力闭合与单机故障验收计划

## 1. 目标与交付边界

以当前 `e54b645` 为基线，完成交付矩阵中全部剩余实现和接入缺口，完成当前 Mac 单机可执行的功能、并发、恢复和故障验收。保留现有本地模式、业务 API 和 CLI。

执行开始时将本计划保存为 `plans/horizontal-scaling-completion-plan.md`，更新现有交付矩阵，逐项关联调用点、测试与原始证据。保留工作区原有 `config.example.yaml` 改动。

用户已确认：

- 覆盖全部剩余功能，不只处理安全和恢复。
- 上传同时支持现有 API 分片中转与浏览器直连 S3 的预签名 multipart。
- 双机、规定大容量、真实模型、Windows/Linux 实测保持独立验收状态；相应实现和自动化仍在本轮交付。
- agent 保持单实例网关；NFS、存储 HA/分片、多租户和 agent 多实例维持原有范围约定。

## 2. 实现顺序与退出条件

### 第一批：运行上下文、启动准入与任务边界

- 审计全部缓存、后台线程、API 生命周期和 CLI 前台入口；缓存身份统一包含库 UUID 与后端身份，远端上下文在退出时释放连接、staging owner、线程及客户端。
- 集群启动和 readiness 校验 schema、运行协议、库身份、索引空间、分词器和后端能力。集群缺少必要派生数据时明确要求回填，不进入无预算的全快照路径。
- 审计六类任务的提交、重试、恢复与终态；补齐绕过持久账本的处理入口。业务写入、发布和取消继续使用显式执行凭证。
- GPU 准入改为显式物理资源组配置，支持多个模型服务共享同一组容量；未声明任务所需资源组时，集群拒绝该任务。worker 租约过期不能证明远端 GPU 请求已停止，未知执行状态保留占用并进入核对流程。
- schema 仅追加迁移，从当前 v21 顺序升级；不改写已发布 DDL，不支持混合协议版本滚动运行。

退出条件：上下文关闭、换库缓存隔离、查询池耗尽、控制通道失败、前台入口与持久入口一致性测试通过。

### 第二批：权威文件、staging、远端 pins 与 GC

- 建立统一权威资源登记和引用遍历入口，供业务读取、备份、迁移和 GC 共用。覆盖字幕及归档、转写/分析检查点、人物图像、音乐、声音样本、选题输入、Studio 输入与历史产物。
- 清理剩余远端裸 Path 消费。处理期间持有物化上下文；导出 HTML 所引用的媒体复制到导出目录，不能指向可淘汰缓存。
- 为输出和临时工作目录增加跨进程工作集预约。无法可靠预估大小的输出使用可增长预约；扩容失败立即停止写入并返回明确诊断，不突破预算。
- 统一 attempt、发布版本、备份和下载的远端 pin。活动 pin 可续期；预签名下载 pin 至少覆盖 URL 有效期及现有下载宽限。
- 新增持久对象协调状态。引用发布、pin 创建和删除使用相同的对象协调锁；GC 执行“标记候选—等待宽限—重新读取当前引用与 pins—校验对象身份—条件删除”。不能仅复用扫描开始时的引用集合。
- 删除中的对象拒绝新签名或发布；崩溃后的删除意图可幂等恢复。后端缺少安全删除所需能力时停止自动 GC，并在 doctor 中明确报告。
- 当前目录历史继续保守保留；本轮不自动缩短历史保留期。

退出条件：清空节点缓存仍可读取和恢复；跨进程预算、进程崩溃回收、备份/purge、发布/GC、下载/删除竞争均无数据损坏。

### 第三批：双路径上传与媒体访问

- 扩展现有上传会话，创建时选择 `api` 或 `s3` 传输方式；默认仍为 `api`，保持现有客户端兼容。
- 增加按会话签发分片 URL、查询/登记分片及恢复 S3 multipart 状态的接口。客户端只能写该会话的 pending 对象，不能指定正式对象 key。
- 增加独立浏览器 endpoint 和允许的浏览器 origin 配置；签名使用浏览器实际访问的 endpoint。服务端数据访问仍使用内部 endpoint。
- doctor 检查 endpoint、签名和 CORS 能力；不自动覆盖已有 bucket CORS。提供最小部署配置及验证命令。
- complete 使用持久完成状态和互斥协调；通过服务端流式读取复算完整摘要和大小，再原子登记正式资产。ETag 不能充当 SHA256。
- abort、过期回收和崩溃恢复同时清理应用层分片与 S3 原生 multipart；重复 complete 返回同一结果。
- 两条路径使用相同归属、配额和摘要规则。浏览器直传失败后保留会话，用户可续传或显式重新上传，不隐式重做整个上传。
- 补齐 Content-Type、HEAD、Range、If-Range、ETag 条件请求、过期 URL 和长视频 seek。

退出条件：真实浏览器通过独立 endpoint/CORS 上传；中断、重复完成、错误凭据、摘要错误、过期及磁盘不足测试通过。

### 第四批：检索内存与查询预算

- 用可分页 eligible 查询及 SQL 聚合统计替代完整 eligible 列表；候选只水合所需字段。
- 能下推到 Chroma 的条件直接下推；其余条件分页读取 ID 后分批查询，并合并全局排序。不能通过截断 eligible 集合扩大范围或静默改变结果。
- 默认 ID 页大小 512；候选上限沿用现有 `search.candidates`。增加集群查询期限、缓存字节上限和缓存条目数限制，默认查询期限 5 秒、查询缓存预算 64 MiB。
- 查询期限同时约束池等待、SQL、向量请求和水合。预算耗尽返回明确可重试错误；容量报告将错误请求计入失败，不从延迟统计中排除。
- SQL BM25、人物、annotation、可见性和素材范围使用同一 eligible 定义；集群不自动回退到全量快照。
- 容量脚本保留原数据规模、维度、并发和质量门槛。若现有 Chroma 查询路径达不到门槛，保留失败证据和剖析结果，再启动原计划允许的替代后端评估。

退出条件：与参考实现的筛选、评分和排序一致；页边界无遗漏；窄范围不越界；内存、缓存和超时预算可验证。

### 第五批：迁移、激活与恢复

- 在任何目标对象写入前持久化 migration_id、源清单摘要、源库身份和阶段状态；同一迁移可恢复，其他迁移或异值目标一律拒绝。
- 增加对象、向量集合及批次级恢复账本。写入成功而日志未落时，续跑先验证已有目标内容，再补记完成；禁止盲目覆盖或重复 upsert 异值数据。
- 阶段固定为：预检、身份绑定、媒体、向量、元数据、恢复任务、验证、激活。
- 源元数据对账与目标运行状态分开记录；旧 running attempt 不恢复为成功，只转换为可重试或待核对状态，且在激活前不执行。
- 目标处于迁移状态时，业务节点不得写入或领取任务。activate 在完整验证后原子开放业务；已激活并产生新写入后禁止重放旧 bundle。
- 用统一资源登记核对媒体、向量和 Studio 历史闭包。裁剪已登记秘密字段，未知秘密载体阻止正式激活并列出具体位置，不改写普通用户内容。
- 完成目标产生新写入后的反向导出、装载和校验。
- 提供 PG/WAL 和对象保护恢复脚本，在独立持久测试卷上演练；组件测试的 tmpfs 不用于灾备结论。

退出条件：每个阶段和写入/记账边界中断后可恢复；非空及异值目标未被覆盖；完整 local→cluster→local 往返一致。

### 第六批：网关、设置页、桌面和文档

- 审计 agent 的 SSE、附件、取消、重连、认证、MCP 和流式关闭；业务 API 与远程 stdio MCP 不创建本机会话状态。
- 网关重启后按持久游标重放 outbox，事件落盘后才确认；重复投递保持同一可见事件身份。
- readiness 增加有界依赖探测，明确区分数据库、控制通道、S3、Chroma、迁移状态和网关故障；liveness 保持进程存活语义。
- 设置页增加部署配置读取、验证和保存接口，返回配置 revision、字段可编辑性及重启要求。模型/检索运行参数保留热更新；身份、后端、连接池、资源组和存储变更需重启，库切换必须经过迁移流程。
- 凭据仅接受已有环境变量或密钥引用，不通过设置 API 保存、回显明文管理凭据。保存使用修订校验；无可写配置文件的部署返回明确只读状态。
- 完成 macOS 实际应用的完整创作流程、重启、断网恢复和凭据清除；系统安全存储只使用隔离测试配置和随机测试令牌，失败不自动降级为明文。
- 同步中文 CLI/错误及中英 UI，清理旧部署指南、inventory 和 roadmap 中的矛盾状态。

退出条件：网关与实际桌面故障流程通过；部署字段的验证、修订冲突、热更新和重启边界均有测试。

## 3. 单机验收矩阵

新增统一单机故障验收入口，自动创建两 API、两 worker、单网关、PG、MinIO、Chroma 和互不共享的节点目录；只清理本轮服务和数据。

必须执行：

- worker `kill -9`、`SIGSTOP` 超 TTL、旧进程恢复、重复领取、取消竞争和发布边界崩溃，核对账本、执行凭证、发布指针与产物摘要。
- 查询池耗尽、控制通道失败、PG/S3/Chroma 断连与恢复，核对 live/ready、任务状态和恢复行为。
- 网关事件落盘前后及确认前后崩溃、SSE 重连、附件中断、MCP 断流，核对可见事件身份和资源释放。
- 双 API 真实浏览器编辑冲突与保留输入；本轮使用真实 PG 冲突响应，补齐此前响应注入与后端 CAS 分开验证的缺口。
- 发布/GC、备份/purge、下载/删除和 staging 淘汰竞争；检查活动对象与历史产物未损坏。
- 两种上传路径的续传、完成与回收边界，以及真实浏览器 CORS、Range、过期 URL 和 seek。
- 迁移各阶段强制退出、续跑、异值保护、目标新写入后的逆向迁移和持久卷恢复演练。
- macOS 实际应用、本地 sidecar、默认依赖负向检查、cluster extra、源码包、wheel、冻结产物及完整离线回归。
- 独立运行真实 CPU 吞吐测试，保持 ≥1.5 倍门槛；完整回归期间不并行打包或运行其他验收负载。

集群必需依赖缺失或测试意外 skip 均令专项失败。每次记录代码版本、源码摘要、服务版本、硬件、数据规模、命令、JUnit、日志与结果；失败、环境不足和中断分别保留。

## 4. 提交、验收状态与完成标准

- 按六批顺序提交；每批实现、集成和定向测试完成后更新矩阵，最后冻结代码执行完整回归。
- 执行开始时保存本计划，不覆盖原增强方案；所有剩余矩阵条目映射到上述批次或外部验收。
- 本轮完成标准：全部剩余实现和接入调用点关闭，单机可执行的验收全部有记录，文档与代码一致。
- 规定大容量、真实模型、双机、Windows/Linux 安装和系统密钥环实测保持原门槛。缺少环境时保留待验收，并交付可执行脚本；不以脚本或较小样本标记通过。
- 单机灾备演练记录实际数据规模与恢复时间；只有代表性规模实测满足要求后，才将 RPO≤24h、RTO≤8h 标为完成。
