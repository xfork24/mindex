# 界面文案与多语言（i18n）

Mindex 界面中英双语，**中文原文是文案唯一源**：先写中文，再配英文译文；键名与译文都由中文原文驱动。本页讲清键规则、生成链路与回归校验；页面热切换的行为见下文「语言切换」。

## 文案目录与键规则

- 文案目录：`frontend/src/shared/messages.json`，3,100+ 键，随文案增长。每键一个对象：`{"zh": "中文原文", "en": "English"}`，占位符用 `{name}` 形式，中英文占位名一致。
- 键一律带 `ui.` 前缀，两种取法：
  1. **语义名**：可读的稳定标识，如 `ui.studio_tab_jobs`、`ui.studio_tabs_aria`。用于长期存在、可能改字的文案（改字不改键）。
  2. **中文原文哈希**：`ui.` + 中文原文 sha1 前 12 位（如 `ui.a89476443984`）。用于一次性的长文案；正文变化即换键，避免旧译文漂移。
- `system.*` 前缀是系统诊断文案（后端消息映射用，见下文），不要用于界面静态文案。

## 生成链路（勿手编镜像）

```bash
python scripts/build-messages.py          # 由 messages.json 生成 messages.js
python scripts/build-messages.py --check  # CI 校验两者一致，不一致退出码 1
```

`messages.js` 只是给页面 `<script>` 加载的镜像（`window.MindexMessages = <messages.json 内容>`），**永远不要手工编辑**——改文案只改 `messages.json`，再重新生成。

文案改动后还要运行 `python scripts/build-assets.py`，把页面里 `/assets/…?v=` 的版本参数刷新为内容哈希（详见 [前端结构](frontend.md#资源版本)）。

## 语言切换（frontend/src/shared/i18n.js）

- 切换**不重建 DOM**：只更新现有节点的文案与相关属性，保留未提交的输入、滚动位置与正在播放的媒体。
- HTML 侧用 `data-i18n` 属性绑定键（支持带索引的列表绑定，如 `data-i18n="[[0,'ui.xxx']]"`），`data-i18n-aria-label` 等属性同理。
- 用户内容（素材名、任务标题、模型输出）不翻译，始终显示原文。

## 后端消息反向映射（backend/src/shared/i18n.py）

后端错误与诊断消息仍是中文原文。`shared/i18n.py` 在启动时把 `messages.json` 里含中文的 `zh` 文案编译成反向正则模式：响应携带中文消息时，匹配出稳定的 `message_key` 与 `message_params`（占位符实际值）一并返回，前端按键渲染当前语言的译文；未匹配的回落 `system.diagnostic`。因此**后端新错误消息也应登记进 messages.json**，否则前端只能显示通用诊断文案。

## 校验与回归

- `tests/test_i18n.py`：以 `--check` 方式校验 messages.json 与 messages.js 一致，并检查键规则。
- `tests/i18n_ui.cjs`：浏览器回归——切换语言后未提交输入保留、DOM 不重建。
- CI 顺序提醒：先 `build-messages.py` 再 `build-assets.py`，两个 `--check` 都在 CI 里运行。
