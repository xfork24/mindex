# 人物库、出镜检索与镜头详情

实现范围与验收要求见 [person-recognition-plan.md](../plans/person-recognition-plan.md)。人物库入口 `/persons`，素材管理镜头详情入口 `/admin`。人物模型不参与既有 WeMM 三渠道索引构建。

## 先登记，再处理和发布

1. 演员表导入是人物的主要创建入口（页面第一位）：确认时同名演员与同作品同名角色自动复用，不存在的自动创建，无需先手动登记。作品在“演员表导入”中创建（同页“或新建作品名”），在“人物与参考图”中只作为筛选条件出现，也可手动登记演员（全局）和角色（归属一部或多部作品，跨电影角色共用同一身份）。演员与角色是不同身份，姓名歧义提示会标注身份类型。角色可有多个演员，演员可在多个作品出演多个角色。人物库身份与参考图均为全局管理，不绑定具体素材；素材仅通过“所属作品”参与角色关系。手动新建允许重名身份；演员表仅在已有唯一匹配时复用，多名同名演员须明确选择。检索遇到歧义必须选择具体 ID。
2. 在“处理与审核”中核对素材所属作品。每个素材默认有自己的作品，可关联到同一个已有作品。变更作品会清除草稿中的旧出镜配对与覆盖，发布版本仍可回退，重新处理后再发布。
3. “人物与参考图”默认只列出演员：点击演员卡片在整行展开该演员的全部角色（宽卡片），再点收起；卡片标题为中文名（外文名/别名随其后），下一行显示角色数。作品、演员、角色三个筛选对演员与角色同时生效；启用角色或作品筛选后，没有任何匹配角色的演员整张隐藏。演员卡片与角色卡片各自独立管理参考图：角色的照片配给角色本身（不与演员照片混用），可分别追加与移除；点击照片下的“修改”同时编辑姓名、别名及配对关系，角色卡片编辑作品与演员关系。未关联演员的角色也会单独列出，可补充出演演员。演员与角色均可在卡片上直接删除（按钮样式与其他操作一致，仅用红色区分）：已接受分镜确认到该身份，或整镜尚未确认且候选涉及该身份时，删除会被拒绝；已接受分镜仅确认其他身份时，其中未结清的该身份候选不再拦截，并弹出完整关联列表，显示素材、原片时间、分镜 ID 及逐镜核对入口；此列表包含非最高分身份，不受审核分类筛选限制。参考图不阻碍删除，会随身份一同移除；删除演员会自动解除其角色配对，已排除审核留档及已发布快照保留。角色参考图同样参与人脸匹配，每张照片只归属照片中的一名演员；角色有多名出演演员时必须明确选择，匹配按角色比较最高分与置信差；同演员的多个角色分别竞争，同角色多演员保留获胜照片的演员来源。角色关系变更后，不再属于该角色的演员照片会在任务报告中提示重新配对。“从原片选取参考”可同时指定演员与角色，定位时间后预览该帧并在截图上拖拽框选人物；截图始终配给所选角色，不框选则保存整幅画面。每张参考图卡片左上角显示编号徽章（uuid 前 8 位，悬停显示完整编号），与处理任务日志中「参考图 xxxxxxxx」的指向一致。上传、原片截图与演员表导入确认在入库前执行与处理任务预检同口径的质检：不合格的图片整张拒绝并返回原因（同批其他文件不受影响，重传已入库旧图不受新策略影响）；人物识别服务不可用时拒绝添加，须先启动人物服务（见「独立模型服务」）。多选上传按文件聚合结果提示「成功 N 张，失败 M 张」及各失败文件的原因。移除参考后重新处理已有区间，重新发布；视频特征不会重算。
4. 演员表可上传多张图（一次多张，或分多次追加到当前草稿；同内容图片自动忽略）。页面默认列出全部历史 cast 图片（含已确认导入），点击即加载对应草稿继续编辑；按钮始终可操作，已确认草稿上的写操作由服务端拒绝并给出提示。每张历史图片可单独删除（草稿与已确认均可）：删除即从历史中消失，草稿图片删空后整条草稿移除；已确认导入建立的演员、角色与参考图不受影响。自动拆分逐张执行并显示每张的进度与失败状态，可单张重试；失败时保留该图已有条目，不阻塞其他图。全部原图纵向排列，条目统一列在图下方（每行两个）；条目可指定所属原图，选择条目后在对应原图拖框（坐标为原图像素），也可用 x1/y1/x2/y2 精确修改。条目只含演员名与角色名：同一人物的不同时期（如老年叶淑柔）直接写成完整角色名，不使用阶段字段。同名演员与同作品同名角色自动复用并合并演员表；跨电影同一角色可在条目中显式关联。导入作品可下拉选择，也可直接填写新作品名创建。确认时批内重复条目（演员+角色同名且未关联现有人物）自动跳过并汇总提示；同内容同框的重复导入只复用既有参考图，不重复写入。确认时逐条目执行参考图入库前质检，任一条目不合格整批拒绝并点名「条目 N（演员名）」及原因，草稿保持未确认，不会留下部分导入；人物识别服务不可用时同样整批拒绝。未确认不会写入人物库。LLM 不可用时直接手动增加条目；角色名缺失允许只建演员。
5. 先用约三分钟区间处理。起点默认 0 秒，终点默认 0，表示从起点处理至片尾；填写具体终点秒数可限定区间，旧请求的 null 仍表示至片尾。任务请求立即返回 ID，按分镜保存检查点。任务失败或服务重启后可重试；追加照片仅重新提取新照片并重新配对已有视频特征。改名后重新发布即可，不需要重跑推理。
6. 核对候选或纠错（位于“处理与审核”页的“人物处理任务”之后，面板名“出镜审核”）：审核列表按镜头分组，显示完整证据和状态计数。“待确认 / 已接受”支持“演员-角色筛选”，每项显示当前素材、状态下的分镜总数。待确认分镜只归入最高分候选的演员-角色分类（不按帧数或平均分）；已接受分镜按全部已接受身份筛选，包含自动接受及人工确认，多人出镜时可在各确认人物的筛选下分别找到同一分镜。已驳回身份和仅待确认身份不计入已接受分类。各分类计数分别按分镜去重，“全部”按分镜总数显示，不累加重叠分类。重新核对后按当前确认人物查找。列表逐人显示确认来源及分数：自动确认取该身份已接受证据的最高分；人工确认显示“人工确认”及原始候选最高分，不展示人工记录内部固定的 1.0。新人工核对记录冻结原始分数，旧记录从保留帧恢复；从未有该身份候选时显示“原始分数未记录”。分数仅使用同一演员-角色配对的证据，不借用仅演员证据。“已排除”表示已确认无出镜人物，不显示演员-角色筛选或候选分类，保留完整证据以便重新核对；已排除证据不会阻碍删除对应演员或角色，删除按整镜状态检查：已接受仅检查确认身份，待确认检查候选身份，已排除不拦截，参考图随身份删除。审核列表、筛选、计数、确认人物、识别证据和核对 checkbox 均只包含当前作品的有效演员-角色配对；不列全库演员或“未指定角色”。迁移直接删除未关联角色的仅演员证据，不自动推断角色；所有演员-角色配对与人工排除记录均保留，既有发布快照不变。清理后无有效角色证据的分镜归入“无候选”，人工明确排除的整镜保持已排除。没有身份候选的证据及已处理但没有检测结果的分镜归入“无候选”，未处理分镜不混入审核列表。分类与筛选先于分页，卡内始终保留整个分镜的完整证据。卡片右上勾选框可多选分镜，“全选当前筛选（含所有页）”可选中该分类下全部分镜；翻页保留选择，切换素材、状态、身份筛选或重新读取证据会清空旧选择，也可点击“取消选择”。顶部“批量核对”对全部所选分镜统一应用同一组人物勾选（批量弹窗不显示图片与视频）。状态按分镜归类而非逐帧：任一帧被自动接受或人工确认，整个分镜即为“已接受”；完全没有已确认帧且仍有候选证据的分镜，以及已处理但没有检测结果、尚未人工核对的分镜，列在“待确认”；整镜证据均被驳回时为“已排除”。“已接受”不代表整个镜头已完成人工审核，卡内仍显示剩余候选，并汇总所有帧中识别到的演员-角色身份（含候选、保留的已驳回模型证据），显示各身份最高分和识别证据数。旧任务需要重新运行才能得到全帧结果；旧抽帧缓存不会用于新的全帧任务。播放完整镜头后勾选角色及其演员配对，再保存；也可排除此镜头的全部人物证据。勾选结果是人工确认的整个镜头出镜区间，其余旧证据驳回留档，该分镜随即不再出现在待确认列表。重新处理或更换模型空间不会覆盖此人工结论；此操作不会修改已发布版本。
7. 在设置页最底部的“索引版本”中点击“发布当前检索组合”（人物库页不再放发布入口），生成不可变人物快照及绑定内容索引的检索发布记录，并在单个事务内切换。发布记录（检索组合）可逐条删除；正在生效的组合受保护，需先恢复到其他组合再删除，无其他组合引用的人物快照会一并清理，身份与证据不受影响。处理与审核页只显示最近 3 条任务日志，更早的记录仍保留在库中。任务日志是不可变的历史记录：其中的分镜数、耗时等一律取该次任务自己落库的结果（task.result）；页面统一使用“分镜”，不展示接受 / 候选帧数，不随之后的重跑或人工出镜审核而变化。出镜审核（分镜级证据核对、批量核对）位于同一页的「人物处理任务」之后。人物服务离线不影响已发布证据查询。回退可以选择发布组合；既有内容索引回退恢复该索引最近的对应组合。

角色检索支持模糊识别：输入“叶淑柔”会同时召回名为“老年叶淑柔”“少年叶淑柔”等以该名字结尾的角色（联合命中，任一变体出镜即算），不会因变体同名报歧义；输入完整名“老年叶淑柔”则只召回该角色（最长名优先）。演员名与角色名同名、或无关身份同名的歧义仍必须显式选择。演员出镜查询通过发布快照中演员关联的角色命中；角色查询保持精确，任一或同时出现的多人语义不变。新匹配规则更新缓存版本并复用兼容视频特征。旧发布快照保持不变；重新处理、发布后使用新的角色证据及关系快照。

## 独立模型服务

应用侧安装解码与 ByteTrack：

```sh
uv sync --extra person --extra dev
./scripts/setup-person-service.sh
```

模型环境为 `.venv-person`。SDK 固定到 InsightFace commit `81929474ec02e54e3655f6841bced800009c592d`，使用 [`PersonAnalysis` 官方接口](https://github.com/deepinsight/insightface/blob/81929474ec02e54e3655f6841bced800009c592d/python-package/docs/person_analysis.md)。`setup-person-service.sh` 通过 `scripts/download_insightface_weights.py`（幂等、仅标准库）从官方 model-zoo 下载完整 `cheetah_l` V2 到 `models/insightface/models/cheetah_l/`，并做一次引擎级验证；位置可用 `MINDEX_PERSON_MODEL_ROOT` 覆盖，`run-person-service.sh` 默认导出同一根目录。也可按 `person.model_root/models/cheetah_l/` 手动安装离线包。服务检查四类任务、所有模型文件 SHA-256 与 manifest 摘要；服务自身不自动下载或修复模型，没有模型包时启动明确失败；下载脚本遇到损坏的已有包会改名保留（`.invalid-<时间戳>`）后重装。

```sh
./scripts/run-person-service.sh
curl http://127.0.0.1:4050/health
```

把 health 的完整 `space` 保存为 YAML `person.expected_space` 或人物模型档案的 `expected_space`，固定权重摘要、预处理、SDK/ONNX Runtime、执行 provider 与尺寸。设置页可建立人物模型档案并测试连接。没有设置 expected_space 时，任务仍会固定启动时的空间，响应或完成时空间变化会拒绝发布；不同空间的参考和视频特征绝不混用。

默认 CPU provider。GPU 环境将 `onnxruntime` 换成对应 CUDA 的 `onnxruntime-gpu`，并设置 `MINDEX_PERSON_PROVIDERS=CUDAExecutionProvider,CPUExecutionProvider`。CPU/GPU 的 space 不同，需要重新提取。服务启动时持有与现有模型服务相同的 `MINDEX_GPU_LOCK`（默认 `~/.cache/mindex/gpu.lock`）；锁已占用会启动失败，不会停止其他模型。单 GPU 由操作者按阶段启动服务。已有通过 llama-server 启动的外部服务不一定持有此锁，仍需操作者安排显存。

`MINDEX_MODEL_API_KEY` 是服务端 Bearer 密钥。应用通过人物配置的 `api_key_env` 或模型档案保存的密钥发送；任务快照和 API 输出不会序列化明文密钥。

人物任务使用启动时当前生效的人物识别模型配置（任务内固定模型空间及识别阈值）。应用在本地按原片 PTS 解码并按 person.frame_interval 抽取实际视频帧（默认 15，即第 1、16、31…帧；1 表示逐帧），匹配成功后仍继续处理其余帧。短分镜至少抽取首个有效帧；person.fps 仅兼容旧配置，不参与抽帧；跟踪频率根据实际帧间隔计算。仅把抽取的 JPEG 按每批最多 16 张发给 `/extract/frames`，避免每个镜头重复上传整片。人脸/人体特征由服务提取；应用使用 ByteTrack 在镜头内关联。镜头边界、检测缺失、交叉框、关联不可靠或冲突人脸都会撤销身份继承。未匹配或不确定的检测保留为候选。证据覆盖只计实际帧后的有限时段，不把某一帧的人物扩散到整个镜头。

人物任务仅加载素材所属作品的有效角色参考图，不使用演员通用图或其他作品的角色图。人脸匹配按角色聚合合格参考图的最佳分数，并检查不同角色之间的分数差；候选也直接带角色。分数不是正确率。参考图校验只认清晰人脸主体：画面边缘的无人脸人体检出（路人、肩膀）不影响，群照与主体背对镜头时拒绝。质量门槛分两条，均可在设置页「人物识别」档案中调整：`min_reference_quality`（默认 0，全部参考图参与匹配，抬高后低于门槛的参考图会在任务报告 `reference_errors` 中显式列出对应演员、角色名称及参考图标识，名称保留任务当时的记录；旧日志按仍存在的参考图补充身份）与 `min_face_quality`（默认 0.6，视频帧低于此值不做自动确认）。添加参考图（上传、原片截图、演员表导入确认）时即执行同一判定与文案，检测结果（含被拒图片）写入 `person_features` 缓存供处理任务复用；人物识别服务不可用时拒绝添加。角色有歧义时保留角色候选，需人工确认，不生成独立演员出镜结论。纯外观的跨镜头候选，只使用同作品、同特征空间、人工确认且关联角色的样本；候选不会进入严格检索，也不会扩展样本。人体外观匹配始终只生成候选，需人工核对。

## 检索与接口

`POST /api/search/text` 新增：

```json
{"text":"阿青哭泣","person_ids":[],"person_mode":"auto","person_relation":"all"}
```

`auto` 只解析人物库姓名和别名；角色名支持后缀模糊识别（输入“叶淑柔”联合召回“老年叶淑柔”等变体，变体之间任一出镜即算，不影响多人物 `all` 的同时出镜判定）。查询中显式的中文文档指称（如「关于阿公郑木生的记录」「某人的照片」）只把被指称的姓名保留在语义查询中、不入出镜过滤——否则无同框证据时候选恒为 0；同一姓名在查询另一处作为出镜主体时仍进入过滤。该规则只针对明确的文档指称写法，不是通用语法解析；自动模式且查询包含此类指称时，分镜召回签名加入规则版本，不复用规则修复前的空候选结果。命中时先以已发布出镜证据筛选，再用“哭泣”执行现有渠道召回，渠道权重不变。仅人物名时按出镜覆盖和证据质量排序，不调用 WeMM。`onscreen` 要求人物；`mentioned` 只检索对白并按登记名称/别名限制字面提及。`all` 要求多个人物（或变体组）出镜时间有交集，`any` 接受任一人物。覆盖缺失会返回提示，不降级为对白提及。搜索结果可查看截图、定位出镜时间和进入人物库纠错。

主要 API：

- `GET /api/persons`：实体、参考、任务、作品关系、覆盖与发布记录。
- `POST /api/persons/entities`、`PUT /api/persons/entities/{id}`：登记与修改。`GET /entities/{id}/linked-shots`：分页列出全部未排除关联分镜；`DELETE /entities/{id}`：无关联分镜时删除身份及参考图，有关联时返回 422，`detail.linked_shots` 提供具体分镜及总数。
- `POST /api/persons/references`（multipart，演员照片给 `actor_id`，角色照片给 `role_id` 及照片中的 `actor_id`；角色只有一名演员时可省略 `actor_id`）、`PUT/DELETE /api/persons/references/{id}`（PUT 的 JSON 使用相同配对字段）、`POST /api/persons/references/from-source`。三条参考图添加路径（含 `/imports/{id}/confirm`）入库前同步质检：不合格返回 422 及中文原因（导入确认会点名「条目 N（演员名）」），人物服务不可用返回 503；被拒图片不写入人物库。
- `POST /api/persons/imports`（multipart 多文件）、`POST /imports/{id}/parse`、`PUT /imports/{id}`（保存草稿）、`POST /imports/{id}/confirm`（人工确认）。
- `POST /api/persons/sources/{id}/process`：`{"start":0,"end":180,"publish":false}`，返回 202 和任务 ID。
- `GET /api/persons/tasks/{id}`、`POST /tasks/{id}/retry`、`POST /tasks/{id}/cancel`（取消排队中或运行中的任务，其他状态 409；已保存的检查点保留，可重试续接）。
- `POST /api/persons/identify`：multipart `file`（≤20 MiB）+ `top_k`（默认 5），对图片中的每张人脸按角色和按演员返回前 k 个候选（智能助手 `identify_person` 使用）；人物服务不可用或空间不符返回 503。
- `GET /api/persons/evidence?source_id=...&status=candidate`：分页读取原始证据。
- `GET /api/persons/review/shots`、`GET /review/shots/{shot_id}`：按镜头读取审核证据；`POST /review/shot`：`{"source_id":"...","shot_id":"...","selections":[{"actor_id":"...","role_id":null}]}`。空 selections 排除该镜头全部人物证据。
  列表支持 `source_id`、`status`、`actor_id` + 可选 `role_id` 精确配对筛选，`no_candidate=true` 筛选无候选；`limit` / `offset` 分页，`compact=true` 为跨页全选返回去重身份及状态，不传特征或截图数据。`status=rejected` 时忽略身份及无候选筛选，`filters` 为空且 `items[].candidate` 为 null。其他状态响应中的 `filters` 是当前素材、状态下各配对的全量分镜计数，`items[].candidate` 是最高分候选（无候选为 null），`items[].confirmed_people` 是该分镜全部已接受身份，包含 `score`、`original_score` 和 `manual`（人工确认）字段；`scope_total` 是当前素材、状态下未按身份筛选的去重分镜总数。
- `DELETE /api/persons/tasks/{id}`：删除失败或中断的任务记录，保留镜头缓存与出镜证据。
- `POST /api/persons/publish`：`{}` 绑定活动内容索引；`GET /api/persons/releases` 返回当前生效组合（`content_id` / `release_id` / `person_id`）与最近 30 条检索组合；`POST /api/persons/releases/{id}/activate` 恢复组合，`DELETE /api/persons/releases/{id}` 删除非生效组合。`GET /api/persons` 不再携带发布记录；人物库页面用 `GET /api/persons?compact=true`，以 `coverage_counts`（素材 id → 覆盖分镜数）代替逐行 `coverage`，也不计算 `review_shots`。

上述缩写路径均继续以 `/api/persons` 为前缀。

CLI：

```sh
mindex persons list
mindex persons save actor.json
mindex persons reference ACTOR_ID photo1.png photo2.png
mindex persons process SOURCE_ID --start 0 --end 180
mindex persons status TASK_ID
mindex persons process SOURCE_ID --retry TASK_ID
mindex persons review review.json
mindex persons publish
mindex persons activate RELEASE_ID
```

CLI review 使用与分镜审核接口相同的 JSON（source_id、shot_id、selections）。CLI process 启动独立工作进程并立即返回持久化任务 ID；日志位于 `data/persons/task-logs/`。数据库按镜头存储检测、特征、配对缓存；失败任务不会自动重发，显式重试继续检查点。删除素材清除该素材人物轨迹、缓存、截图和历史发布中的相关证据，保留全局演员和用户参考图。

## 素材管理镜头详情

镜头操作顺序为“详情、备注、收藏、隐藏”。`GET /api/admin/segments/{id}/details` 返回独立 `asr`、`subtitles`、`llm`：ASR 使用已有转写/词级结果；字幕读取各原片字幕轨道并按镜头时间过滤；LLM 读取该镜头已保存的最新分析。没有结果分别显示“ASR 未处理”“无字幕轨道”“LLM 未处理”。位图、无本镜头对白、提取失败和等待对齐分别显示真实状态。读取详情不运行 ASR/LLM，不依赖在线模型或索引发布。文本字幕缓存于 `data/subtitles/{source_id}/`。

## 验收界限

自动化与测试素材只能验证工程行为，不能证明真实人物识别准确率。恢复工作时，现有素材库已包含 12 张参考图、已完成的原片 600–1200 秒人物任务及 1 条人工审核记录；详见验证记录中的现有任务核验。应继续人工核对正脸转背影、交叉、遮挡、换装与同演员多角色，确认参考图质量与召回效果后才扩展整片。

## 旧数据兼容

人物身份仅有演员、作品与角色，不再提供角色阶段、年龄、造型或服装设置。旧阶段身份首次加载时保留 ID、姓名和别名，转为普通角色并继承原角色的作品及演员关系；旧参考图保留图片与演员配对，旧审核结论保留。历史发布快照保持原文件内容不变，在读取时兼容为普通角色。更改配对只重新匹配已有特征，不重新提取原片或画面嵌入。

## 多选框搜索

所有涉及作品/演员/角色的多选列表框（检索页演员/角色、人物库筛选与编辑对话框、创作页召回设置）上方都有搜索框，实时过滤选项；条目默认按中文字典序排列，“全部选择”行不受过滤影响。


## 展示帧存储与旧库迁移

新处理的证据图默认保存为长边不超过 640 的 JPEG（质量 85）。模型仍接收原始视频帧，
图片压缩发生在提取特征之后，不影响检测、人脸向量或匹配结果。参考图和导入图保持原尺寸 PNG。

```bash
uv run mindex persons migrate-frames                 # 预览，无文件/证据写入
uv run mindex persons migrate-frames --apply         # 执行，可安全重跑
uv run mindex persons migrate-frames --source SOURCE_ID --apply
```

迁移无需人物服务、重新提取特征、重新索引或重新发布。已有向量、缓存 ID、coverage、
内容索引、人物发布快照和搜索发布组合均保留。`person.frames_max_edge`（0 表示不缩放）与
`person.frames_jpeg_quality` 不参与匹配缓存键；已有合规 JPEG 不因质量配置变化再次有损重编码。

镜头有任意 accepted 证据即视为已确认：每个 `(actor_id, role_id)` 保留一张 accepted 图，
优先真实匹配分；整镜人工确认使用 original_score，track 继承分仅兜底。未确认镜头保留
全部有图证据，含 rejected 留档。共用图片取保留集合的并集。

迁移先写新图，单源事务更新证据与 shot 特征缓存的图片路径，提交后删除冗余图片。
某源的保留图缺失/解码失败会报告 error，跳过该源的删除；其他源继续处理。
预览和执行均持管线独占锁及索引写锁，忙时退出。报告 deleted_bytes 是删除旧文件的字节数，
不扣除新 JPEG 的写入量；最终占用取决于待审帧数，不能保证固定体积。

历史快照保持不可变。证据图 API 依次尝试当前证据、历史快照、镜头缩略图；因此被清理的
旧图可能显示镜头缩略图。缓存复算写回证据时，缺失的旧图引用会改用镜头缩略图；尚存的旧引用也遵循同样回退。原图与缩略图均缺失时返回 404。
`mindex clean` 使用同一保留策略清理冗余帧；图片删除不可恢复为原分辨率，需保留原图时请先自行备份。

已有审核数据可用 `uv run python scripts/prune-person-review-frames.py --interval 15` 预览清理数量，再加 `--apply --vacuum` 执行并回收数据库空间。工具逐镜按实际 PTS 定位第 1、16、31…帧，删除其余帧上的已确认、已排除证据，保留抽取帧审核、候选及整镜审核标记，并使匹配缓存失效。执行结果写入 `data/reports/person-review-frame-pruning.json`。
