# 三份计划实现审查与端到端验收

日期：2026-10-17。范围：[人物库计划](../plans/PERSON_RECO_PLAN.md)、[独立渠道计划](../plans/RECALL_ENHANCEMENT_PLAN.md)、[创作页召回迁移计划](../plans/RECALL_MIGRATION_PLAN.md)。

## 本轮发现并修复

- 镜头详情缺少人物处理小节：补齐覆盖区间合并、与当前镜头求交、缺口、三态、证据计数与实时人物名；无需索引或模型，精细片段沿用其自身原片区间。
- 创作页召回固定内容索引后仍可能选到较新的人物发布：执行时显式绑定签名记录的人物发布，验证同一内容索引下回退人物发布后恢复对应证据与旧签名。
- 查询上传在异步端点持有线程锁，可能阻塞事件循环：上传暂存后，将校验及原子提交放入工作线程，在工作线程内获取修改锁。并发上传与状态读取回归通过。
- 查询媒体 ID 未限制为摘要，引用校验可能接受目录/临时文件：要求 64 位小写十六进制 ID，排除非文件与 `.partial`；执行前校验文件 SHA-256，损坏或缺失明确报错。
- 相同内容换后缀会生成重复文件，重复上传无法修复损坏缓存：跨后缀查找相同摘要，复验并在必要时原子恢复；限制落盘后缀为媒体类型。
- 人物/素材选项懒加载完成后已展开编辑器不更新：补齐刷新与跨任务请求保护；规范化旧内容默认设置的 dirty 判定，合并时将显式全默认与无 recall 视为等价；防止旧上传响应覆盖已切换的编辑状态。
- 没有检测证据的镜头直接人工确认时缺少证据图：使用现有镜头缩略图作为后备；已有无图证据不输出无效图片请求，检索页与创作页按实际图地址展示。
- 对白提及过滤错误地要求所有时期变体同时出现，且英文姓名可能命中另一姓名内部：变体组内任一命中，组间保留 all/any；英文采用与姓名解析相同的词边界。

## 自动化链路

`tests/test_recall_e2e.py` 使用真实 FFmpeg 字幕、SQLite、Chroma、PyAV 原片采样、ByteTrack、人物 HTTP 服务端点和后台任务；人物与嵌入推理使用标明 test-only 的颜色特征。

链路包括：准备素材 → 字幕优先对白任务 → 增量发布 → 上传人物参考图 → 人物任务及发布 → 出镜/提及检索 → 镜头详情 → 创作任务上传查询图 → 保存召回设置 → HTTP 提交召回节点 → 读取已保存候选。LLM 与 ASR 工厂被设置为禁止调用，字幕路径没有触发它们。核心反例通过：绿色镜头只在字幕提及演员，严格出镜仅返回红色镜头；提及模式返回绿色镜头。HTTP 证据图可读取，只有人物名的查询不调用嵌入。

额外回归覆盖发布回退、摘要破坏、跨后缀去重、并发上传、覆盖区间边界、人物变体提及与英文姓名边界。
