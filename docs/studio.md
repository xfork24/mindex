# Studio 分镜与版本工作台

入口 `/studio`。设计依据为 [STUDIO_UI_PLAN.md](../plans/STUDIO_UI_PLAN.md)。保留 Python、文件存储和原生前端；首次进入任务工作台时接入版本模型，原文件和执行历史保留。

## 工作区

任务标题可以独立保存，不改变方案、分镜或媒体版本。任务包含多个构建方案，可以新建、命名、复制和切换。方案分别保存分镜表、内容版本、阶段选择、人工素材范围及参数，共享任务内的产物历史。重新拆分使用新分镜身份，不影响其他方案。

创建任务（表单标题“创作视频”）只提交视频大纲与“可用素材”多选（默认全选），不再提供高级选项：音轨、字幕、召回数量使用服务默认值（默认软字幕轨道），创建后在“方案参数”里调整。可用素材是任务级的召回硬上限：逐镜“文本与查询”里的素材范围只能在其中二次选择，两层取交集。全选等价于不限（记录为 `null`，此后新增素材自动可用），全不选会被拒绝并提示至少选择一个素材。所选 id 记在 `job.json` 的 `source_ids`，创建后只读，不进方案参数对话框；旧任务没有该字段即不限。图片与视频召回同样受此限制。分镜素材范围与任务范围没有交集时直接报错，不退化成全库。

任务 ID 与构建方案之间有只读的“任务元信息”折叠区，只展示创建后不可变的输入：视频大纲（老任务显示创建时填写的创作文案；整行铺开，按原文分段换行，不截断）、创建时间、可用素材（`null` 显示为“不限（全部素材）”）。这些值取自 `job.json`，面板不提供任何写入路径；音轨、字幕、召回数量、音色等高级选项由方案参数独立展示并可动态调整，不在元信息中重复。

分镜矩阵的列依次为文本与查询、召回、配音、选片与对齐、分镜渲染。格内显示已选版本、摘要、最近执行结果和兼容性提示，详情展开后可浏览候选、试听、查看历史或选为构建输入。这两个历史操作互相独立；选择版本不会执行模型或渲染。矩阵支持横向滚动，固定分镜标识和表头，也可以整体折叠。下方依次为成片、产物与调试记录。

召回详情的“执行 / 复用”优先选择输入、检索设置及索引等匹配且文件完好的成功召回版本，没有时才重新检索；“强制重新生成”跳过复用，每次重新检索并新增版本。两者仅执行召回。“查看完整版本”集中展示完整的实际输入、参数、候选数据、依赖树及 candidates 文件下载；单元格详情不再重复下载入口和参数段落。

配音、选片与对齐、分镜渲染详情也统一通过“查看完整版本”下载文件及查看实际输入、参数和依赖树。配音和渲染详情保留内嵌播放器；选片详情保留窗口与音画试听，已保存选片版本的预览入口集中在完整版本中。

点击单元格会在该分镜下方展开整行详情，同格再次点击收起，同镜其他格切换详情；不同分镜可独立展开。文本、查询和预估时长水平编辑，保存只修改当前镜；移动、合并、插入和删除也在该镜详情内操作。未保存草稿按任务、方案和分镜保留，执行前需保存或取消。轮询保留未变化的详情和播放器。

文本与查询详情中的“召回设置”支持文字与人物、图片找视频、视频找相似，并可限定素材。文字模式可多选已登记人物，选择出镜或对白提及，以及同时出镜或任一人物。图片限 20MB，视频限 100MB、30 秒；上传后可预览，保存分镜后生效。每镜独立保存设置；合并保留上一镜设置，上一镜为默认文字时继承下一镜设置。人物候选显示身份、证据图及审核链接，覆盖不足时明确提示。文本与查询详情还提供“检索粒度”与“返回数量”下拉（选项与视频检索页一致）：默认“跟随方案”（粒度取服务配置、数量取方案参数的召回数量），选定后仅覆盖当前分镜的召回，格内摘要显示“召回覆盖”标记；四种召回模式均受其影响。

查询文件按 SHA-256 保存在任务的 `inputs/`，相同内容去重，纳入产物和任务 ZIP。执行前复验摘要，文件缺失或损坏会要求重新上传。更换召回方式、人物、素材或文件会使对应召回版本需要重建；改回旧设置可复用历史成功版本。召回同时绑定内容索引与人物发布记录，回退后使用对应组合。分镜工作台的分镜表上方用一行显示“检索组合”：当前生效的组合、当前工作台（各分镜已选召回版本）依赖的组合，以及两者是否一致；组合以检索发布版、内容索引、人物快照 ID 表示（正文取前 8 位，悬停显示完整值），依赖多个组合时逐个列出分镜数。“成片”面板的“历史成片与完整依赖”中，成片合成节点下增加“检索组合”一项，列出该成片沿 渲染 → 选片 → 召回 依赖链用到的组合，与当前生效不一致时标出。不一致的召回节点会提示“选用版本兼容性”，可重新执行召回，或在设置页“索引版本”恢复对应组合；数据来自工作区详情的 `retrieval` 字段（`active`、`used`、`compose`）。新增人物发布参数会使部署前的召回版本进行一次重建；全默认分镜设置保持旧查询 payload 不变。

“构建成片”位于“方案参数”右侧。方案栏下方的只读工作日志展示当前方案最近一次执行，并在运行时增量刷新；结束后保留日志。每个业务列头提供“全部重新生成”：文本与查询按当前方案的文案重新拆分整份分镜，其他列仅强制执行本列当前所有分镜。缺少输入的镜头标为阻塞，其他独立镜头继续；不会自动执行其他阶段或合成成片。

## 文案创作

创建任务时只填写视频大纲，例如“生成一个新加坡旅游介绍视频，300 字左右，按顺序讲星耀樟宜、植物园、牛车水中国美食、滨海湾公园的白天和夜景，最后总结一下。英文”。大纲存在 `job.json` 的 `outline`（仍受 `studio.max_input_chars` 限制，默认 2000 字）。创建后只异步生成标题，标题输入是大纲；此时不生成文案，也不拆分镜。

文案是方案级的版本化阶段 `script`，位于“分镜工作台”上方的“文案创作”区域：

- 默认显示“文案待创作”。点击“生成文案”调用“文案创作”模型（设置页新增的 `writer` 角色，配置与“文本拆分镜”相同，见 [设置页](settings.md)）。模型收到大纲，以及一段独立的“可用素材摘要”参考段（见下文）。提示词要求只保留旁白正文，不要标题、小标题、Markdown 或前后说明，并遵守大纲对语言、字数和顺序的要求；温度 0.7，重复点击会得到新的文案版本。
- 文案可在文本框里直接修改，点击“保存文案”生成新版本（`origin=manual`）。文本框有未保存修改时，“构建成片”和其他会改动方案的按钮不可用；重新生成会丢弃这些修改，并先确认。
- 每个版本记录来源：`generated`（模型生成）、`manual`（手动保存）、`legacy`（老任务迁移）。新建方案继承当前方案的文案，不带分镜；复制方案连同文案和分镜一起复制。

构建成片的顺序是：生成文案 → 拆分镜 → 召回 / 配音 → 选片对齐 → 分镜渲染 → 成片合成。文案是后面所有阶段的依赖：拆分镜版本的输入记录所用文案版本，依赖树沿着它一直追溯到文案。构建遇到已有文案时直接复用，不会悄悄重写；只有方案还没有文案时，才在最前面自动加入“生成文案”。文案生成失败时，后续全部阻塞。

文案变化后（手动保存或重新生成），已有分镜保留产物但被标记为过期：分镜工作台提示“文案已变化”，构建预检把拆分镜列为重建，确认构建后整份重新拆分。拆分镜之前的版本和其他方案不受影响。

老任务的 `input_text` 本来就是文案：首次读取时迁移为一个已完成的 `legacy` 文案版本，所有方案共用，现有分镜视为由它拆出，因此行为不变，也不会被判为过期。老任务没有大纲，不能重新生成文案，但可以手动编辑保存。

旧的分步接口（`/steps`、`/run`）只认创建时传入的文案；新任务没有 `input_text`，调用会返回 422，请改用版本工作台。

## 可用素材摘要

文案创作、拆分镜和“按画面意象重写召回词”参照同一份可用素材摘要（Material Digest，`studio/material_digest.py`）。摘要只取召回实际比对的画面分析文字 `views.analysis`，让文案写素材里真实存在的画面，召回词贴近素材用词。摘要按需计算，不落盘，不进任何签名；只读生效内容索引快照与覆盖层，不修改快照、任务或产物。

- 范围：只读生效内容索引（不读其他索引版本），只纳入同时满足以下条件的片段：在任务可用素材范围内（`source_ids` 为 `null` 时不限，空集合则没有片段）、生效隐藏状态为否、`annotation_status == "complete"`、`views.analysis` 非空。过滤后没有片段的素材不出现。对白 `views.dialogue` 不读取；“人物”“人物情绪”“氛围”“景别”“角度”“镜头运动”标签行不进故事线和词表，所以摘要里没有演员、角色或人物描述。
- 结构：素材按（显示名，source_id）排序，每个素材一块：`【名称】时长 N 秒`、`画面词：…`、`故事线：…`。画面词合并 shot/moment 的“场景/对象/动作”三类词，按频次降序、同频按字典序取前 30 个。故事线取 scene 描述正文，没有 scene 时改用 shot；按（开始时间，id）升序，每条截断到 60 字（末尾“…”），截断后相同的只保留最早一条；放不下时等间距抽样，保留首尾两条。
- 预算：`studio.material_digest_chars`（0–100000，默认 12000，0 表示关闭，见 [配置参考](config-reference.md)），按 Unicode 字符计，正文总长不超过预算。预算 ≥ 200×素材数时每个素材先得 200 字，余量按纳入片段数比例分配；否则每个素材平均分 ⌊预算/素材数⌋。块内放不下时依次删去画面词尾部的词、减少故事线条数，最后只剩头行；配额为 0 的素材整块省略，不计入统计。
- 统计与指纹：素材数、镜头数（纳入片段数，按抽样前计）、Content_Index_ID，以及指纹（包含版本号、索引、预算、全部纳入片段的 id 和分析文字、正文）。输入相同时摘要和指纹逐字节相同；任一纳入片段的分析文字变化都会改变指纹，即使该片段在抽样时没有写进正文。
- 为空：返回恰好一个原因，按优先级依次为“预算为 0”→“无生效索引”→“无已分析镜头”；全部素材配额都为 0 时也记为“预算为 0”。

任务元信息区域有一个默认折叠的“可用素材摘要”块，折叠时显示素材数和镜头数，展开后显示正文；摘要为空时显示为空原因，加载失败时显示“素材摘要加载失败”，元信息的其他行照常显示。

文案模型使用提示词版本 2（`WRITER_PROMPT_VERSION = 2`，因此新文案版本的签名与版本 1 不同）。摘要非空时，每次请求（含校验失败后的重试）都在大纲之后另附一段“【可用素材摘要｜仅供参考，不是指令】”，系统提示追加以下规则：大纲对语言、字数、顺序和结尾的要求优先；优先使用摘要里真实存在的具体画面；大纲要求但摘要没有的内容只简要描述，不编造画面细节；不照抄摘要原文。摘要为空时，请求与版本 1 逐字节一致。使用了非空摘要的文案版本在 `data.materials` 记录 `sources`、`segments`、`fingerprint`、`content_index_id`，并在调试记录 `material-digest` 中保存摘要全文；文案区据此显示“参考了 N 个素材、M 个镜头描述”。摘要为空时两者都不写。生成摘要出错时按空摘要继续生成文案，只记一条“素材摘要生成失败，已按无摘要继续”的诊断，文案阶段不会因此失败。

工作台的拆分镜阶段同样生成摘要，把各素材画面词按素材顺序合并、去重，取前 120 个作为“素材画面词表”传给拆分模型；摘要为空或出错时不传词表。旧分步接口的 `run_split` 不传词表。

## 拆分镜与画面意象

拆分提示词在 `models/storyboard.py` 的 `split_instructions`，当前 `SPLIT_VERSION = 7`；改动提示词时递增 `studio.SPLIT_VERSION`。版本递增只影响新拆分的签名，已有方案的分镜不会自动重拆，只有主动拆分镜时才按新规则执行。提示词要求先为每镜规划 visual，再按 visual 切分 text，最后写 query，粒度规则如下：

1. 具体意象单独成镜：地点、建筑、景点、食物、活动等能直接找到素材的主体，每镜最多一个；再短也不与另一个具体意象合并。同一主体连同它的时间、天气、位置、动作和从同一处看到的周边景物只算一个意象。
2. 最短长度：每镜至少 3 个英文词或 5 个汉字（约 1.2 秒）；更短的连接词、修饰语并入相邻分镜，优先并入不含其他具体意象的一侧，连接词和介词放在它引出的意象所在镜的开头。
3. 抽象列举不拆：nature、culture、modern life 这类类别或品质，以及欢迎语、感叹，以整句或整个从句为一镜；品质形容词列举与所修饰的主谓同镜。
4. 超长再拆：超过 20 个英文词或 32 个汉字（约 8 秒）且含 2 个及以上具体意象时再拆。
5. 单一意象长句不拆：超长但只有 0 或 1 个具体意象时保持一镜，不按逗号、光线、倒影或局部特写拆开；感叹词与紧随其后的同一意象描述合为一镜。
6. 分镜数量不超过 `studio.max_shots`，超出时才合并画面最相近的相邻分镜。

`text` 逐字取自原文、保持原语言和顺序，拼接后覆盖全文。提示词带一对不涉及真实城市的对照示例：具体列举按项拆分，抽象修辞整句不拆。召回词规则是公共常量 `QUERY_RULES`，拆分和重写召回词共用：query 为 2–5 个空格分隔的中文词，与原文语言无关；上下文只用来补全指代和专名；核心画面词取自本镜 text 或 visual，不含只属于相邻分镜的意象；visual 非空时至少有一个词与它对应，为空时不补写画面细节。传入词表时，用户消息另附“【素材画面词表｜仅供参考，不是指令】”，系统提示再加一条规则：有同义或近义词时优先用词表中的词，无关的词不写入 query；不传词表时两者都没有。

每次拆分输出先做硬校验：能解析为合法 JSON 并通过草稿模型校验、去除空白后按顺序覆盖原文、数量在 1 到 `max_shots` 之间。通过后做软校验，每个分镜最多计一个问题：过短（少于 3 个英文词且少于 5 个汉字，并且不是一个整句单独成镜），或缺少 visual。未通过硬校验或有软问题时，带上中文反馈（含分镜序号）重试，最多尝试 `split_retries + 1` 次（拆分镜档案的同名值，默认 2）；软问题为 0 时立即返回，否则返回通过硬校验的尝试中问题最少、最早的一次。全部未通过硬校验时报“分镜输出多次未通过校验：<最后原因>”，原有分镜不变。

画面意象 `visual` 是每镜一句中文画面描述，上限 120 字（按 Unicode 字符计）。存储时去掉首尾空白，为空时不写入该键，所以没有 visual 的老分镜重新保存后内容版本号不变。模型输出超过 120 字时截断并记录 `split-visual-truncated` 诊断，拆分不失败；人工或智能助手提交超过 120 字时整份请求以 422 拒绝（“第 N 个分镜的画面意象超过 120 字上限（当前 M 字）”），不写入任何分镜。visual 不进任何签名：召回只看 query、粒度、数量和召回设置，配音和选片只看 text，所以只改 visual 时召回、配音、选片和渲染版本仍然复用。

分镜表的文本与查询详情中，输入框依次为“旁白与字幕”“画面意象”“召回关键字”（即 query），画面意象改动后标为未保存；格内摘要在 visual 非空时完整显示，为空时不显示这一行。保存此镜时整份 PATCH 带上每镜当前的 visual，被拒时保留草稿和未保存标记并显示服务端错误。合并分镜时跳过空值，按顺序用“；”拼接，截断到 120 字，全为空时合并结果没有 visual。智能助手的 update、split 和 merge 规则相同（`visual=""` 表示清空，拆开时各段默认继承原镜 visual），`shot_rows` 输出 visual，为空时为 null。

按画面意象重写召回词：在文本与查询详情中修改画面意象后，点击“按画面意象重写召回词”。前端用草稿中当前的 visual 请求建议，请求期间禁用按钮；成功后只替换草稿里的 query 并标为未保存，点击“保存此镜”后才生效，在此之前已保存的 query 和召回产物不变。失败时在编辑器中显示错误，草稿和未保存标记不变。服务端用 `suggest_query` 调用一次拆分镜模型（不重试），参考前后镜的 text 和素材画面词表。

拆分粒度与带召回的检查可以用 `eval/split_eval.py` 复跑，用法见 [评测说明](../eval/README.md)。

## 版本与依赖

每次实际执行保存独立的不可变版本，包含阶段、分镜身份、成功或失败结果、输入版本、参数快照、文件路径及 SHA-256。成功后更新当前方案的对应选择；失败只新增记录，保留原有选择和全部下游产物。

兼容性按实际使用的内容和阶段参数检查：查询影响召回，旁白与声音影响配音，选片依赖其实际配音、召回版本及候选锚点。新人工窗口保存候选引用；仅旧式人工素材范围不依赖召回。分镜渲染绑定选片与音频版本、原片文件身份及处理参数。上游变化只展示具体冲突；构建时才决定复用和重建。

构建依赖为 `内容 → 召回 / 配音 → 选片 → 分镜渲染 → 成片合成`。分镜表另外记录身份、数量和顺序。每个新成片保存实际使用的完整依赖图及方案快照；依赖树可展开、查看节点详情，并可复制为新方案。

## 构建与人工控制

“构建成片”先显示复用、重建、阻塞和无需执行的清单，确认后执行。预检令牌绑定方案、输入版本与生效参数，提交时变化会要求重新预检。每格也支持单独执行或复用，强制重新生成是单独入口。

某节点失败后，其他独立镜头及分支继续执行，依赖失败节点的后续节点标为阻塞。必需依赖未齐时不合成新成片，已有成片始终可播放和下载。再次预检续建会复用输入指纹和文件哈希均匹配的成功版本。构建状态为 running/complete/partial/failed/cancelled，节点另有 reused/blocked/skipped 状态；界面遇到未知状态时显示原始值。

逐镜选片按“选择召回候选 → 拖动定长窗口 → 保存当前窗口”操作。召回和选片详情分别提供候选预览、设为参考锚点与恢复自动选择；自动模式沿用综合评分，不固定使用首个候选。锚点按方案和分镜保存，绑定召回版本与候选 ID。选择只修改构建输入，保留已有选片与视频；更换锚点会移除此前确认范围。切换召回版本后，人工锚点来自其他版本时显示具体冲突，需重新选择候选或恢复自动模式。

“恢复自动选择”保存自动模式，从人工模式切换时清除此前人工范围，不立即选择或保存某个候选。打开选片窗口或执行选片时，才结合语义、实际成功配音时长及素材延长情况评分；窗口显示解析出的实际参考候选。无成功配音时等待配音完成。恢复自动模式不会改变已有选片与视频的历史依赖。

局部上下文为同一原片的前两镜、整个候选锚点组和后两镜；不足配音有效时长的两倍时，按前后两侧原有时长比例增加相邻镜头，直到总时长至少达到两倍；一侧无法延伸时由另一侧补足。隐藏区间、素材边界和断点均停止延伸。定长窗口使用当前成功配音的实际时长；明确设置速度时除以该速度，未指定时为原速。仍不足时禁用窗口与确认，不自动变速或冻结。无配音也能选择候选，窗口等待配音完成。

时间轴显示连续视频缩略图、镜头边界与锚点标记。可以整体拖动、点击定位、左右方向键逐帧微调，Shift 移动十帧，Home / End 到合法边界；缩放后支持横向滚动。窗口可以完全离开锚点。拖动只在本地定位画面；直接使用视频窗口内的播放键播放当前选区，到窗口结束自动暂停，从结尾再次播放会回到窗口起点。“保存当前窗口”无需先点预览，内部自动获取当前范围的校验令牌后保存；缺少配音、素材不足或正在执行时禁用，并显示具体状态。“试听配音与画面”是可选操作，生成当前范围与配音混合的音画预览，本身不保存选片。保存后创建新选片版本，保存真实候选、上下文、最终范围、实际范围和音频依赖。配音、速度、素材可见性或方案 revision 变化会使旧预览失效。草稿按任务、方案、分镜、候选、配音版本和速度隔离，切换详情保留有效位置。

选片详情的“按当前输入选片 / 复用”使用当前锚点或已保存范围，优先复用成功版本；“重新生成选片版本”跳过复用并新增版本。两者都不保存尚未提交的窗口草稿，也不自动渲染分镜或合成成片。

旧区间 API 与历史产物继续保留。缺少候选引用的旧人工版本展示原范围，重新调整前要求明确选择候选，不从范围内第一镜推断历史锚点。

方案参数包括当前配音服务的声音 ID、召回数量、原声混音及增益、字幕模式、配音速度和补齐策略；任务级素材范围不属于方案参数，创建后不可更改。自动选片的速度留空时自动选择；冻结策略保持原速配音；严格策略要求范围与配音时长匹配。人工定长窗口始终使用指定速度或原速。没有新增跨素材拼接、情感控制、版本删除或自动清理。

音色默认采用 `voice_mode=inherit, voice=null`，每次提交执行时读取当前配音服务的默认音色；切换模型或默认音色无需逐任务修改。只有明确选择“为本方案指定音色”时，才使用 `voice_mode=custom` 和指定的 `voice`。批次提交后使用当次配置快照，各配音产物保存实际音色和模型；历史文件与参数不随全局设置修改。新建方案默认跟随默认音色，复制方案保留明确的覆盖选择。

旧方案没有记录默认音色与人工覆盖的区别，现按跟随默认处理；旧值保留为 `legacy_voice` 参考，不再参与执行。读取时仅在内存中规范化，下一次受执行锁保护的写操作才保存；历史产物与成片快照不修改。若需要固定某个旧音色，可重新明确指定。

仍使用全局 `studio.lock` 串行执行。方案编辑、选择、删除任务、ZIP 导出与执行互斥，冲突返回 409。服务重启后的未完成构建保留历史并标为中断，可重新预检续建。

## 取消执行与删除方案

构建执行中，“构建成片”旁显示“取消执行”。点击后请求取消（`POST /jobs/{id}/builds/{build}/cancel`），工作日志记一条“已请求取消，当前节点完成后停止”，按钮显示为正在取消。执行器在下一个节点开始前检查取消标记（进程内事件与哨兵文件 `builds/<build_id>.cancel`，跨进程可见）：已开始的节点照常完成，其余 pending 节点标为阻塞、原因“已取消”，构建状态记为 `cancelled`，已生成的版本全部保留，之后可重新预检续建。服务重启恢复只处理 running 的构建，不改变已取消的构建。只有 running 构建可以取消，其他状态返回 409。

旧任务的步骤执行（`/steps`、`/run`）运行时，页面显示执行中提示和“取消执行”按钮（`POST /jobs/{id}/cancel`）：worker 在步骤之间检查任务目录下的 `steps.cancel` 哨兵，当前步骤完成后停止，执行状态记为 `cancelled`，未开始的步骤保持原状态。

方案栏的“删除方案”需要二次确认，只剩一个方案时不可用。`DELETE /jobs/{id}/plans/{plan}` 在创作修改锁内只删除方案记录：版本、构建记录和文件都保留，不再被引用的产物由 `mindex clean` 按策略回收。删除的是当前方案时，切换到其余方案中创建时间最新的一个。有构建正在执行时返回 409，删除唯一的方案返回 422（“至少保留一个方案”），两种情况都不做修改。

## 诊断与智能助手

`GET /jobs/{id}/plans/{plan}/diagnostics` 汇总一个方案的状态，只读、不加锁，构建执行期间也可调用：分镜的硬性检查、软性问题与文案覆盖；方案烧录字幕时的字幕滤镜与字体检查；各已选节点是否缺失、失败、文件损坏或过期，以及与 `conflicts` 一致的变化原因（例如“旁白已变化”）；构建预检摘要；各阶段当前的输入（`inputs_by_stage`）。智能助手的 `diagnose_plan` 用它解释“为什么这个分镜要重建”，`run_column` 用 `inputs_by_stage` 组装整列执行的输入。

智能助手在创作页可完成的操作见 [智能助手](agent.md#能力范围与缺口)：`studio` 领域覆盖任务、方案、文案、分镜（含逐镜召回设置、图片或视频召回）、构建、取消与删除方案；`studio_detail` 领域覆盖诊断、版本依赖、召回词建议、素材摘要、版本预览、整列执行和人工选片。人工选片工具与页面走同一组接口：`get_selection_candidates` 读取 selection-context，`preview_selection` 用候选加起点（定长窗口，必要时先设人工锚点）或素材加起止时间（任意区间）调用 range-preview，`confirm_selection` 提交与预览一致的请求体和 preview_token 调用 range-confirm。方案 revision 或对齐结果在预览后变化时提交会被拒绝，需要重新预览；没有成功配音或有构建正在执行时，选片工具直接返回原因。

## 文件与迁移

```text
data/studio/<job_id>/
  job.json                  # 任务标题、原文及旧流程状态
  workspace.json            # schema=2：方案指针、版本索引、构建执行与节点结果
  builds/<build_id>/events.jsonl # 可增量读取的人类可读执行日志
  versions/<version_id>/
    version.json            # 不可变版本记录
    debug/*.json            # 请求、响应、ffmpeg 命令及错误诊断
    ...                     # 此版本的候选、音频、视频或成片
  migration-v2/             # 迁移前 job/storyboard/timeline/audio/checkpoints 快照
  attempts/...              # 原执行产物与历史，原样保留
  previews/...              # 由明确版本/参数生成的预览缓存
  exports/*.zip             # 导出包不递归包含导出包
```

迁移校验旧 manifest 的文件哈希，导入可验证的召回、配音、分镜视频及历史成片。无法证明输入关系和参数的旧版本标为“记录不完整”，不会按当前分镜猜测旧依赖，也不会自动视为可复用版本。旧成片仍可下载；依赖关系不完整时不能恢复为可验证方案。所有新版本均保存明确依赖。迁移是按任务进行的，打开前不会批量修改现有任务。

认证头、密钥和 URL 中的凭据经过诊断脱敏。原片不复制进任务目录；版本记录素材身份及文件指纹。产物下载 URL 指向确定版本文件，不依靠可变别名或缓存查询参数代表版本。

## 媒体与字幕

分镜渲染独立保存确定帧数的视频和处理后的 48kHz PCM 音频。帧数依据实际处理后采样数计算，保证在任意成片位置都能容纳完整配音。合成混选版本时，根据累计帧边界统一计算各镜的采样补齐和字幕时间，避免逐镜浮点累计或独立取整造成漂移。

定长窗口的字幕结束时间和分镜时长使用同一精确值，保留音频采样和变速带来的非整数毫秒时长；毫秒取整仅用于界面显示及字幕文件输出，不用于放宽事件的边界校验。

视频先裁到实际原片范围，再冻结末帧。音频支持变速、响度归一化及原声压低混音。成片发布前检查音视频轨道、字幕模式、时长和完整解码；失败保留已有成片。软字幕同时保存 MP4 mov_text、SRT 和 WebVTT；烧录字幕需要部署环境的 ffmpeg subtitles/libass 和可用中文字体。

技术对齐不保证叙事、人物或查询质量，仍需人工审阅。确定性测试音频也不代表真实发音质量。

逐镜文本编辑器的召回设置支持素材范围多选、场景、人物情绪、景别和最短／最长时长；这些素材筛选也适用于图片及视频召回。素材列表带搜索过滤和右下角高度拖拽；不选素材时搜索全部库。任务限定了可用素材时，这里只列出范围内的素材。旧的单素材设置继续读取，保存新的多选时写入 `filters.source_ids`。素材顺序和重复项不影响召回版本复用，单项多选与旧单素材配置保持相同签名；全选时不写入筛选，签名保持默认，历史召回版本继续复用。

分镜工作台默认折叠所有行，左上角按钮可切换展开/折叠所有行。阶段列同时提供全部执行/复用和全部重新生成。文本与查询中的素材范围默认全选任务允许素材；演员和角色仅显示所选素材关联影片中的组合，切换素材时清除不再适用的人物。自动选片使用与定长窗口一致的默认范围，尾部不足时向前移动起点，保证可用范围内完整容纳配音。

创作任务默认使用软字幕轨道。任务元信息中的文案隐藏空白行，可用素材独占整行并逐项列出。拆分镜粒度规则、画面意象与召回词规则见上文“拆分镜与画面意象”；各分镜 `text` 仍须逐字取自原文并按顺序拼接后覆盖全文，分镜文案保留原文语言。召回候选图右上角标记当前自动选择或人工已选择的锚点。
