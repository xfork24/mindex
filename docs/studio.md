# Studio 分镜与版本工作台

网页创建任务时会保存当前界面语言：中文任务的初始构建方案名为“默认方案”，英文任务为“Default Plan”；自动分镜的画面意象与召回关键词也使用任务创建语言，旁白原文保持原语言。之后切换界面不会重命名方案或翻译已保存的分镜。旧任务默认中文，可重新拆分镜生成新版结果。任务信息中的“可用素材摘要”独立跟随当前界面语言，选择双语分析中对应语言的故事线与画面词；旧的单语言分析保留原文。素材的自定义名称也保留原文。

入口 `/studio`。设计依据为 [STUDIO_UI_PLAN.md](../plans/STUDIO_UI_PLAN.md)。保留 Python、文件存储和原生前端；首次进入任务工作台时接入版本模型，原文件和执行历史保留。

创作页有三个分区标签：「创作任务」（`/studio`）、「选题挖掘」（`/studio/topics`，见[选题挖掘](topics.md)）与「文案模板」（`/studio/templates`）。从选题建出的任务在任务详情顶部显示来源选题与账号档案；档案更新后可以「同步」，同步后文案区提示可重新生成文案（`script_profile_changed`），不会自动重写。

## 工作区

任务标题可以独立保存，不改变方案、分镜或媒体版本。任务包含多个构建方案，可以新建、命名、复制和切换。方案分别保存分镜表、内容版本、阶段选择、人工素材范围及参数，共享任务内的产物历史。重新拆分使用新分镜身份，不影响其他方案。

创建任务（表单标题“创作视频”）只提交视频大纲与“可用素材”多选（默认全选），不再提供高级选项：音轨、字幕、召回数量使用服务默认值（默认软字幕轨道），创建后在“方案参数”里调整。可用素材是任务级的召回硬上限：逐镜“文本与查询”里的素材范围只能在其中二次选择，两层取交集。全选等价于不限（记录为 `null`，此后新增素材自动可用），全不选会被拒绝并提示至少选择一个素材。所选 id 记在 `job.json` 的 `source_ids`，创建后只读，不进方案参数对话框；旧任务没有该字段即不限。图片与视频召回同样受此限制。分镜素材范围与任务范围没有交集时直接报错，不退化成全库。

任务 ID 与构建方案之间有只读的“任务元信息”折叠区，只展示创建后不可变的输入：视频大纲（老任务显示创建时填写的创作文案；整行铺开，按原文分段换行，不截断）、创建时间、可用素材（`null` 显示为“不限（全部素材）”）。这些值取自 `job.json`，面板不提供任何写入路径；音轨、字幕、召回数量、音色等高级选项由方案参数独立展示并可动态调整，不在元信息中重复。

分镜工作台由三部分组成：顶部的“批量操作”栏、横向滚动的分镜条，以及分镜条下方整块的阶段详情区。分镜条按方案顺序排列分镜卡片，宽屏一屏约 5 张（卡片宽度下限 220px），支持触控板横向滚动、鼠标滚轮（纵向滚动转为横向，到尽头交还页面）和两端的上一组/下一组按钮（窄于 700px 时隐藏）。每个分镜可打开的阶段为：文本与查询、画面阶段、以及该分镜包含的配音 / 选片与对齐 / 分镜渲染；画面阶段统一显示每个分镜的画面：素材召回为召回结果，AI 生成图片、AI 生成视频、AI 动画分别为生成图片（draw）、生成画面（generate）、生成动画（animate），上传片段/静态图片分镜为上传素材预览（在文本与查询里更换）。[背景音乐](#背景音乐)并入配音阶段，不单独列出；画面来源没有的阶段（如静态图片的选片）不出现。卡片上每个阶段有一个状态点：未执行、已完成、已过期（已选版本与当前输入签名冲突）、失败、执行中。卡片显示的阶段：存在已过期阶段时为第一个已过期阶段（标“已过期”），否则为最后一个已有产物的阶段，都没有时为文本与查询；卡片内显示该阶段的已选版本、摘要、最近执行结果和兼容性提示，并直接嵌入产物：配音为音频，分镜渲染为带配音与该镜字幕的预览视频，不单独显示音频（字幕取时间线事件 `event.subtitle`，以叠加层显示，底边对齐可视画面底边：取帧检测 pad 黑边，字幕放在黑边之上；全屏时改用原生字幕轨），生成画面为视频，生成图片为图片，召回为最多 3 张候选缩略图，上传素材为素材预览，选片为原片区间（素材库来源先显示缩略图，点击后经 `source-playlist` 加载镜头播放列表；上传片段/生成画面直接播放文件区间）；生成动画只显示摘要。卡片中除分镜渲染外的视频静音，所有播放器不自动播放、只预加载元数据，卡片进入可视区域才创建媒体、离开时暂停，轮询刷新不打断播放。详情中可浏览候选、试听、查看历史或选为构建输入，这两个历史操作互相独立；选择版本不会执行模型或渲染。下方依次为成片、产物与调试记录。

召回详情的“执行 / 复用”优先选择输入、检索设置及索引等匹配且文件完好的成功召回版本，没有时才重新检索；“强制重新生成”跳过复用，每次重新检索并新增版本。两者仅执行召回。“查看完整版本”集中展示完整的实际输入、参数、候选数据、依赖树及 candidates 文件下载；阶段详情不再重复下载入口和参数段落。

配音、选片与对齐、分镜渲染详情也统一通过“查看完整版本”下载文件及查看实际输入、参数和依赖树。配音和渲染详情保留内嵌播放器；选片详情保留窗口与音画试听，已保存选片版本的预览入口集中在完整版本中。

鼠标悬停卡片（媒体区之外）约 120ms 后，卡片正下方竖排展开该分镜的全部阶段（带状态点与状态文字，当前打开的阶段高亮），鼠标在卡片或列表内时保持展开，离开约 200ms 后收起；列表渲染在分镜条之外，不被滚动区域裁剪，分镜条滚动时跟随卡片，卡片滚出可视区域时收起。点击列表中的阶段在下方打开该阶段；点击卡片空白处直接打开卡片显示的阶段。触屏没有悬停：卡片右上角的“阶段 ▾”按钮展开列表。键盘：Tab 聚焦卡片即展开列表，Enter 打开卡片显示的阶段，下方向键进入列表、上下键切换、Enter 打开、Esc 收起。下方详情区一次显示一个分镜的一个阶段，标题为“分镜 N · 阶段 · ID”，“关闭”后回到提示；打开的分镜卡片有选中样式。打开的分镜与阶段按任务和方案分别记住。文本、查询和预估时长水平编辑，保存只修改当前镜；移动、合并、插入和删除也在该镜详情内操作，新增的分镜自动打开其文本与查询。未保存草稿按任务、方案和分镜保留（卡片同样标“未保存修改”），执行前需保存或取消。轮询保留未变化的详情和播放器。

文本与查询详情中的“召回设置”支持文字与人物、图片找视频、视频找相似，并可限定素材。文字模式可多选已登记人物，选择出镜或对白提及，以及同时出镜或任一人物。图片限 20MB，视频限 100MB、30 秒；上传后可预览，保存分镜后生效。每镜独立保存设置；合并保留上一镜设置，上一镜为默认文字时继承下一镜设置。人物候选显示身份、证据图及审核链接，覆盖不足时明确提示。文本与查询详情还提供“检索粒度”与“返回数量”下拉（选项与视频检索页一致）：默认“跟随方案”（粒度取服务配置、数量取方案参数的召回数量），选定后仅覆盖当前分镜的召回，格内摘要显示“召回覆盖”标记；四种召回模式均受其影响。

查询文件按 SHA-256 保存在任务的 `inputs/`，相同内容去重，纳入产物和任务 ZIP。执行前复验摘要，文件缺失或损坏会要求重新上传。更换召回方式、人物、素材或文件会使对应召回版本需要重建；改回旧设置可复用历史成功版本。召回同时绑定内容索引与人物发布记录，回退后使用对应组合。分镜工作台的分镜条上方用一行显示“检索组合”：当前生效的组合、当前工作台（各分镜已选召回版本）依赖的组合，以及两者是否一致；组合以检索发布版、内容索引、人物快照 ID 表示（正文取前 8 位，悬停显示完整值），依赖多个组合时逐个列出分镜数。“成片”面板的“历史成片与完整依赖”中，成片合成节点下增加“检索组合”一项，列出该成片沿 渲染 → 选片 → 召回 依赖链用到的组合，与当前生效不一致时标出。不一致的召回节点会提示“选用版本兼容性”，可重新执行召回，或在设置页“索引版本”恢复对应组合；数据来自工作区详情的 `retrieval` 字段（`active`、`used`、`compose`）。新增人物发布参数会使部署前的召回版本进行一次重建；全默认分镜设置保持旧查询 payload 不变。

“构建成片”位于“方案参数”右侧。方案栏下方的只读工作日志展示当前方案最近一次执行，并在运行时增量刷新；结束后保留日志。分镜条上方的“批量操作”选择阶段（文本与查询（拆分镜）、召回（画面）、配音、选片与对齐、分镜渲染）后提供“全部执行/复用”与“全部重新生成”：文本与查询按当前方案的文案重新拆分整份分镜，其他阶段仅对当前所有分镜执行该阶段。缺少输入的镜头标为阻塞，其他独立镜头继续；不会自动执行其他阶段或合成成片。

## 文案创作

创建任务时只填写视频大纲，例如“生成一个新加坡旅游介绍视频，300 字左右，按顺序讲星耀樟宜、植物园、牛车水中国美食、滨海湾公园的白天和夜景，最后总结一下。英文”。大纲存在 `job.json` 的 `outline`（仍受 `studio.max_input_chars` 限制，默认 2000 字）。创建后只异步生成标题，标题输入是大纲；此时不生成文案，也不拆分镜。

文案是方案级的版本化阶段 `script`，位于“分镜工作台”上方的“文案创作”区域：

- 默认显示“文案待创作”。点击“生成文案”调用“文案创作”模型（设置页新增的 `writer` 角色，配置与“文本拆分镜”相同，见 [设置页](settings.md)）。模型收到大纲，以及一段独立的“可用素材摘要”参考段（见下文）。系统提示来自方案选择的[文案模板](#文案模板)（缺省“通用解说”）：只保留旁白正文，不要标题、小标题、Markdown 或前后说明，并遵守大纲对语言、字数和顺序的要求；温度 0.7，重复点击会得到新的文案版本。
- 文案可在文本框里直接修改，点击“保存文案”生成新版本（`origin=manual`）。文本框有未保存修改时，“构建成片”和其他会改动方案的按钮不可用；重新生成会丢弃这些修改，并先确认。
- 每个版本记录来源：`generated`（模型生成）、`manual`（手动保存）、`legacy`（老任务迁移）。新建方案继承当前方案的文案，不带分镜；复制方案连同文案和分镜一起复制。

构建成片的顺序是：生成文案 → 拆分镜 → 召回 / 配音 → 选片对齐 → 分镜渲染 → 成片合成。文案是后面所有阶段的依赖：拆分镜版本的输入记录所用文案版本，依赖树沿着它一直追溯到文案。构建遇到已有文案时直接复用，不会悄悄重写；只有方案还没有文案时，才在最前面自动加入“生成文案”。文案生成失败时，后续全部阻塞。

文案变化后（手动保存或重新生成），已有分镜保留产物但被标记为过期：分镜工作台提示“文案已变化”，构建预检把拆分镜列为重建，确认构建后整份重新拆分。拆分镜之前的版本和其他方案不受影响。

老任务的 `input_text` 本来就是文案：首次读取时迁移为一个已完成的 `legacy` 文案版本，所有方案共用，现有分镜视为由它拆出，因此行为不变，也不会被判为过期。老任务没有大纲，不能重新生成文案，但可以手动编辑保存。

旧的分步接口（`/steps`、`/run`）只认创建时传入的文案；新任务没有 `input_text`，调用会返回 422，请改用版本工作台。

## 文案模板

文案区的“文案模板”下拉为当前方案选择模板（方案参数 `options.template_id`，新方案缺省 `base`；没有该键的旧方案同样按 `base` 处理）。内置六个模板，定义在 `backend/src/studio/templates/*.yaml`，随程序打包、只读：

| ID | 名称 | 类型 | 要点 |
|---|---|---|---|
| `base` | 通用解说 | outline | 按大纲组织：开头抓住注意，中段逐点展开，结尾总结；短句、适合配音节奏 |
| `history` | 历史解说 | outline | 时间线与因果推进，人物和事件交代清楚，有史实边界，避免演义化 |
| `hot` | 热点评论 | outline | 先说事件和争议点，再给观点与论据，最后做判断，事实与观点分开 |
| `film` | 影视解说 | outline | 剧情压缩，关键转折处设悬念，讲清人物动机，控制剧透程度 |
| `science` | 知识科普 | outline | 从问题引入，再讲概念、例证和类比，结尾给结论 |
| `interview` | 访谈改写 | rewrite | 从参考文稿提炼观点，改成第三人称叙述，保留关键原话 |

模板字段：`id`、`name`、`category`、`kind`（`outline` 按大纲写 / `rewrite` 改写参考文稿）、`version`、`description`、`instructions`（系统提示）、`constraints.max_chars`（`null` 时用 `studio.max_input_chars`，否则取二者较小值）。模型严格校验（`shared/types.py` 的 `ScriptTemplate`），未知字段直接报错。`rewrite` 模板允许大纲为空，但至少需要一份[参考文稿](#参考文稿)；没有参考文稿时预检把文案节点列为阻塞，原因“访谈改写模板需要参考文稿”。

模板在独立的模板管理页 `/studio/templates` 管理（创作页顶部“创作任务 / 文案模板”分区标签，或文案区的“管理模板”链接进入；链接带上当前模板与来源任务 `?id=…&job=…`，“创作任务”标签回到该任务）。左侧列出全部模板并可按名称、分类或提示词搜索；右侧显示完整提示词。内置模板只读，可以查看与试写，“复制为自定义模板”后才能修改；复制出的用户模板（ID 以 `user-` 开头，存 metadata 库的 `script_templates` 表，迁移步骤 v2）可以修改名称、分类、类型、字数上限、说明和提示词，也可以删除。被任一任务的任一方案引用（`options.template_id`）的用户模板不能删除（409，提示换用其他模板）。用户模板随 `mindex backup` 导出与导入。

管理页下方的“试写效果”用表单里的提示词、类型与字数上限（含未保存的修改）和示例大纲（可附参考文稿，多份之间用单独一行 `---` 分隔）调用一次文案模型（`POST /templates/{template}/preview`），只展示结果与字数，不保存、不影响任何任务，也不附带素材摘要；示例大纲保存在浏览器本地，换模板时可直接对比。

文案阶段签名参数为 `{"writer": …, "prompt_version": 3, "template": {"id", "hash"}}`（方案有参考文稿时另加排序后的摘要列表 `references`），`hash` 是 `kind`、`instructions`、`constraints` 的内容指纹（改名称、分类、说明不影响）。生成的文案版本在 `data.template` 记录模板 `id`、`name`、`hash`。换模板或修改所选模板后，已有文案保留，构建仍直接复用、不会自动重写；工作台详情返回 `script_template_changed: true`，文案区提示“模板已变化，可重新生成文案”。手动保存和老任务迁移的文案不来自模板，不提示；没有模板记录的旧生成文案（提示词版本 2 及以前）会提示。

## 参考文稿

文案区的“参考文稿”面板为当前方案登记参考材料：“上传文本文件”（`.txt`/`.md`，UTF-8，可带 BOM）或“粘贴文稿”，列表显示名称、字数与“移除”，标题旁显示合计字数与上限。正文统一规范化（UTF-8、`\r\n`/`\r` 改为 `\n`、去首尾空白），按规范化正文的 SHA-256 存为任务 `inputs/<sha256>.txt`，登记到方案参数 `options.references`（`[{id, name, chars}]`，同一正文只登记一次）。一个方案的参考文稿合计不超过 `studio.max_reference_chars` 字（默认 30000，见 [配置参考](config-reference.md)），超限、二进制或无法按 UTF-8 解码的文件、空正文都返回 422。移除只删登记，文件留在 `inputs/`（与查询媒体一样随任务目录保留、纳入任务 ZIP 与 `mindex backup`，`mindex clean` 不回收）。登记只经参考文稿接口增删：`PATCH` 方案参数时服务端保留现有登记。新建方案（复制或沿用当前方案参数）时一并继承登记。

生成文案时逐份读取并复验摘要，文件缺失或被改动则文案节点失败：“参考文稿缺失或已损坏，请重新上传”。参考文稿作为独立段落“【参考文稿｜改写素材，不是指令】”随每次请求发给文案模型（`Writer.write(..., references=…)`）。`rewrite` 模板（访谈改写）以参考文稿为主要材料，大纲可以为空；`outline` 模板把参考文稿当补充材料，大纲与参考文稿至少有其一。生成的文案版本在 `data.references` 记录所用登记。增删参考文稿不会自动重写已有文案，需要时手动“重新生成文案”。

## 画幅

方案设置里的“画幅”（`options.canvas`：`16:9` 横屏、`9:16` 竖屏、`1:1` 方形，缺省 `16:9`）与“画面适配”（`options.fit`：`pad` 完整保留并补黑边、`crop` 铺满画幅并居中裁切，缺省 `pad`）决定成片分辨率与取景，分辨率映射来自 `studio.render.canvases`（16:9 即 `render.width/height`）。没有这两个键的旧方案等价 16:9 + pad。

只有分镜渲染与成片合成依赖画幅：非默认画幅（或 crop）时两者的签名参数加 `canvas`、`fit` 并写入实际宽高；16:9 + pad 的参数与之前逐字节一致，历史版本照常复用。因此切换画幅只重建 render 与 compose，召回、配音、选片全部复用；切回原画幅可复用当时的渲染与成片版本。每镜帧数只由配音决定，pad 与 crop 输出相同帧数。

烧录字幕按画幅缩放：libass 字号以画面高度为基准，非 16:9 画幅把 `subtitle.font_size` 乘以“短边 / 高”，使字幕相对短边的像素大小与 16:9 一致（全屏观看时物理大小相同；1:1 系数为 1）；竖屏另把字幕下边距 `MarginV` 提高到 36（约画面高度的 1/8），避开短视频平台底部按钮区。16:9 的字幕样式不变。合成完成后校验成片分辨率与画幅一致。分镜快速预览仍按 16:9 缩略尺寸生成。

## 分镜画面来源

每个分镜的画面来源记录在分镜内容的 `source`（`Shot.source`，按 `kind` 判别）：

| kind | 设置 | 逐镜阶段 | 说明 |
|---|---|---|---|
| `recall`（缺省） | — | 召回 → 配音 → 选片对齐 → 分镜渲染 | 素材库召回与选片，即原有流程；需要活动索引 |
| `clip` | `media_id`，可选 `start`（秒，≥0） | 配音 → 选片对齐 → 分镜渲染 | 上传的视频片段：从起点（缺省 0）起取与配音等长的窗口 |
| `image` | `media_id`，`motion`（`zoom-in`/`zoom-out`/`pan-left`/`pan-right`/`none`，缺省 zoom-in），`strength`（0–1，缺省 0.3） | 配音 → 分镜渲染 | 静态图片按运动方式生成与配音等长的画面 |
| `aigc_image` | 可选 `prompt`（≤1500 字）、`reference_id`（主体参考图 sha256，图生图）、`seed`、`prompt_optimizer`；`motion`、`strength` 同 image | 配音 → 生成图片 → 分镜渲染 | AI 生成图片：图片生成服务按提示词生成一张图片，再按静态图片推拉/平移；见 [AI 生成图片](#ai-生成图片) |
| `aigc` | 可选 `prompt`（≤1000 字）、`negative`（≤500 字）、`image_id`（首帧图 sha256）、`seed`（0–2147483647）；MiniMax H3 另有 `mode`、`last_image_id`、`references`、`model`、`resolution`、`ratio`、`duration` | 配音 → 生成画面 → 选片对齐 → 分镜渲染 | AI 生成视频：视频生成服务按提示词生成片段，再从片段开头取与配音等长的窗口；见 [AI 生成视频](#ai-生成视频) |
| `animation` | 可选 `brief`（画面说明，≤2000 字） | 配音 → 生成动画 → 分镜渲染 | 动画生成 LLM 写自包含 HTML/JS 动画，渲染时在离线沙箱里逐帧录制；源码可人工修改；见 [AI 动画](#ai-动画) |
| `tool` | `tool_id`（工具源）、`tool`（白名单工具名）、`arguments`（JSON，≤8000 字符）、可选 `uploads`（≤4 个任务素材）、`output`（video/image）；图片产物另有 `motion`、`strength` | 视频：配音 → 调用第三方工具 → 选片对齐 → 分镜渲染；图片：配音 → 调用第三方工具 → 分镜渲染 | 调用登记的 HTTP 或 MCP 工具生成画面；见 [第三方工具](#第三方工具) |

`source` 为空即素材召回，dump 时省略该键；显式提交 `{"kind": "recall"}` 也规范化为空。因此没有设置来源的分镜内容版本号与签名都不变（`tests/test_studio_signature_snapshot.py`）。来源表在阶段注册表的 `SHOT_SOURCES`，预检、依赖与执行按每个分镜的序列展开：clip 与 image 没有召回节点，不需要发布索引，纯 clip/image 任务在没有活动索引时也能完整构建；混合来源的分镜在成片合成里按分镜顺序拼接。改变来源时，新来源没有的阶段选用（例如改为图片后的召回与选片）以及人工区间、参考锚点从方案中移除；候选、锚点与人工选片接口对非召回分镜返回 422“该分镜的画面来源不是素材召回，不能选择候选或人工选片”。

来源文件复用查询文件通道上传（`POST …/query-media`，`purpose=source`），按内容 SHA-256 存为任务 `inputs/<sha256>.<suffix>`：视频受 `studio.max_clip_seconds`（默认 300 秒）与 `studio.max_clip_mb`（默认 500 MB）限制，图片与查询图片相同。保存分镜时校验文件已上传且类型匹配（clip 须为视频、image 须为图片），预检在文件缺失时把节点阻塞为“画面文件缺失或已损坏，请重新上传”，执行前按文件名中的摘要复验，文件被改动时节点失败并给出同样的原因。来源文件与查询媒体、参考文稿一样随任务目录保留、纳入任务 ZIP 与 `mindex backup`，`mindex clean` 不回收 `inputs/`。

- clip 选片：窗口为 `[start, start + 配音时长 / 变速]`（变速取方案 `atempo`，自动时不变速），片段从起点起不够长时冻结末帧补足（`alignment=padded`，并给出警告；`strict` 对齐时拒绝），起点超出片段时长时报错。选片签名只含旁白、配音版本、片段摘要与起点（`clip_version`），因此改起点只重建选片、渲染与成片，配音复用。ducking 音轨使用片段自身的原声。
- image 渲染：图片先经 `shared/images.image_png` 归一化（EXIF 方向、透明铺白），按画幅 pad/crop 适配到 2 倍超采样画布，再由 ffmpeg zoompan 逐帧取景，输出恰好等于配音帧数、尺寸等于方案画幅的画面（`studio_render.still_shot`）。zoom-in 从 1 倍推到 `1 + strength/2` 倍，zoom-out 反向，pan-left/pan-right 在最大倍数下把取景框从右到左/从左到右移过画面，none 为静止；同一输入输出确定。图片没有原声，ducking 方案也只有配音。渲染签名含图片摘要、`motion`、`strength`、变速与画幅参数（`image_version`），改运动方式或强度只重建该镜渲染与成片。

时间线视频因此有两种形态（`TimelineVideo` 判别联合）：素材区间 `LibraryVideo`（缺省形态，旧数据没有 `kind`，dump 也不写 `kind`，旧选片版本逐字节不变）与文件区间 `FileVideo`（`kind=file`，`ref` 为 `{"input": "<sha256>.<suffix>"}` 或 `{"version", "file"}`，`start`/`end` 是文件内秒数）。clip 的选片版本与 image 的渲染版本记录文件区间；分镜渲染、带声预览、成片字幕与智能助手的选片摘要都识别两种形态。

创作页分镜内容的“画面来源”选择素材召回 / 上传片段 / 静态图片 / AI 生成图片 / AI 生成视频 / AI 动画：上传片段提供文件上传、起点（秒）与预览（视频从起点开始播放，并说明窗口按配音时长截取），静态图片提供文件上传、运动方式与强度滑块；非召回来源隐藏召回设置与粒度/数量覆盖，分镜卡片中不出现该来源没有的阶段。工作台详情的 `shot_stages` 给出每个分镜的阶段序列。智能助手 `edit_shots` 的 `source` 字段设置来源（`clear: ["source"]` 恢复素材召回），`attach_query_media` 的 `purpose=source` 把附件上传为画面文件并设为 clip（视频）或 image（图片）来源，预览说明下次构建要重建哪些阶段；`get_shot_details` 显示画面来源。

### AI 生成图片

`aigc_image` 分镜由设置页的“图片生成”角色（`studio.image_generator`，默认 MiniMax `image-01`，也可用本地 ComfyUI 工作流；`models/image_generators.py`，协议 `ImageGenerator`：generate / health）先生成一张图片，之后与静态图片完全相同。没有激活图片生成档案（且 yaml 未设 `enabled: true`）时，预检把 `draw` 节点阻塞为“未配置图片生成服务，请在设置页激活图片生成档案”，其后的渲染与成片随之阻塞。

- 生成图片（`draw`，`studio/workspace/handlers/draw.py`）不依赖配音：提示词取 `prompt`，缺省用画面意象，再缺省用召回查询；MiniMax 的 `aspect_ratio` 取与方案画幅最接近的比例（16:9 / 9:16 / 1:1 等），ComfyUI 直接映射宽高；有 `reference_id` 时作为主体参考（`subject_reference`，图生图）。请求只取一张（`n=1`，base64 返回，立即落盘）。结果经 `image_png` 规范化为 `versions/<vid>/image.png`，另存脱敏 `request.json`。
- 签名：参数为图片生成服务的 backend、model（ComfyUI 另含工作流摘要与映射），载荷为提示词、参考图摘要、seed、提示词优化开关与画幅尺寸；`motion`/`strength` 只进渲染签名，改运动方式不会重新生成图片。
- 渲染：与 image 相同的 `still_shot`，图片取自所选 `draw` 版本（时间线文件区间 `{"version": <draw 版本>, "file": "image"}`），签名含 draw 版本、图片摘要、运动参数与变速。

创作页“AI 生成图片”提供提示词、种子、提示词自动优化、主体参考图上传/移除，以及与静态图片相同的运动方式和强度；生成图片作为该分镜的画面阶段显示。智能助手：`edit_shots` 的 `source` 支持 `kind=aigc_image`，分镜是 aigc_image 时 `attach_query_media`（`purpose=source`）把图片附件设为主体参考图，`run_node`/`run_column` 支持 `stage=draw`。

### AI 生成视频

`aigc` 分镜由设置页的“视频生成”角色（`studio.video_generator`，见 [设置页](settings.md) 与 [配置参考](config-reference.md)）生成画面。设置页默认档案为 MiniMax H3（`backend: minimax_h3`，视频生成 V2：`POST /v2/video_generation`、`GET /v2/query/video_generation/{task_id}`），设置页只配置 endpoint 与密钥，生成方式与 H3 参数逐镜设置；也可用 MiniMax 海螺、阿里通义万相或本地 ComfyUI（`models/video_generators.py`，协议 `VideoGenerator`：submit / poll / fetch / 可选 cancel / health）。没有激活视频生成档案（且 yaml 未设 `enabled: true`）时，预检把 `generate` 节点阻塞为“未配置视频生成服务，请在设置页激活视频生成档案”，其后的选片、渲染与成片随之阻塞；ComfyUI 未导入工作流或节点映射、线上后端未填模型名时同样阻塞并说明原因。

- 生成方式 `mode`：`text` 文生视频；`first_frame` 首帧图生视频（`image_id`）；`last_frame` 尾帧图生视频（`last_image_id`）；`first_last` 首尾帧生视频；`reference` 主体（多模态）参考生视频（`references`：`{kind: image|video|audio, media_id}`，最多 9 图、3 视频、3 音频，不能只有音频）。缺省时有首帧图为 `first_frame`，否则 `text`。H3 逐镜参数：`model`（`MiniMax-H3` / `-Highspeed` / `-Lite` / `-Max`，缺省用档案模型）、`resolution`（480P/768P/2K，缺省 768P；2K 只有 MiniMax-H3，480P 只有 Lite/Max）、`ratio`（缺省按方案画幅；文生视频不能为 adaptive，图生视频固定 adaptive）、`duration`（4–15 秒整数，Max 为 5–15；缺省按配音时长取整）。尾帧、首尾帧与主体参考只有 H3 支持：其他后端的预检阻塞为“当前视频生成档案（…）不支持…”。参考素材（图片/视频/音频）都经 `query-media`（`purpose=source`）上传，PATCH 与预检校验已上传。H3 文档未给出取消接口，取消构建时只停止轮询。
- 生成画面（`generate`，`studio/workspace/handlers/generate.py`）依赖配音：提示词取 `prompt`，缺省用画面意象 `visual`，再缺省用召回查询 `query`；时长 = 配音时长 ÷ 方案变速，向上取整到 `durations` 中的允许值，都更短时取最大值（不足部分由选片冻结末帧补足）；尺寸为方案画幅分辨率。参考图经 `query-media`（`kind=image`，`purpose=source`）上传为 `inputs/<sha256>.<suffix>`，保存分镜时校验已上传，预检缺失时阻塞为“参考图片缺失或已损坏，请重新上传”，执行前复验摘要。
- 执行：提交任务后轮询，间隔从 `poll_interval`（默认 5 秒）起按 1.5 倍退避、上限 4 倍，总等待不超过 `max_wait`（默认 900 秒），超时尽力撤销远端任务并失败；轮询之间每 0.2 秒检查一次构建取消，取消时撤销远端任务，节点记为“已取消”，其余未执行节点阻塞。连续 3 次轮询网络错误才失败，审核拒绝立即失败。状态变化（排队中/生成中/已完成）写入执行日志。结果下载后统一封装为 MP4（无法直接封装时转 H.264）并经 ffprobe 校验。
- 产物：`versions/<vid>/generated.mp4` 与 `request.json`（提示词、时长、尺寸、参考图摘要、生成服务 backend/model、任务 ID、最后一次状态与轮询次数；不含密钥与请求头，结果 URL 去掉签名查询串）。失败或取消的版本保留 `request.json` 与 `debug/` 诊断，不被选用。
- 签名：`generate` 的参数为生成服务的 backend、model、允许时长（ComfyUI 另含 fps、工作流内容摘要与节点映射），载荷为提示词、反向提示词、seed、参考图摘要、取整后的时长与画幅尺寸，输入为分镜内容与配音版本；不含密钥、超时与轮询参数。签名一致时直接复用已生成版本，不再调用服务（线上生成按次计费）。
- 选片：在生成片段内从 0 起取与配音等长的窗口，时间线记录文件区间 `{"version": <generate 版本>, "file": "generated"}`；片段偏短时冻结末帧补足（`alignment=padded` 并给出警告，`strict` 对齐拒绝）。选片签名含旁白、配音版本与生成版本（`aigc_version`）。渲染与成片沿用文件区间流程；ducking 方案使用生成片段自带的音轨（如有）。

创作页“画面来源”选择“AI 生成视频”后提供生成方式、模型档位、分辨率、宽高比、时长（MiniMax H3 专用，档案不是 H3 时有提示），首帧/尾帧图与主体参考素材的上传/移除，以及提示词（占位文字显示缺省会用的画面意象或查询）、反向提示词与种子；生成画面作为该分镜的画面阶段显示，摘要显示生成时长与轮询次数，详情展示提示词、任务 ID、请求/实际时长与生成结果预览。智能助手 `edit_shots` 的 `source` 支持 `kind=aigc` 及 `prompt`/`negative`/`image_id`/`seed` 与 H3 的 `mode`/`last_image_id`/`references`/`model`/`resolution`/`ratio`/`duration`，分镜已是 aigc 来源时 `attach_query_media`（`purpose=source`，`role=first_frame|last_frame|reference`）把附件设为首帧、尾帧或主体参考；`run_node`/`run_column` 支持 `stage=generate`（预览提示会调用视频生成服务、可能产生费用），`get_shot_details` 显示 aigc 来源、生成状态并以媒体附上生成画面；视频生成档案可用 `create_model_profile` 等档案工具管理（见 [智能助手](agent.md)）。自建 ComfyUI 的部署与工作流导出见 [GPU 模型部署](DEPLOYMENT.md#comfyui可选的-aigc-视频生成服务)。

### AI 动画

`animation` 分镜由设置页的“动画生成”角色（`studio.animator`；设置页首次启动建好并激活默认档案智谱 `glm-5.3-flash`，需要填写 API Key；没有激活动画生成档案时才复制 `agent.llm` 并跟随激活的智能助手档案，见 [设置页](settings.md) 与 [配置参考](config-reference.md#animator--动画生成studioanimator)）编写 HTML/JS 动画源码，再在沙箱里逐帧录制成画面。它适合数据图表、文字动效、流程/原理示意、时间线等需要准确文字与数字的画面；与 AIGC（扩散模型生成写实视频）不同，动画是可读可改的程序，画面完全由源码决定。未启用动画生成（`enabled=false`）或档案缺少地址/模型名时，预检把 `animate` 节点阻塞为“未配置动画生成服务，请在设置页激活动画生成档案”，其后的渲染与成片随之阻塞。

- 生成动画（`animate`，`studio/workspace/handlers/animate.py`，模型客户端 `models/animator.py`）依赖配音：画面说明取 `brief`，缺省用画面意象 `visual`，再缺省用旁白 `text`；动画时长 = 配音时长 ÷ 方案变速，画布为方案画幅分辨率，帧率为 `studio.render.fps`。系统提示要求只输出一份自包含 HTML（内联 CSS/JS，画布恰好铺满、`overflow: hidden`，只由时间驱动、同一时刻画面确定，中文字体只用 `sans-serif`），改提示词须递增 `ANIMATOR_PROMPT_VERSION`（当前 1）。产物为 `versions/<vid>/animation.html`（`data.origin = "generated"`）。
- 静态校验（`validate_animation`，生成结果与人工保存都要过）：大小不超过 `max_html_kb`（默认 200 KB）；必须含 `<html>` 或 `<body>`；拒绝属性、CSS `url()` 与脚本赋值中的 `http://`、`https://`、`//` 外部地址，`@import`，`fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource`、`navigator.sendBeacon`、动态 `import()`、Worker/Service Worker，`<script src>`、`<link>`、`<iframe>`、`<object>`、`<embed>`、`<meta http-equiv=refresh>`，`window.open`、`localStorage`/`sessionStorage`、`indexedDB`、`document.cookie`。未通过时把中文违规清单作为反馈让模型重写，最多重试 `retries` 次（默认 2）。
- 录制（`studio/animation_capture.py`，渲染阶段执行）：Playwright 无头 Chromium，每次使用全新的临时 user-data-dir（录完即删），离线模式，`context.route` 中止除 `data:`/`blob:`/`about:` 以外的全部请求，WebSocket 一律接管且不连接服务器，Service Worker 禁用。初始化脚本在页面脚本之前接管 `Date`（从固定时刻起走）、`performance.now`、`requestAnimationFrame`、定时器、`requestIdleCallback` 与 `document.timeline.currentTime`，并把 `Math.random` 换成固定种子；CSS 动画/过渡与 Web Animations 每帧暂停并把 `currentTime` 设为虚拟时刻。第 i 帧对应虚拟时刻 `i × 1000 / fps` 毫秒，按渲染帧数（与配音采样对齐的 `frames`）逐帧推进并截图，PNG 经管道交给 ffmpeg 编为 H.264（`animation.mp4`），再按画幅规范化为 `video.mp4`。同一源码、画布与 fps 的两次录制逐帧一致。页面加载与每帧推进各有 5 秒上限（推进经 CDP `Runtime.evaluate` 的 timeout 终止脚本，死循环与定时器风暴都会以中文错误失败），整体墙钟不超过 `max_capture_seconds`（默认 60 秒）。依赖为可选 extra `animation`，未安装时渲染失败并提示“AI 动画录制需要安装可选依赖：uv sync --extra animation && uv run playwright install chromium”（见 [部署](DEPLOYMENT.md#ai-动画录制可选)）。动画没有原声，ducking 方案也只有配音。
- 签名：`animate` 的参数为动画生成服务的 backend、model、`max_html_kb` 与提示词版本，载荷为画面说明、时长、画布尺寸与帧率，输入为分镜内容与配音版本；不含密钥与超时。渲染的输入为分镜内容、配音与动画版本，载荷含动画版本、源码 SHA-256 与变速（`animation_version`），画幅与帧率在渲染参数里。
- 人工修改：`PATCH …/shots/{shot}/animation`（`{revision, html}`）经同一套静态校验后写入 `origin = "manual"` 的新动画版本并选用，只有该分镜的渲染（重新录制）与成片需要重建，配音与其他分镜复用。人工版本被“钉住”：选用期间构建直接复用它（即使画面说明或配音之后变化，也不会按签名重新生成覆盖，冲突列表不报告它自身的签名差异），只有强制构建或单独执行生成动画（重新生成）才替换；手改版本的签名由源码摘要派生，不会被按签名的复用误选。`dry_run: true` 只返回 `{valid, errors, bytes, max_kb}`，不写版本（智能助手预览用）。
- 预览：`GET …/versions/{vid}/animation.html` 返回源码，响应头 `Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; media-src data: blob:; font-src data:; sandbox allow-scripts` 与 `X-Content-Type-Options: nosniff`；产物下载接口返回 HTML/SVG 文件时带同样的沙箱头。创作页以 `<iframe sandbox="allow-scripts">`（不含 `allow-same-origin`）加载，动画脚本运行在不透明源里，拿不到本站 Cookie、存储与父页面 DOM，也无法发起网络请求。

创作页“画面来源”选择“AI 动画”后提供画面说明（占位文字显示缺省会用的画面意象或旁白）；生成动画作为该分镜的画面阶段显示，摘要显示来源（模型生成/人工修改）、字符数与时长，详情展示画面说明、沙箱预览（可重新播放）与“编辑源码”对话框（等宽文本框，保存即提交 PATCH，校验未通过时在对话框顶部列出违规项），“重新生成”按钮让模型重写源码，分镜渲染阶段的“重新生成”只重新录制。智能助手：`edit_shots` 的 `source` 支持 `kind=animation` 与 `brief`，`run_node`/`run_column` 支持 `stage=animate`，`get_animation_source`/`edit_animation_source`（studio_detail 领域）读取与修改源码（修改走预览确认，预览先做服务端静态校验），`get_shot_details` 显示动画版本、沙箱预览地址并以媒体附上录制画面；动画生成档案可用档案工具管理（见 [智能助手](agent.md)）。

## 背景音乐

背景音乐在分镜工作台的配音阶段详情里设置：分镜内容的 `music`（`Shot.music`）是提示点，默认没有背景音乐。

| kind | 设置 | 含义 |
|---|---|---|
| `generate` | `prompt`（音乐描述，≤2000 字）、`instrumental`（缺省 true 纯音乐）、可选 `lyrics`（≤3500 字，非纯音乐时使用；为空时由模型按描述写词）、`volume`（0–1，缺省 0.25） | 从此分镜起生成新的背景音乐 |
| `cover` | `audio_id`（参考音频 sha256，6 秒–6 分钟）、`prompt`（目标风格，10–300 字）、可选 `lyrics`、`volume` | 从此分镜起按参考音频翻唱 |
| `library` | `track_id`（曲库曲目 ID，即音频 sha256）、`volume` | 从此分镜起铺曲库音乐，见 [曲库](#曲库) |
| `none` | — | 从此分镜起停止背景音乐 |

没有提示点的分镜顺延前一段背景音乐，直到下一个提示点；方案开头到第一个提示点之前没有背景音乐（`workspace/music.py` 的 `segments`）。工作台详情的 `shot_music` 给出每个分镜的归属（`start` 提示点、`from` 顺延自哪个分镜、`stop` 停止）。配音可以跨分镜，背景音乐段落按分镜边界计算，与配音如何切分无关。

- 背景音乐阶段（`music`，`handlers/music.py`）只出现在 generate/cover/library 提示点分镜上，位于配音之后（library 只复制曲库曲目，见 [曲库](#曲库)）；调用设置页的“音乐生成”角色（`studio.music_generator`，默认 MiniMax `music-3.0`，翻唱 `music-cover`；或本地 ComfyUI 工作流，映射 prompt/lyrics/seconds/seed/audio），产物为 `versions/<vid>/music.<ext>`。签名为提示点（不含音量）与服务 backend/model（ComfyUI 另含工作流与段落预估时长）；改音量只重新合成成片。未激活音乐生成档案时预检阻塞为“未配置音乐生成服务，请在设置页激活音乐生成档案”。
- 歌词生成：`POST /jobs/{id}/music/lyrics`（MiniMax `lyrics_generation`，`write_full_song` 或 `edit`），只返回 `{title, style_tags, lyrics}`，不改分镜；ComfyUI 档案不支持。
- 成片合成：每段音乐循环/截断到段落长度（按分镜采样边界），淡入 0.5 秒、淡出最多 1.5 秒，按 `volume` 缩放，段外静音；再以配音为侧链（`sidechaincompress`，阈值 0.06、压缩比 3）自动压低后与配音混合——说话时背景音乐约压低 3–6 dB 但仍清晰可闻（旧参数阈值 0.03、比 6 会把整段配音下的背景音乐压到近乎无声，已修正）。切换发生在对应的提示点分镜：上一段在分镜边界前淡出，新的一段从提示点分镜起淡入，不会跨镜重叠。成片签名只在有背景音乐段落时加入各段（起始分镜、覆盖分镜、音乐版本与音量）和混音版本 `music_mix`（`MUSIC_MIX_VERSION`，修改混音参数时递增，使旧的有背景音乐成片需要重新合成），没有背景音乐的成片签名与旧版逐字节一致。
- 素材列表：分镜卡片停在分镜渲染阶段时的摘要与分镜渲染详情列出本镜适用的背景音乐（在哪个分镜切入/顺延/停止、描述、音量、音乐版本与试听，尚未生成时提示）；分镜预览只含配音（与原声），背景音乐不进入 `render` 签名——音乐跨分镜循环，只能按成片时间线在合成时混入，改音乐或音量因此不会重新渲染分镜。成片版本数据 `music` 记录实际混入的各段（`cue`、`shots`、`version`、`volume`、`kind`、`prompt`、成片时间线 `start`/`end`），“成片”面板据此列出每段并可试听；没有背景音乐时无此键。
- MiniMax 公告：自 2026-08-20 起付费音乐生成与歌词生成接口不再对新用户开放，历史付费用户可继续使用；无权限时平台错误原样转述。

创作页在配音格内显示背景音乐摘要（从此镜开始 / 顺延 #n / 停止），配音详情里的“背景音乐”区可选择顺延、生成、翻唱或停止，填写描述、纯音乐开关、歌词（“生成/改写歌词”调用歌词生成）、上传翻唱参考音频、调整音量，保存后可单独执行/重新生成并试听。智能助手：`edit_shots` 的 `music` 字段设置提示点（`clear: ["music"]` 去掉），`generate_lyrics`（studio_detail 领域）生成歌词，`attach_query_media`（`role=cover`）上传翻唱参考音频，`run_node`/`run_column` 支持 `stage=music`。

### 曲库

曲库（`studio/music_library.py`，素材管理页的“音乐库”标签 `/admin/music`；旧地址 `/studio/music` 重定向到这里）保存带授权信息的音乐：导入时授权来源、许可、署名必填，有效期可选（`YYYY-MM-DD`，含当天）。曲目 ID 即音频内容 sha256，文件按内容寻址存放在 `data_dir/music/`，重复导入返回已有曲目、不改原记录；记录在 metadata 库 `music_tracks` 表，备份随数据目录带上文件。

- 分析（`studio/beats.py`，纯 numpy，桌面版同样可用）：ffmpeg 解码为 22050 Hz 单声道 → STFT（2048/512）→ 半波整流谱通量 → 自相关在 60–200 BPM 求峰（对数高斯先验偏向 120 BPM）→ 动态规划节拍跟踪，另算能量与亮度（频谱质心）。合成节拍器上 BPM 误差 ≤ 2%、节拍误差 ≤ 30 ms（`tests/test_studio_beats.py`）。导入时自动分析，在请求线程池中同步完成（几分钟的曲目约 1 秒）；`ANALYSIS_VERSION` 变化后曲目标为需要重新分析。
- 情绪标签：文案模型（`studio.writer`）按曲名、标签与节奏特征从固定词表（calm、warm、happy、energetic、epic、tense、sad、mysterious、inspiring、tech、romantic、playful）选 1–3 个；模型不可用或输出无效时按节奏特征推断。可在曲库页修改；重新分析时可保留人工标签。
- 推荐：`POST /music-library/recommend` 按段落文案（或提示点分镜到下一个提示点之前的旁白与预估时长）推断情绪与 BPM 区间（文案模型，不可用时按关键词），按情绪重合、BPM 距离与时长覆盖打分，给出理由；授权过期的曲目不参与。
- 选用：提示点 `kind=library` 的背景音乐阶段把曲目复制进版本目录（签名只有提示点身份，与音乐生成服务无关），版本数据带曲名、许可与署名；成片版本数据 `music` 的曲库段落含 `attribution`，发布元数据把署名写进简介。曲目不存在、文件损坏或授权过期时预检阻塞（过期时即使已有版本也阻塞）；被方案选用的曲目拒绝删除（409）。

创作页配音详情的“背景音乐”区选择“曲库音乐”后可从下拉选曲或“按文案推荐”；`mindex studio music import/list/show/update/analyze/recommend/use/delete`；智能助手 `list_music_tracks`、`get_music_track`、`import_music_track`、`update_music_track`、`analyze_music_track`、`recommend_music`（`studio_post` 领域，MCP 同名导出），选曲用 `edit_shots` 的 `music={kind: library, track_id}`。

### 节拍对齐

方案参数 `beat_align = {tolerance}`（秒，0.04–1；None 关闭）。开启后成片合成把背景音乐段落内的切点推迟到 `[切点 − 半帧, 切点 + tolerance]` 内最近的节拍（`workspace/beat_align.py`）：

- 每个非末镜的分镜渲染多留 `tolerance` 秒尾部余量（与重叠转场共用余量，取较大值）；切点推迟 δ 帧（≤ 余量）时画面多取 δ 帧，配音段末尾补 δ 帧静音，之后的字幕、背景音乐与边界整体后移。对齐后切点与节拍距离 ≤ 1 帧，配音不被截断。
- 节拍取自段落音乐文件的分析，段落循环播放时按曲长周期延伸；只对同一段落内的切点对齐，有重叠转场（`next`）或出场转场（`leave`）的切点不推迟（有出场转场的分镜不留余量）。
- 成片边界中被推迟的切点带 `beat_delay`（帧数）；关闭时 render 与 compose 签名与旧版一致。

创作页方案参数“节拍对齐容差”，`mindex studio plan set --beat-align 0.3`（0 关闭），智能助手 `update_plan_options` 的 `beat_align`。

## 成片后期

后期能力都在合成成片或分镜渲染时生效，每项都有四个入口：创作页（分镜「分镜渲染」详情里的「后期」面板、方案参数、`/studio/brands` 品牌模板页）、`mindex studio` CLI（`shot set`、`plan set`、`brand …`、`overlay …`，见 [CLI 参考](cli-reference.md#创作任务)）、智能助手与 MCP（`edit_shots`、`update_plan_options` 与 `studio_post` 领域，见 [智能助手](agent.md#studio_post)）。底层是同一组 REST 接口，Web 与桌面版行为一致。没有使用任何后期能力的方案，签名与产物与之前完全相同。

成片合成在 `studio/workspace/post.py` 里按步骤执行：逐镜对齐 → 画面拼接（硬切或重叠转场）→ 配音与背景音乐 → 片头片尾 → 字幕与文字层 → 水印与封装。

### 转场

分镜字段 `transition`：

- `enter` / `leave` 是镜内转场：fade 黑场、white 白场、zoom 缩放（伴随淡入淡出）、slide 滑入滑出。时长 0.1–2 秒，超过镜头一半时自动截短，并在渲染版本里记录说明。镜头时长不变，只重建该镜渲染。
- `next` 是到下一镜的重叠转场（xfade 样式：fade、dissolve、wipeleft、slideleft、circleopen 等）。本镜在渲染时多出等于转场时长的尾部画面：素材类优先从源继续取，取不到时冻结末帧；图片与动画直接多渲染。合成时只把重叠转场相连的几镜用 xfade 重新编码，其余仍复制码流。过渡从切点开始、在下一镜开头完成，所以成片总帧数、配音、字幕、背景音乐与边界都与硬切相同。
- 设置了 `next` 时，本镜的 `leave` 与下一镜的 `enter` 被取代；最后一镜的 `next` 被忽略。

### 字幕样式与高亮词

方案参数 `subtitle_style` 选择烧录字幕的样式：classic 经典、outline 粗描边、box 底条、highlight 描边加高亮。分镜字段 `highlights` 是字幕里要变色的词（最多 10 个）。只有烧录字幕且选了样式（或有高亮词、或品牌模板给出样式）时，成片才改用生成的 `final.ass` 烧录；字号与边距按短边换算，竖屏底边距与旧版一致。SRT 与 VTT 照常导出。样式只影响成片合成。

### 文字层

分镜字段 `overlays`（每镜最多 4 个）：title 标题卡（居中）、lower_third 下三分之一信息条（左下，在字幕上方）、data_card 数据卡片（右上，标签与数值），custom 只用于 HTML 方式。`start`/`end` 是相对本镜的秒数，留空表示整镜；入场效果 none、fade、slide。两种方式按图层选：

- `engine=ass`：在成片合成时写进同一份 `final.ass` 烧录，轻量、快。软字幕方案同样烧录文字层，字幕保持软字幕轨。
- `engine=html`：分镜多一个「生成叠加层」阶段（`overlay`），产出透明背景的 HTML 动画源码。标题卡、信息条、数据卡片用内置模板 `studio/overlays/layer.html` 注入数据生成，不调用模型；custom 按画面说明由动画生成模型编写（透明背景提示词），需要激活动画生成档案。分镜渲染时透明录制（argb MOV）并叠加在画面上，先于镜内转场，因此需要动画录制组件（桌面版为可选的 Chromium 组件），没有时预检阻塞并提示安装。叠加层源码可在后期面板、`mindex studio overlay edit` 或 `edit_overlay_source` 人工修改，人工版本被钉住，之后的构建保留它。

文字层的颜色取自品牌模板的文字层样式，没有品牌时为白字、黑色半透明底、橙色强调。

### 品牌模板、片头片尾与水印

品牌模板统一字幕样式、文字层样式、片头、片尾与水印。内置三个只读模板（简洁、新闻资讯、科技评测，`studio/brands/*.yaml`），复制后可修改并上传素材；用户模板存在 metadata 库的 `brand_templates` 表，被方案引用时不能删除。品牌素材（片头片尾视频不超过 30 秒，水印建议透明 PNG）按内容寻址存放在 `data_dir/brand/`，读取时复验摘要，备份按数据库引用自动带上。

方案参数 `brand_id` 选用模板，`brand_overrides` 覆盖其中几项（完整的字幕或文字层样式、换一个片头或片尾）或用 `disable` 关闭片头、片尾、水印。字幕样式的优先级：方案覆盖里的完整样式 > 方案参数 `subtitle_style` > 品牌模板样式。

- 片头片尾按方案画幅、帧率与适配方式规范化后接在正文前后；字幕、文字层、背景音乐报告与章节时间整体后移，背景音乐只铺在正文里。成片版本数据 `bookends` 记录各段帧数与时长。
- 水印按短边比例缩放，放在画面一角，默认只出现在正文时间段（`include_bookends` 为真时片头片尾也加）。软字幕方案同样叠加水印。
- 修改品牌模板或方案覆盖只重新合成成片，分镜产物照常复用。

## 多画幅导出与平台发布

创作页“交付”区、`mindex studio export … / publish …`、智能助手与 MCP（`set_exports`、`set_publish`、`build_publish_package` 等，`studio_post` 领域）共用同一组接口。这些都是成片之后的阶段（compose → export → metadata → cover → package），按变体（画幅或平台）展开节点；选用记在方案的 `finals`（`阶段:变体` → 版本），compose 仍在 `final`。只有 compose 的方案行为不变。

### 交付模板

「交付模板」分区位于「风格模板」之后（`/studio/delivery-templates`）。内置基本模板只读，复制后可编辑、重命名、删除。默认目标画幅为 16:9、9:16、1:1，默认平台为哔哩哔哩、抖音、YouTube；导出可选快速派生＋居中裁切、快速派生＋加边、分别重新渲染，并可逐画幅调整。

任务中选择模板会复制到当前方案的 `options.delivery`（来源 ID、名称、完整 config）；之后修改或删除模板不影响已有方案。新任务、新方案默认复制基本模板；旧方案不自动开启交付。方案的 `exports` 和 `publish` 保留为执行配置，应用快照时排除主画幅，兼容原 CLI 与助手调用。

模板与方案共用配置表单：封面三种来源及文字叠加、逐平台标题/简介生成要求、固定标签和简介尾注、交付包可选文件及命名、画幅/封面/文案检查的提醒或阻止策略。命名支持 `{job_id}`、`{plan_id}`、`{platform}`、`{canvas}`；视频与清单始终包含。通用封面复用持久化素材上传存储，应用时复制到任务 inputs；模板表的素材路径索引确保部分备份也携带该图片。

模板 REST 接口为 `/api/studio/delivery-templates`（列表）、`/{id}`（详情、PUT 保存、DELETE 删除）、`/{id}/copy`（POST 复制）。用户模板存入 metadata 数据库的 `delivery_templates` 表（迁移 v7）。模板名称不进入构建签名，打包选项与检查策略只影响发布包；文案规则影响元数据阶段。生成文案仍可在任务中人工修改并钉住。

### 平台管理

交付模板页上半部分为平台管理，下半部分为交付模板管理。两处交付配置表单（模板与任务副本）的画幅卡片、平台选项、封面字段、文案规则和交付选项均横向排列，自然换行。

平台目录存入 `delivery_platforms`（迁移 v8），首次升级初始化三个预置平台，之后它们与自定义平台一样可编辑、删除。标识创建后不可修改；删除保留墓碑，不可复用，重启不重新初始化。新任务和基本模板仅默认选择仍在目录中的预置平台，自定义平台需手动添加；预置平台全部删除则默认不启用平台交付。

平台规则包括目标画幅、封面规格、文案和标签限制、章节规则及生成语言。`GET /api/studio/platforms` 列出可选目录；`POST /api/studio/platforms` 创建；`GET/PUT/DELETE /api/studio/platforms/{id}` 读取、更新、删除。CLI 与助手通过同一目录选择平台，没有三个平台的枚举或数量限制。

模板及方案的 `publish.platform_specs` 保存按平台标识索引的完整规则快照；运行时不查询目录。目录更新不自动改变快照，可显式点击「更新平台规则」；目录删除后保留快照并标记“已从平台库删除”，仍可构建。平台更新不会自动给已有方案开启额外画幅；不匹配时沿用交付检查策略。旧模板、旧方案没有快照时使用原 YAML 规则补齐，保持历史语义；YAML 不再作为可编辑目录。

### 多画幅导出

方案参数 `exports`（最多两项，不能与方案画幅相同）：

- `derive` 快速派生：成片阶段另存一份无字幕、无水印的画面 `clean.mp4`，导出阶段 `export:<画幅>` 按目标画幅 pad/crop，再按新画幅重新排版字幕、字幕引擎文字层与水印，音轨直接取自成片。HTML 文字层已叠进逐镜画面，只能随画面一起缩放裁切。
- `rerender` 重新渲染：工作台自动维护一个关联子方案（`variant_of = {plan, canvas}`，名称“方案名 · 画幅”），与主方案共享分镜内容、文案、召回、配音、背景音乐与选片，按该画幅逐镜重新渲染与合成；主方案保存分镜或参数时同步。导出阶段登记子方案的成片。“构建全部画幅”（`?all_canvases=true` 预检与 `{all_canvases: true}` 构建；CLI `build --all-canvases`；`run_build(all_canvases=true)`）在一次构建里先构建子方案再构建主方案，可整体取消。子方案被主方案引用时不能删除；取消该画幅的重新渲染后子方案保留并解除关联。

### 平台发布

方案参数 `publish = {platforms, cover}`。内置平台预设 `studio/platforms/*.yaml`：bilibili（16:9）、douyin（9:16，无章节）、youtube（16:9）。每个平台的成片取与预设画幅一致的那个（方案画幅一致时用成片，否则用该画幅的导出；都没有时用方案成片并在发布包清单标出 `mismatch`）。

- 发布元数据 `metadata:<平台>`：文案模型（`studio.writer`）按大纲与逐镜旁白写标题、简介与标签（JSON），按预设截断、去重；章节由成片镜头边界生成（含片头偏移，按最短时长合并，不满足规则时不附章节）；曲库音乐的署名写进简介。人工修改（`PATCH …/publish-metadata/{平台}`）的版本被钉住。
- 封面 `cover:<平台>`：成片挑帧（`time` 省略时自动选清晰度最高的镜头中点；`GET …/cover-candidates?platform=` 列出候选）、图片生成模型生成（`prompt`，未激活图片生成档案时预检阻塞）或上传图片（`media_id`）；居中裁切到预设尺寸，底部叠加标题与副标题（标题缺省取发布元数据；字体与字幕相同，颜色取品牌文字层样式），按格式与大小上限保存。
- 发布包 `package:<平台>`：`<平台>/` 目录（video.mp4、cover、subtitles.srt/vtt、metadata.json、metadata.txt、manifest.json 含各文件 sha256）与 zip，经产物接口 `?download=true` 下载。上游任一产物变化后需要重建。

平台限制数值写在 YAML 注释里，注明核对日期与来源；B 站与抖音的字数与标签上限没有找到平台官方文档，发布前请人工复核。

## 第三方工具

分镜画面来源 `kind=tool` 调用登记的第三方工具（`studio/tools/`，设置页的“第三方工具”配置组 `/settings#tools`；旧地址 `/studio/tools` 重定向到这里）。工具源记录在 metadata 库 `tool_sources` 表：

- 协议：`http`（HTTP manifest：`POST base_url + submit_path` 提交 `{"tool", "arguments", "uploads"}`，`poll_path` 轮询直到 `status_field` 进入 done/failed，按 `result_field` 点分路径取产物地址；`poll_path` 为空时提交响应即结果）、`mcp-stdio`（本机进程，`command` 必须是绝对路径，`env` 追加到最小默认环境，不依赖 GUI 的 PATH）、`mcp-http`（streamable-http）。MCP 经 `list_tools` 发现、`call_tool` 调用，产物取图片内容、内嵌二进制资源、资源链接、`structuredContent.url(s)` 或文本里的 http(s) 地址；`mcp` 是可选组件（`uv sync --extra mcp`，桌面版已内置），缺失时预检提示安装。
- 白名单：只有 `tools` 里的工具能被调用；每个工具声明产物（video/image）、`allow_upload`（未勾选时携带素材的分镜预检阻塞）、`timeout`（秒）与 `max_mb`（产物上限）。产物只能从 `artifact_hosts`（http 协议另含 base_url 的主机）下载，流式计数超限即中止，手动跟随重定向并逐跳检查主机。
- 密钥：请求头与环境变量的值写 `secret:名称`，运行时替换为该工具源 `secrets` 中的值。密钥只写不读（接口只返回名称与是否已填写），不含密钥的备份导出清空 `secret` 列。
- `invoke` 阶段（画面阶段）：参数字符串里的 `{{text}}`/`{{visual}}`/`{{query}}` 替换为本镜内容；签名含工具源 ID、工具配置摘要（协议、连接、产物类型与上传许可；不含密钥值、超时与主机白名单）、工具名、参数、上传素材摘要与产物类型。产物经 ffprobe（视频，统一封装为 `artifact.mp4`）或图片解码（`artifact.png`）校验后登记为不可变版本文件，另存 `request.json`（参数、任务记录、产物来源主机，无密钥）。视频产物之后在产物内选窗对齐（与 AI 生成视频相同），图片产物直接按运动参数渲染。
- 预检阻塞：工具源未登记、工具不在白名单、产物类型不符、携带素材但未允许上传、缺密钥、缺 mcp 组件、上传素材缺失。被分镜使用的工具源拒绝删除（409）。

创作页分镜“画面来源”选“第三方工具”后选择工具源与工具，填写 JSON 参数并（允许时）上传素材；`mindex studio tools list/show/add/test/delete` 与 `shot set --tool 源/工具 --tool-args JSON`；智能助手 `list_tool_sources`、`test_tool_source`、`save_tool_source`（http / mcp-http，danger）与 `save_stdio_tool_source`（danger，不导出到 MCP：外部 MCP 客户端不能让 Mindex 执行任意命令），分镜用 `edit_shots` 的 `source={kind: tool, …}`。

## 可用素材摘要

文案创作、拆分镜和“按画面意象重写召回词”参照同一份可用素材摘要（Material Digest，`studio/material_digest.py`）。摘要只取召回实际比对的画面分析文字 `views.analysis`，让文案写素材里真实存在的画面，召回词贴近素材用词。摘要按需计算，不落盘，不进任何签名；只读生效内容索引快照与覆盖层，不修改快照、任务或产物。

- 范围：只读生效内容索引（不读其他索引版本），只纳入同时满足以下条件的片段：在任务可用素材范围内（`source_ids` 为 `null` 时不限，空集合则没有片段）、生效隐藏状态为否、`annotation_status == "complete"`、`views.analysis` 非空。过滤后没有片段的素材不出现。对白 `views.dialogue` 不读取；“人物”“人物情绪”“氛围”“景别”“角度”“镜头运动”标签行不进故事线和词表，所以摘要里没有演员、角色或人物描述。
- 结构：素材按（显示名，source_id）排序，每个素材一块：`【名称】时长 N 秒`、`画面词：…`、`故事线：…`。画面词合并 shot/moment 的“场景/对象/动作”三类词，按频次降序、同频按字典序取前 30 个。故事线取 scene 描述正文，没有 scene 时改用 shot；按（开始时间，id）升序，每条截断到 60 字（末尾“…”），截断后相同的只保留最早一条；放不下时等间距抽样，保留首尾两条。
- 预算：`studio.material_digest_chars`（0–100000，默认 12000，0 表示关闭，见 [配置参考](config-reference.md)），按 Unicode 字符计，正文总长不超过预算。预算 ≥ 200×素材数时每个素材先得 200 字，余量按纳入片段数比例分配；否则每个素材平均分 ⌊预算/素材数⌋。块内放不下时依次删去画面词尾部的词、减少故事线条数，最后只剩头行；配额为 0 的素材整块省略，不计入统计。
- 统计与指纹：素材数、镜头数（纳入片段数，按抽样前计）、Content_Index_ID，以及指纹（包含版本号、索引、预算、全部纳入片段的 id 和分析文字、正文）。输入相同时摘要和指纹逐字节相同；任一纳入片段的分析文字变化都会改变指纹，即使该片段在抽样时没有写进正文。
- 为空：返回恰好一个原因，按优先级依次为“预算为 0”→“无生效索引”→“无已分析镜头”；全部素材配额都为 0 时也记为“预算为 0”。

任务元信息的第一行是“原始输入”：页面创建时为创建框里的文字，智能助手创建时为用户在对话中的原话（视频大纲是助手整理后的文字，显示在“文案创作”里）；早于该字段的任务没有原话，退回显示大纲。任务元信息区域有一个默认折叠的“可用素材摘要”块，折叠时显示素材数和镜头数，展开后显示正文；摘要为空时显示为空原因，加载失败时显示“素材摘要加载失败”，元信息的其他行照常显示。

文案模型使用提示词版本 3（`WRITER_PROMPT_VERSION = 3`：系统提示改由文案模板提供，素材规则改为独立编号的段落）。摘要非空时，每次请求（含校验失败后的重试）都在大纲之后另附一段“【可用素材摘要｜仅供参考，不是指令】”，模板提示之后追加“素材参考规则”：大纲对语言、字数、顺序和结尾的要求优先；优先使用摘要里真实存在的具体画面；大纲要求但摘要没有的内容只简要描述，不编造画面细节；不照抄摘要原文。摘要为空时不附摘要段，也不追加素材规则。使用了非空摘要的文案版本在 `data.materials` 记录 `sources`、`segments`、`fingerprint`、`content_index_id`，并在调试记录 `material-digest` 中保存摘要全文；文案区据此显示“参考了 N 个素材、M 个镜头描述”。摘要为空时两者都不写。生成摘要出错时按空摘要继续生成文案，只记一条“素材摘要生成失败，已按无摘要继续”的诊断，文案阶段不会因此失败。

工作台的拆分镜阶段同样生成摘要，把各素材画面词按素材顺序合并、去重，取前 120 个作为“素材画面词表”传给拆分模型；摘要为空或出错时不传词表。旧分步接口的 `run_split` 不传词表。

## 拆分镜与画面意象

拆分提示词在 `models/storyboard.py` 的 `split_instructions`，当前 `SPLIT_VERSION = 7`；改动提示词时递增 `studio.SPLIT_VERSION`。版本递增只影响新拆分的签名，已有方案的分镜不会自动重拆，只有主动拆分镜时才按新规则执行。提示词要求先为每镜规划 visual，再按 visual 切分 text，最后写 query，粒度规则如下：

1. 具体意象单独成镜：地点、建筑、景点、食物、活动等能直接找到素材的主体，每镜最多一个；再短也不与另一个具体意象合并。同一主体连同它的时间、天气、位置、动作和从同一处看到的周边景物只算一个意象。
2. 最短长度：每镜至少 3 个英文词或 5 个汉字（约 1.2 秒）；更短的连接词、修饰语并入相邻分镜，优先并入不含其他具体意象的一侧，连接词和介词放在它引出的意象所在镜的开头。
3. 抽象列举不拆：nature、culture、modern life 这类类别或品质，以及欢迎语、感叹，以整句或整个从句为一镜；品质形容词列举与所修饰的主谓同镜。
4. 超长再拆：超过 20 个英文词或 32 个汉字（约 8 秒）且含 2 个及以上具体意象时再拆。
5. 单一意象长句不拆：超长但只有 0 或 1 个具体意象时保持一镜，不按逗号、光线、倒影或局部特写拆开；感叹词与紧随其后的同一意象描述合为一镜。
6. 分镜数量不超过 `studio.max_shots`，超出时才合并画面最相近的相邻分镜。

`text` 逐字取自原文、保持原语言和顺序，拼接后覆盖全文。提示词带一对不涉及真实城市的对照示例：具体列举按项拆分，抽象修辞整句不拆。召回词规则是公共常量 `QUERY_RULES`，拆分和重写召回词共用：query 为 2–5 个空格分隔的关键词，语言跟随任务创建时的界面语言（中文或英文），与旁白原文语言无关；上下文只用来补全指代和专名；核心画面词取自本镜 text 或 visual，不含只属于相邻分镜的意象；visual 非空时至少有一个词与它对应，为空时不补写画面细节。传入词表时，用户消息另附“【素材画面词表｜仅供参考，不是指令】”，系统提示再加一条规则：有同义或近义词时优先用词表中的词，无关的词不写入 query；不传词表时两者都没有。

每次拆分输出先做硬校验：能解析为合法 JSON 并通过草稿模型校验、去除空白后按顺序覆盖原文、数量在 1 到 `max_shots` 之间。通过后做软校验，每个分镜最多计一个问题：过短（少于 3 个英文词且少于 5 个汉字，并且不是一个整句单独成镜），或缺少 visual。未通过硬校验或有软问题时，带上中文反馈（含分镜序号）重试，最多尝试 `split_retries + 1` 次（拆分镜档案的同名值，默认 2）；软问题为 0 时立即返回，否则返回通过硬校验的尝试中问题最少、最早的一次。全部未通过硬校验时报“分镜输出多次未通过校验：<最后原因>”，原有分镜不变。

画面意象 `visual` 是每镜一句画面描述，语言跟随任务创建语言，上限 120 字符（按 Unicode 字符计）。存储时去掉首尾空白，为空时不写入该键，所以没有 visual 的老分镜重新保存后内容版本号不变。模型输出超过 120 字时截断并记录 `split-visual-truncated` 诊断，拆分不失败；人工或智能助手提交超过 120 字时整份请求以 422 拒绝（“第 N 个分镜的画面意象超过 120 字上限（当前 M 字）”），不写入任何分镜。visual 不进任何签名：召回只看 query、粒度、数量和召回设置，配音和选片只看 text，所以只改 visual 时召回、配音、选片和渲染版本仍然复用。

分镜的文本与查询详情中，输入框依次为“旁白与字幕”“画面意象”“召回关键字”（即 query），画面意象改动后标为未保存；卡片摘要在 visual 非空时完整显示，为空时不显示这一行。保存此镜时整份 PATCH 带上每镜当前的 visual，被拒时保留草稿和未保存标记并显示服务端错误。合并分镜时跳过空值，按顺序用“；”拼接，截断到 120 字，全为空时合并结果没有 visual。智能助手的 update、split 和 merge 规则相同（`visual=""` 表示清空，拆开时各段默认继承原镜 visual），`shot_rows` 输出 visual，为空时为 null。

按画面意象重写召回词：在文本与查询详情中修改画面意象后，点击“按画面意象重写召回词”。前端用草稿中当前的 visual 请求建议，请求期间禁用按钮；成功后只替换草稿里的 query 并标为未保存，点击“保存此镜”后才生效，在此之前已保存的 query 和召回产物不变。失败时在编辑器中显示错误，草稿和未保存标记不变。服务端用 `suggest_query` 调用一次拆分镜模型（不重试），参考前后镜的 text 和素材画面词表。

拆分粒度与带召回的检查可以用 `eval/split_eval.py` 复跑，用法见 [评测说明](../eval/README.md)。

## 版本与依赖

每次实际执行保存独立的不可变版本，包含阶段、分镜身份、成功或失败结果、输入版本、参数快照、文件路径及 SHA-256。成功后更新当前方案的对应选择；失败只新增记录，保留原有选择和全部下游产物。

兼容性按实际使用的内容和阶段参数检查：查询影响召回，旁白与声音影响配音，选片依赖其实际配音、召回版本及候选锚点。新人工窗口保存候选引用；仅旧式人工素材范围不依赖召回。分镜渲染绑定选片与音频版本、原片文件身份及处理参数。上游变化只展示具体冲突；构建时才决定复用和重建。

兼容性提示逐项显示变化字段及原值、当前值，包括视觉/对白/分析召回权重、素材可见性指纹、活动索引版本、人物检索发布版本、嵌入模型与服务参数等。素材的隐藏/显示会改变可见性指纹，即使没有修改分镜，也可能使召回及其下游产物过期。llama.cpp 嵌入服务根地址和同址 `/v1` 写法视为等价，不因地址拼写差异要求重建；真正更换地址、模型或检索设置仍检查失效。界面语言切换同时更新提示及嵌套上游原因，历史版本记录保持原样。

构建依赖为 `文案 → 拆分镜 → 逐镜阶段 → 成片合成`，逐镜阶段按画面来源展开（素材召回为 `召回 / 配音 → 选片 → 分镜渲染`，其他来源见[阶段注册表](#验证)）。分镜表另外记录身份、数量和顺序。每个新成片保存实际使用的完整依赖图及方案快照；依赖树可展开、查看节点详情，并可复制为新方案。

## 构建与人工控制

“构建成片”先显示复用、重建、阻塞和无需执行的清单，确认后执行。预检令牌绑定方案、输入版本与生效参数，提交时变化会要求重新预检。每格也支持单独执行或复用，强制重新生成是单独入口。

某节点失败后，其他独立镜头及分支继续执行，依赖失败节点的后续节点标为阻塞。必需依赖未齐时不合成新成片，已有成片始终可播放和下载。再次预检续建会复用输入指纹和文件哈希均匹配的成功版本。构建状态为 running/complete/partial/failed/cancelled，节点另有 reused/blocked/skipped 状态；界面遇到未知状态时显示原始值。

逐镜选片按“选择召回候选 → 拖动定长窗口 → 保存当前窗口”操作。召回和选片详情分别提供候选预览、设为参考锚点与恢复自动选择；自动模式沿用综合评分，不固定使用首个候选。锚点按方案和分镜保存，绑定召回版本与候选 ID。选择只修改构建输入，保留已有选片与视频；更换锚点会移除此前确认范围。切换召回版本后，人工锚点来自其他版本时显示具体冲突，需重新选择候选或恢复自动模式。

“恢复自动选择”保存自动模式，从人工模式切换时清除此前人工范围，不立即选择或保存某个候选。打开选片窗口或执行选片时，才结合语义、实际成功配音时长及素材延长情况评分；窗口显示解析出的实际参考候选。无成功配音时等待配音完成。恢复自动模式不会改变已有选片与视频的历史依赖。

局部上下文为同一原片的前两镜、整个候选锚点组和后两镜；不足配音有效时长的两倍时，按前后两侧原有时长比例增加相邻镜头，直到总时长至少达到两倍；一侧无法延伸时由另一侧补足。隐藏区间、素材边界和断点均停止延伸。定长窗口使用当前成功配音的实际时长；明确设置速度时除以该速度，未指定时为原速。仍不足时禁用窗口与确认，不自动变速或冻结。无配音也能选择候选，窗口等待配音完成。

时间轴显示连续视频缩略图、镜头边界与锚点标记。可以整体拖动、点击定位、左右方向键逐帧微调，Shift 移动十帧，Home / End 到合法边界；缩放后支持横向滚动。窗口可以完全离开锚点。拖动只在本地定位画面；直接使用视频窗口内的播放键播放当前选区，到窗口结束自动暂停，从结尾再次播放会回到窗口起点。“保存当前窗口”无需先点预览，内部自动获取当前范围的校验令牌后保存；缺少配音、素材不足或正在执行时禁用，并显示具体状态。“试听配音与画面”是可选操作，生成当前范围与配音混合的音画预览，本身不保存选片。保存后创建新选片版本，保存真实候选、上下文、最终范围、实际范围和音频依赖。配音、速度、素材可见性或方案 revision 变化会使旧预览失效。草稿按任务、方案、分镜、候选、配音版本和速度隔离，切换详情保留有效位置。

选片详情的“按当前输入选片 / 复用”使用当前锚点或已保存范围，优先复用成功版本；“重新生成选片版本”跳过复用并新增版本。两者都不保存尚未提交的窗口草稿，也不自动渲染分镜或合成成片。

旧区间 API 与历史产物继续保留。缺少候选引用的旧人工版本展示原范围，重新调整前要求明确选择候选，不从范围内第一镜推断历史锚点。

方案参数包括当前配音服务的声音 ID、召回数量、原声混音及增益、字幕模式、配音速度和补齐策略；任务级素材范围不属于方案参数，创建后不可更改。自动选片的速度留空时自动选择；冻结策略保持原速配音；严格策略要求范围与配音时长匹配。人工定长窗口始终使用指定速度或原速。没有新增跨素材拼接、情感控制、版本删除或自动清理。

音色默认采用 `voice_mode=inherit, voice=null`，每次提交执行时读取当前配音服务的默认音色；切换模型或默认音色无需逐任务修改。只有明确选择“为本方案指定音色”时，才使用 `voice_mode=custom` 和指定的 `voice`。批次提交后使用当次配置快照，各配音产物保存实际音色和模型；历史文件与参数不随全局设置修改。新建方案默认跟随默认音色，复制方案保留明确的覆盖选择。

旧方案没有记录默认音色与人工覆盖的区别，现按跟随默认处理；旧值保留为 `legacy_voice` 参考，不再参与执行。读取时仅在内存中规范化，下一次受执行锁保护的写操作才保存；历史产物与成片快照不修改。若需要固定某个旧音色，可重新明确指定。

执行经 `studio/executor.py` 的 `StudioExecutor`：进程内单执行线程，持全局 `studio.lock` 串行执行。方案编辑、选择、删除任务、ZIP 导出与执行互斥，冲突返回 409。服务重启后的未完成构建保留历史并标为中断，可重新预检续建。

## 取消执行与删除方案

构建执行中，“构建成片”旁显示“取消执行”。点击后请求取消（`POST /jobs/{id}/builds/{build}/cancel`），工作日志记一条“已请求取消，当前节点完成后停止”，按钮显示为正在取消。执行器在下一个节点开始前检查取消标记（进程内事件与哨兵文件 `builds/<build_id>.cancel`，跨进程可见）：已开始的节点照常完成，其余 pending 节点标为阻塞、原因“已取消”，构建状态记为 `cancelled`，已生成的版本全部保留，之后可重新预检续建。服务重启恢复只处理 running 的构建，不改变已取消的构建。只有 running 构建可以取消，其他状态返回 409。

旧任务的步骤执行（`/steps`、`/run`）运行时，页面显示执行中提示和“取消执行”按钮（`POST /jobs/{id}/cancel`）：worker 在步骤之间检查任务目录下的 `steps.cancel` 哨兵，当前步骤完成后停止，执行状态记为 `cancelled`，未开始的步骤保持原状态。

方案栏的“删除方案”需要二次确认，只剩一个方案时不可用。`DELETE /jobs/{id}/plans/{plan}` 在创作修改锁内只删除方案记录：版本、构建记录和文件都保留（`mindex clean` 目前不回收 `versions/`，只按策略回收预览、旧 attempt 与导出包）。删除的是当前方案时，切换到其余方案中创建时间最新的一个。有构建正在执行时返回 409，删除唯一的方案返回 422（“至少保留一个方案”），两种情况都不做修改。

## 诊断与智能助手

`GET /jobs/{id}/plans/{plan}/diagnostics` 汇总一个方案的状态，只读、不加锁，构建执行期间也可调用：分镜的硬性检查、软性问题与文案覆盖；方案烧录字幕时的字幕滤镜与字体检查；各已选节点是否缺失、失败、文件损坏或过期，以及与 `conflicts` 一致的变化原因（例如“旁白已变化”）；构建预检摘要；各阶段当前的输入（`inputs_by_stage`）。智能助手的 `diagnose_plan` 用它解释“为什么这个分镜要重建”，`run_column` 用 `inputs_by_stage` 组装整列执行的输入。

智能助手在创作页可完成的操作见 [智能助手](agent.md#能力范围与缺口)：`studio` 领域覆盖任务、方案、文案与文案模板（列出、读取、复制、修改、删除用户模板）、参考文稿、画幅、分镜（含逐镜召回设置、图片或视频召回、画面来源）、构建、取消与删除方案；`studio_detail` 领域覆盖诊断、版本依赖、召回词建议、素材摘要、版本预览、整列执行和人工选片。人工选片工具与页面走同一组接口：`get_selection_candidates` 读取 selection-context，`preview_selection` 用候选加起点（定长窗口，必要时先设人工锚点）或素材加起止时间（任意区间）调用 range-preview，`confirm_selection` 提交与预览一致的请求体和 preview_token 调用 range-confirm。方案 revision 或对齐结果在预览后变化时提交会被拒绝，需要重新预览；没有成功配音或有构建正在执行时，选片工具直接返回原因。

## 文件与迁移

```text
data/studio/<job_id>/
  job.json                  # 任务标题、视频大纲（老任务为原文）、可用素材及旧流程状态
  workspace.json            # schema=2：方案指针、版本索引、构建执行与节点结果
  builds/<build_id>/events.jsonl # 可增量读取的人类可读执行日志
  builds/<build_id>.cancel  # 取消哨兵（旧任务步骤执行为 steps.cancel）
  inputs/<sha256>.<suffix>  # 查询媒体、画面来源文件与参考文稿（.txt），执行前复验摘要
  versions/<version_id>/
    version.json            # 不可变版本记录
    debug/*.json            # 请求、响应、ffmpeg 命令及错误诊断
    ...                     # 此版本的候选、音频、视频或成片
  migration-v2/             # 迁移前 job/storyboard/timeline/audio/checkpoints 快照
  attempts/...              # 原执行产物与历史，原样保留
  previews/...              # 由明确版本/参数生成的预览缓存
  exports/*.zip             # 导出包不递归包含导出包
```

迁移校验旧 manifest 的文件哈希，导入可验证的召回、配音、分镜视频及历史成片。无法证明输入关系和参数的旧版本标为“记录不完整”，不会按当前分镜猜测旧依赖，也不会自动视为可复用版本。旧成片仍可下载；依赖关系不完整时不能恢复为可验证方案。所有新版本均保存明确依赖。迁移是按任务进行的，打开前不会批量修改现有任务。

认证头、密钥和 URL 中的凭据经过诊断脱敏。原片不复制进任务目录；版本记录素材身份及文件指纹。产物下载 URL 指向确定版本文件，不依靠可变别名或缓存查询参数代表版本。

## 媒体与字幕

分镜渲染独立保存确定帧数的视频和处理后的 48kHz PCM 音频。帧数依据实际处理后采样数计算，保证在任意成片位置都能容纳完整配音。合成混选版本时，根据累计帧边界统一计算各镜的采样补齐和字幕时间，避免逐镜浮点累计或独立取整造成漂移。

定长窗口的字幕结束时间和分镜时长使用同一精确值，保留音频采样和变速带来的非整数毫秒时长；毫秒取整仅用于界面显示及字幕文件输出，不用于放宽事件的边界校验。

视频先裁到实际原片范围，再冻结末帧。音频支持变速、响度归一化及原声压低混音。成片发布前检查音视频轨道、字幕模式、时长和完整解码；失败保留已有成片。软字幕同时保存 MP4 mov_text、SRT 和 WebVTT；烧录字幕需要部署环境的 ffmpeg subtitles/libass 和可用中文字体。

技术对齐不保证叙事、人物或查询质量，仍需人工审阅。确定性测试音频也不代表真实发音质量。

## 验证

工作台代码位于 `studio/workspace/` 包：`versions`（任务目录、`workspace.json` 落盘、不可变版本与文件校验）、`plans`（方案选项、文案与分镜编辑、版本选用、分镜快照还原）、`persistence`（读取与旧任务迁移）、`signatures`（阶段参数、签名、冲突与复用）、`preflight`（预检与列重生成节点）、`media_nodes`（区间校验、选片对齐、分镜渲染）、`post`（成片后期管线：拼接、背景音乐、字幕、封装）、`builder`（节点执行、整次构建、取消与重启恢复）、`details`（详情视图）、`stages` 与 `handlers/`（阶段注册表，见下）。`tests/test_studio_signature_snapshot.py` 以 `tests/fixtures/studio_signatures.json` 冻结各阶段签名、预检结果与固定 fixture 的成片时间线结构；只有签名变化是有意为之时才用 `MINDEX_UPDATE_SNAPSHOTS=1` 重新生成。

阶段注册表：每个阶段一个 `StageHandler`（`studio/workspace/stages.py`），处理器位于 `handlers/`（`script`、`split`、`recall`、`tts`、`music`、`draw`、`generate`、`animate`、`invoke`、`select`、`overlay`、`render`、`compose`、`export`、`publish`），导入时经 `register()` 按 plan → shot → final 顺序登记到 `REGISTRY`。处理器提供显示名 `label`、作用域 `scope`、阶段参数 `settings`、签名载荷 `specification`（签名外壳仍在 `signatures.specification`，与历史版本逐字节一致）、依赖 `dependencies`、预检钩子 `preflight`、执行 `run` 与冲突说明 `conflict_labels`；`builder.execute`、预检、列重生成、冲突与复用都按注册表分派，请求体（`NodeBody`、`ColumnBody`、`VersionChoiceBody`）的阶段取值也由注册表生成。每个分镜的阶段序列由镜头来源决定（`shot_stages`，来源表 `SHOT_SOURCES`）：recall 为 `recall → tts → select → render`（即 `ws.STAGES`），clip 为 `tts → select → render`，image 为 `tts → render`，aigc_image 为 `tts → draw → render`，aigc 为 `tts → generate → select → render`，animation 为 `tts → animate → render`，tool 为 `tts → invoke → select → render`（图片产物 `tts → invoke → render`）；带 generate/cover/library 背景音乐提示点的分镜在配音后多一个 `music`（见[分镜画面来源](#分镜画面来源)；来源文件的定位与复验在 `workspace/sources.py`）。新增阶段或来源只需实现处理器并登记，不改预检与执行（`tests/test_studio_stages.py`）。

`tests/test_studio_workspace.py` 覆盖版本选择、失败保护、混选依赖、方案隔离、续建、连续/隐藏镜头、预览确认、迁移和执行锁；使用真实 ffmpeg、SQLite、Chroma 及确定性模型。非整数帧率测试校验帧数、累计采样边界、字幕、完整解码和依赖文件哈希。浏览器及本轮检查见 [工作台验收记录](history/studio-workspace-verification.md)；此前真实模型的质量结论见 [历史验收记录](studio-verification.md)。

本轮行详情与执行日志改造见 [行详情验收记录](history/studio-row-ui-verification.md)。

候选锚点与定长窗口依据 [细化计划](../plans/STUDIO_REFINEMENT_UI_PLAN.md)；测试与浏览器结果见 [定长窗口验收记录](history/studio-refinement-verification.md)。

浏览器专用服务可通过 `uv run python tests/serve_fixture.py --data-dir <临时测试目录> --port 8001` 启动，勿将确定性颜色向量用于真实素材索引。

逐镜文本编辑器的召回设置支持素材范围多选、场景、人物情绪、景别和最短／最长时长；这些素材筛选也适用于图片及视频召回。素材列表带搜索过滤和右下角高度拖拽；不选素材时搜索全部库。任务限定了可用素材时，这里只列出范围内的素材。旧的单素材设置继续读取，保存新的多选时写入 `filters.source_ids`。素材顺序和重复项不影响召回版本复用，单项多选与旧单素材配置保持相同签名；全选时不写入筛选，签名保持默认，历史召回版本继续复用。

分镜工作台打开任务时不展开任何阶段，下方显示选择提示。文本与查询中的素材范围默认全选任务允许素材；演员和角色仅显示所选素材关联影片中的组合，切换素材时清除不再适用的人物。自动选片使用与定长窗口一致的默认范围，尾部不足时向前移动起点，保证可用范围内完整容纳配音。

创作任务默认使用软字幕轨道。任务元信息中的文案隐藏空白行，可用素材独占整行并逐项列出。拆分镜粒度规则、画面意象与召回词规则见上文“拆分镜与画面意象”；各分镜 `text` 仍须逐字取自原文并按顺序拼接后覆盖全文，分镜文案保留原文语言。召回候选图右上角标记当前自动选择或人工已选择的锚点。
