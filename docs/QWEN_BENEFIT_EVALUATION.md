# Qwen 语义分析的检索增益与处理成本评估

日期：2026-10-13。用户重点：海量视频场景下，增加慢速 Qwen3.8:27b 分析，相比仅 WeMM 嵌入是否值得。评估结论写入 `E2E_RESULTS.md`，原始结果保留于实验目录，不预设融合必然提升。

## 固定条件

- 相同的 61 个 moment、原片时间边界、显示/隐藏状态、WeMM 权重/量化/4096 维空间和查询文本。
- 使用用户确认并冻结的 `frozen-queries.reviewed.jsonl`，8 dev / 12 test。不使用测试集调权重或选择有利子集。
- 在同一 enriched 索引内关闭对应检索分路，隔离新增信息的作用；核对其 video_only 与原 visual 基线，记录任何排名差异。
- 不让 ASR 目标片段、描述或风格通过 BM25 偷渡到被关闭的分路。新增 `video_asr` 会同时从词法文档排除 description/style。
- 图片查询是独立的原生 WeMM 功能，不把新增模态带来的收益算为 Qwen 提升。

## 对照组

| 报告 profile | 检索信息 | 回答的问题 |
|---|---|---|
| `video_only` | WeMM 视频向量 | 最低处理成本的基线 |
| `video_asr` | 视频向量＋ASR 对白向量及对白 BM25 | 不调用 Qwen 时，对白本身带来多少收益 |
| `no_dialogue` | 视频＋Qwen 描述/风格向量及对应 BM25 | 不直接检索对白的语义增强效果 |
| `fusion` | 视频＋Qwen 描述/风格＋ASR 对白＋BM25 | 完整系统效果 |
| `description_only` | Qwen 动作场景描述向量 | 描述单路能力 |
| `no_style` | 完整系统移除风格向量及对应 BM25 文本 | 情绪、氛围、景别、角度等信息的增量 |

主要比较：`fusion - video_only` 是完整方案相对基线的总收益；`fusion - video_asr` 是已有 ASR 时增加 Qwen 的收益；`video_asr - video_only` 是 ASR 收益。Qwen 的分析输入包含对白，所以 `no_dialogue` 不是“完全未看过 ASR 的纯视觉 Qwen”；报告中明确这一限制。

默认配置的检索权重保持不变；ASR 对照只保留原有 video/dialogue/lexical 权重，避免为了对照组额外调参。

## 质量报告

- 分别报告 dev/test 的 Hit@1、Hit@5、MRR@10、nDCG@10，以及各组相对于基线的绝对差值。Hit 指标用百分点，并写出命中条数。
- 逐查询比较，给出改善/退步/不变的数量、首个相关片段的名次变化，以及相关片段被误描述挤出的案例。保留所有查询，不只展示成功案例。
- 当前 test 基线为 Hit@1 8/12、Hit@5 11/12；Hit@5 只剩 1 条提升空间，单条变化就是 8.33 个百分点。更看重首位和排序，不能凭一个查询的差异得出普遍结论。
- 观察动作、物体、场景、互动、情绪和镜头类型的差异；某类查询数量不足则只展示个例。当前查询以可见画面为主，不能据此推断对白查询收益。
- 本轮仅为预告片冒烟；海量视频决策需要扩展至多个来源、长镜头、无字幕对白和困难负例，达到至少 40 条独立 test 后复核结论。

## 成本报告

分别记录 WeMM 画面嵌入、ASR、CPU 对齐、Qwen 片段分析/场景分组、额外文本嵌入、建库、在线查询的耗时。分析冒烟的 3 次真实调用被正式批次复用，估算首次完整处理成本时加回其真实耗时，不把缓存命中当成首次吞吐。

统计：输入时长、镜头/moment 数、不同时间区间数、推理请求次数、场景数、文本表示与向量数量、阶段总耗时，以及各 profile 的查询 P50/P95。

给出以下换算，并列明是否为实测或外推：

- 处理速度：输入视频分钟 / 单模型服务占用小时。
- 时间放大倍数：处理墙钟秒数 / 输入视频秒数。
- 每输入视频小时的额外设备占用小时，以及按同样设备处理 1,000 小时视频的估算天数。
- 按当前完整电影的片段密度（2,336 个 moment / 约 118.6 分钟）和预告片密度分别估算，避免将快剪预告片直接线性套用所有视频。
- Qwen 一次性分析费用与 WeMM 额外文本嵌入费用分别列出。索引的重复视频编码属于当前构建方式的实测成本，不能当作 Qwen 必需计算。

阶段墙钟时间不是 GPU 忙碌时间；没有部署机采样时不报告实测 GPU 算力利用率、能耗、显存峰值或货币成本。模型装载/切换耗时未采集则单独标为未知。场景分析当前参与完整阶段，但 moment 查询使用片段自身描述；单独披露这部分成本，避免把所有开销说成 moment 检索必需。

## 最终建议

根据实测收益、退步查询和处理成本给出建议：全量启用、限定高价值素材启用，或默认仅 WeMM（可加 ASR）。若提出稀疏采帧、只分析长镜头/代表片段、换更快模型等方案，将其标为后续实验，不能声称已经取得同等效果。

执行顺序继续遵守单 GPU：当前 Qwen 批处理完成后，用户切回原 WeMM 部署，再建 enriched 索引并评测上述对照组。保持整部电影活动索引不变。
